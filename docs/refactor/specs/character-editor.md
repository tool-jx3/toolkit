# 角色資料編輯器（character-editor）行為規格

## 0. 概要

在瀏覽器裡編輯一個 CCFOLIA 角色，輸出 CCFOLIA 可以直接貼上的「角色剪貼簿 JSON」（在 CCFOLIA 房間裡貼上就會新增這個角色）。
資料可以從三個地方讀進來：貼上的角色 JSON、在 CCFOLIA「キャラクター編集」畫面整頁複製下來的文字、本機的 JSON 檔。
讀進來時不直接覆蓋，而是先列出「目前的角色」與「要匯入的資料」逐項的差異，讓使用者勾選要覆寫哪些項目。
表單可以編輯名稱、先攻值、外部網址、顏色、備註、棋子大小、狀態（標籤／目前值／最大值）、參數（標籤／值）與聊天面板，
狀態與參數可以新增、刪除、拖曳排序，聊天面板可以一鍵插入 `{標籤}` 引用。輸出可以複製，也可以存成 JSON 檔。
全部在瀏覽器內處理，不上傳、不保存任何資料。

靈感來源：organon-torah/ccfoliaCharacterEditor（<https://github.com/organon-torah/ccfoliaCharacterEditor>）

附件：[`character-editor.examples.json`](character-editor.examples.json)——34 組「輸入→差異清單→輸出」的舊版實際紀錄
（JSON 20 組、編輯畫面複製文字 12 組、本機檔案 2 組；輸入全部是觀察者自編的繁中 TRPG 內容）。**差異清單與輸出以附件逐字相符為準**；
本文第 2、3 節的規則是附件的歸納。

名詞：「目前的角色」＝表單上正在編輯的角色；「匯入的資料」＝這次讀進來、經過 2.3 修正後的角色；「項目」＝狀態清單、參數清單裡的一列。

## 2. 輸入

### 2.1 外部格式事實：CCFOLIA 的角色剪貼簿 JSON

CCFOLIA 在房間裡複製角色時放進剪貼簿的資料，也是各種角色卡網站「輸出成 CCFOLIA 角色」所用的格式；在 CCFOLIA 房間畫面貼上（Ctrl＋V）
就會新增一個角色。最外層是物件：

```json
{ "kind": "character", "data": { … } }
```

`data` 的欄位（CCFOLIA 公開的格式；貼上時缺少的欄位由 CCFOLIA 補預設值）：

| 欄位 | 型別 | 意義（對應 CCFOLIA 編輯畫面） |
|---|---|---|
| `name` | 字串 | 角色名稱（名前） |
| `memo` | 字串 | 備註（名前下方的自由文字，常寫 PL 名與簡介） |
| `initiative` | 數字 | 先攻值（イニシアティブ），決定角色清單的排序 |
| `externalUrl` | 字串 | 參照網址（参照URL），通常是角色卡網址 |
| `status` | 陣列 | 狀態（ステータス）：`{ "label": 字串, "value": 數字, "max": 數字 }`，顯示成棋子的狀態條；聊天裡可用 `{標籤}` 參照目前值 |
| `params` | 陣列 | 參數（パラメータ）：`{ "label": 字串, "value": 字串 }`，很少變動的數值或文字；聊天裡可用 `{標籤}` 參照 |
| `iconUrl` | 字串或 null | 頭像圖片網址 |
| `faces` | 陣列 | 差分（立ち絵・差分）：`{ "iconUrl": 字串或 null, "label": 字串 }`，發言時加「@標籤」切換 |
| `x`、`y` | 數字 | 棋子在盤面上的座標 |
| `angle` | 數字 | 棋子旋轉角度 |
| `width`、`height` | 數字 | 棋子大小（駒サイズ，以格為單位） |
| `active` | 布林 | 是否放在盤面上 |
| `secret` | 布林 | 「ステータスを非公開にする」（隱藏狀態） |
| `invisible` | 布林 | 「発言時キャラクターを表示しない」（發言時不顯示角色） |
| `hideStatus` | 布林 | 「盤面キャラクター一覧に表示しない」（不列入盤面角色清單） |
| `color` | 字串 | 發言時名稱的顏色（`#rrggbb`） |
| `commands` | 字串 | 聊天面板（チャットパレット），以換行分隔的指令 |
| `owner` | 字串或 null | 擁有者的使用者 ID |

（`secret`／`invisible`／`hideStatus` 與編輯畫面勾選項的對應是依公開資料整理，本工具不編輯這三個欄位。）

### 2.2 外部格式事實：「キャラクター編集」畫面整頁複製下來的文字

在 CCFOLIA（日文介面）打開角色的「キャラクター編集」對話框，按全選再複製所得到的純文字，一個標籤或一個值各佔一行，結構如下
（`〈…〉` 是使用者的資料；附件 E01 有完整的例子）：

```text
（房間畫面的其他文字，可能含有「名前」「ステータス」等相同字樣）
```

**解析規則**（以結果描述；附件 E01～E12 是實例）：

1. 換行統一（CRLF、CR 都當成 LF），每一行去掉頭尾空白（含全形空白）。
2. 從**最後一個**整行等於「キャラクター編集」的行開始往後看；前面的文字全部忽略。找不到這一行就是錯誤（F07）。
3. 以下「找某標記」都是指：從開頭標記往後，第一個整行等於那個字樣的行。
4. 名稱＝「名前」的下一行，不管那一行是什麼（空行＝空字串；若名稱那一行不存在，會讀到下一個標記「イニシアティブ」當名稱，舊版如此）；沒有這個標記時是空字串。先攻值＝「イニシアティブ」的下一行轉成數字，空白、不是數字或沒有標記時是 0。
   棋子大小＝「駒サイズ」的下一行轉成數字，同樣的情況時是 4。外部網址＝「参照URL」的下一行（沒有時空字串）。
   「x」「y」的下一行也會讀，但不會出現在輸出裡。數字的寫法照 JavaScript 的數字轉換（例如「1e1」＝10、「0x10」＝16；空字串與「12abc」這類算失敗）。
5. 備註＝從「イニシアティブ」往後數第 2 行開始、到「駒サイズ」的前一行為止的所有行，以換行接起來後再去掉頭尾空白
   （中間的空行保留）。兩個標記有一個不存在，或中間沒有任何行時是空字串。
6. 狀態：取「ステータス」到「パラメータ」之間的行（沒有「パラメータ」時取到最後），先刪掉空行與整行等於下列字樣的行：
   「立ち絵・差分」「ステータス」「パラメータ」「チャットパレット」「ステータスを非公開にする」「秘匿NPC・敵キャラクターなど」
   「発言時キャラクターを表示しない」「盤面キャラクター一覧に表示しない」，然後從頭找「ラベル」：
   標籤＝「ラベル」的下一行；接著往後找「現在値」，目前值＝它的下一行；再往後找「最大値」，最大值＝它的下一行；
   數字轉換失敗時是 0。讀完一筆後從「最大値」的值之後繼續找下一個「ラベル」。找不到「現在値」或「最大値」就停止。沒有「ステータス」時是空清單。
7. 參數：取「パラメータ」到「チャットパレット」之間的行，同樣先清理，然後從頭找「ラベル」：下一行若是「値」，表示標籤空白；
   否則下一行就是標籤。接著往後找「値」，值＝它的下一行，但若那一行是「ラベル」，表示值空白（而且那個「ラベル」是下一筆的開頭）。
   找不到「値」就停止。值一律是字串。
8. 聊天面板：從「チャットパレット」的下一行開始，到後面第一個出現的「ステータスを非公開にする」「秘匿NPC・敵キャラクターなど」
   「発言時キャラクターを表示しない」「盤面キャラクター一覧に表示しない」任一行的前一行為止（都沒有時到最後）。
   第一行若正好是 CCFOLIA 的說明文字（上面結構裡那一整句）就略過；其餘以換行接起來，再去掉頭尾空白。每行已在第 1 步去掉頭尾空白，
   所以行首的縮排不會保留（附件 E01：「  CC<=55 【心理學】  」→「CC<=55 【心理學】」），中間的空行保留。
9. 不讀顏色、頭像、差分、勾選項。讀出的角色再經過 2.3 的修正。

### 2.3 匯入資料的修正

| 欄位 | 規則 |
|---|---|
| `name`、`memo`、`externalUrl`、`commands` | 是字串才採用，否則是空字串（注意：匯入資料沒有名稱時名稱是空字串，不是「新角色」） |
| `initiative` | 是有限的數字才採用，否則 0（字串 `"5"` 也算不合格） |
| `width` | 同上，否則 4 |
| `color` | 是 `#` 加 6 位十六進位才採用，否則 `#888888`（但是否列入比較由 F04 決定） |
| `status` | 不是陣列時當成空陣列。每一項：不是物件時當成空物件；`label` 是字串才採用，否則空字串；`value`、`max` 是有限數字才採用，否則 0。**項目上其他的欄位照原樣保留**，欄位順序也保留（附件 J15） |
| `params` | 同上；`label`、`value` 都要是字串，否則空字串（數字的值會變成空字串，附件 J09） |
| 其他欄位 | 讀進來但不參與比較，也不會出現在輸出裡（`iconUrl`、`faces`、`x`、`y`、未知欄位等） |

## 3. 輸出

### 3.1 輸出 JSON

- 格式：2 個半形空白縮排的 JSON（每個鍵值一行），換行是 LF，結尾沒有換行。字串裡的中文等字元直接輸出（不轉成 `\uXXXX`）。
- 最外層固定是 `{"kind": "character", "data": {…}}`。
- `data` 固定只有 9 個欄位，順序固定：`name`、`memo`、`initiative`、`externalUrl`、`status`、`params`、`width`、`color`、`commands`。
  CCFOLIA 格式的其他欄位（頭像、差分、座標、旋轉、高度、勾選項、擁有者）一律不輸出，貼進 CCFOLIA 時由 CCFOLIA 補預設值。
- 狀態項目：表單新增的項目是 `{"label", "value", "max"}`；從匯入套用進來的項目保留它原本的其他欄位與欄位順序（附件 J15）。參數同理。
- 數字照 JavaScript 的 JSON 數字寫法（例：`1e+21`、`-1.5`，附件 J16）。
- 初始名稱「新角色」：新版若想用別的預設名稱需主控確認；比對附件時把預期輸出裡的這個值一併替換即可。

### 3.2 差異的計算與顯示

#### 3.2.1 一般欄位

依序比較：名稱、先攻值、外部網址、顏色（只在 F04 成立時）、備註、棋子大小；最後是聊天面板（排在所有狀態與參數項目之後）。
值完全相同（型別與內容）就不列；不同就列一列。

#### 3.2.2 狀態與參數的項目

- **項目的身分**：標籤去掉頭尾空白後不是空的 → 以「標籤原文」認定（同一清單裡同名的項目只認第一個，後面同名的完全不參與，附件 J07）；
  標籤空白（含只有空白字元）→ 以「在清單中的位置」認定（第 1 個、第 2 個…，附件 J08、J20）。
- **初始空白列**：目前的清單若「剛好只有 1 項，標籤空白，而且狀態是目前值 0、最大值 0／參數是值為空字串」，這一列不參與身分比對：
  目前的清單當成空的，但匯入清單的**第 1 項**改成和這一列比較（套用時取代它，見 3.3）。匯入清單是空的時候這一列保持不動（附件 J18）。
- **列出的順序**：先是目前清單的項目（依目前的順序），再是只出現在匯入清單的項目（依匯入的順序）。
- **比較**：狀態比較標籤、目前值、最大值三者；參數比較標籤與值；項目上的其他欄位不比較。相同就不列。
- **列名**：匯入那一側的標籤；匯入側沒有這個項目或標籤是空字串時用目前那一側的標籤；兩邊都空時用「空白標籤」字樣（新版自訂）。
  只有空白字元的標籤照原樣顯示（看起來像空的）。

#### 3.2.3 值的顯示

- 一般欄位：顯示值的文字（多行文字保留換行；太長時那一格最高約 120 px、內部捲動），空字串顯示一個表示「空」的灰色字樣（新版自訂）。
  兩側都以醒目樣式（舊版是深紅粗體）標示為變更。
- 狀態項目：分兩行顯示「標籤」與「目前值／最大值」；參數項目顯示「標籤」與「值」。逐一比較兩側，**不同的那幾個部分**才以醒目樣式標示
  （例：HP 11/13 → 7/13 只標目前值，附件 J06）。空字串的標籤或值顯示「空」字樣。
- 某一側沒有這個項目時，那一側只顯示「空」字樣，並標示為變更。
- 附件的「差異清單」逐列記錄：欄位、列名、兩側的值、哪些部分被標示。

### 3.3 套用規則

勾選的列依清單順序一列一列套用到目前的角色上（每一列都以「已經套用到一半」的結果為準）：

- 一般欄位：換成匯入的值。
- 項目：
  - 匯入側沒有這個項目 → 在目前清單裡找到同身分的項目就刪掉（找不到就不動）。
  - 目前的清單符合「初始空白列」，而這一列是匯入清單的第 1 項 → 整個清單換成只有這一項。
  - 目前清單裡有同身分的項目 → 原地換成匯入的項目（含它的其他欄位）。
  - 都不是 → 加到清單最後。
  - 「同身分」在套用每一列時都**依當下的清單重新判定**：以位置認定的項目，在前面的列刪掉項目後位置會改變（附件 J20 是這種情況的實例）。
- 沒有勾的列不動；顏色沒列入比較時目前的顏色不變。
- 套用後輸出立刻更新、複製成功訊息消失。

### 3.4 色碼欄的規則

- 打字時：去掉開頭的「#」，最多保留 6 個字元；剛好是 6 位十六進位時立刻套用（轉小寫，例：`12AB` 不套用、再打 `EF` → `#12abef`）。
- 離開欄位或按 Enter（Enter 會讓欄位失去焦點）時：3 位十六進位展開成 6 位並轉小寫（`abc` → `#aabbcc`）；6 位照常套用；
  其他內容（空白、不合格字元、4、5 位）還原成目前顏色的 6 位色碼。
- 欄位顯示目前顏色時不含「#」，大小寫照目前的值（匯入大寫色碼時顯示大寫，附件 J04）。
- 貼上 `#FF0000` 這類含 # 的 7 個字元時，# 被去掉，但欄位只收前 6 個字元的原文，所以實際留下 `FF000`（不套用；離開時還原）。
  新版若改成先去 # 再截 6 個字（得到 `ff0000` 並套用），屬可接受的改善，需主控確認。

### 3.5 存檔的檔名

- 名稱去掉頭尾空白，把每一段連續的 `\ / : * ? " < > |` 換成一個「_」；結果是空的（或名稱本來就空白）時用 `character`；
  再接上 `.ccfolia-character.json`。例：`a/b:c*?"<>|d` → `a_b_c_d.ccfolia-character.json`；`  a//\\b  ` → `a_b.ccfolia-character.json`；
  全空白 → `character.ccfolia-character.json`。Windows 保留名（如 `CON`）不特別處理（舊版如此；新版用 `safeFileName` 會改名，屬可接受差異）。
- 檔名開頭的「.」由瀏覽器處理（Chrome 下載時會拿掉）。
- 內容：輸出區全文，UTF-8，`application/json`。

### 3.6 對等驗證的比對方法

1. 附件 34 組：用 Playwright 在新版依序執行同樣的步驟，比對每一步的結果類型（差異確認／沒有差異／錯誤種類）、差異清單
   （順序、欄位、列名、兩側的值、標示變更的部分）與最後的輸出全文（逐字）。允許的差異：介面文字（「空」字樣、來源名稱的寫法、錯誤訊息文字）。
2. 隨機比對：產生至少 500 組隨機的「目前資料＋匯入 JSON」（含同名標籤、空白標籤、只有空白的標籤、型別不符的值、額外欄位、空陣列、
   初始空白列），各自隨機勾選一部分後套用，比對差異清單與輸出。
3. 表單操作（F17～F32）：兩邊做同樣的輸入、色碼輸入序列、新增／刪除／拖曳、插入引用，比對輸出 JSON、聊天面板內容與游標位置。
4. 複製、存檔（攔截存檔對話框與下載，比對檔名與內容）、重設、不保留狀態。

## 4. 互動與手感

- 沒有「產生」按鈕；表單任何改動都即時反映到輸出。
- 讀入一律要按「讀取」；讀入不會直接改資料，一定經過差異確認（或沒有差異的通知）。
- 差異確認開著時是強制回應：背景不能操作。舊版開啟時焦點留在原本的「讀取」按鈕、不會移進對話框，Esc 與點遮罩都不會關（F41）；新版用共用 Dialog 的焦點鎖定。
- 拖曳排序只能用滑鼠（舊版沒有鍵盤排序）；新版若加上鍵盤排序屬可接受的新增。
- 沒有快捷鍵、沒有復原／重做。不儲存任何狀態。
- 窄畫面時讀入區與表單上下排列；差異確認的按鈕列會換行。

## 5. 容易做壞的地方

- **差異不是「整份覆蓋」**：一般欄位逐欄、狀態與參數逐項比較；預設全部不勾。
- **項目的身分**：有標籤用標籤、空白標籤用位置；同名只認第一個；只有空白字元的標籤算空白（但列名照原樣顯示）。
- **初始空白列**：只有「剛好一列、空白、0／0（或空值）」才特別處理，而且只跟匯入的**第 1 項**配對；其他匯入項目是附加到後面
  （附件 J02：只勾 SAN 時，空白列留著、SAN 加在後面）。
- **套用是逐列進行**，位置認定的項目以當下的清單判定（附件 J20）。
- **顏色**：只有 JSON／檔案、且原始輸入是合格 6 位色碼才比較；編輯畫面複製文字永遠不動顏色（附件 E12）。合格色碼保留大小寫。
- **修正規則的型別很嚴格**：`"5"` 不是數字、數字 60 不是參數值（變空字串）。
- **輸出只有 9 個欄位**、順序固定；但項目上的額外欄位會保留。
- **輸出 JSON 結尾沒有換行**，縮排 2 格。
- **編輯畫面複製文字**：從**最後一個**開頭標記開始；每行先去頭尾空白（所以聊天面板每行開頭的縮排會不見）；聊天面板第一行的說明文字整句相符才略過；
  備註從「イニシアティブ」後第 2 行開始。
- **舊版的解析問題（刻意差異，需主控確認）**：狀態的標籤空白時，複製文字裡「ラベル」後面直接是「現在値」，舊版會把「現在値」當成標籤，
  並把下一筆的數值吃掉（附件 E06：兩筆狀態變成一筆標籤為「現在値」、12/14 的錯誤資料）。建議新版改成：「ラベル」的下一行若是「現在値」，
  標籤當成空白、從該行繼續讀。改了之後 E06 的預期輸出不同，驗證紀錄寫明。
- **數字欄（刻意差異，需主控確認）**：舊版清空數字欄會立刻變回「0」，所以無法先打負號（打「-」會被吃掉）。新版用共用數字欄
  （打字中允許暫時空白、離開時才補 0）屬可接受的改善；輸出值的規則（空白＝0、可小數與負數）不變。
- **Esc 關閉對話框**（F41）：新版共用 Dialog 支援 Esc，行為等同「關閉不套用／取消重設」，屬可接受差異。
- **存檔對話框**：只在支援 File System Access API 的瀏覽器（Chrome、Edge）出現；其他瀏覽器直接下載。新版若一律直接下載，需主控確認（見最後回報）。
- **不要把舊版的其他欄位（`iconUrl` 等）帶進輸出**，除非主控決定改成「保留匯入資料的其他欄位」（屬功能變更）。
