# CCFOLIA & 圖片調色工作室（psd-studio）行為規格

## 0. 概要

一次替一整批素材調色的工作台。可以放進三種東西：**CCFOLIA 匯出的房間 ZIP**、**Photoshop 的 PSD**、**一般圖片**（PNG、APNG、JPG、WebP、GIF，可多選或整個資料夾）。
放進來的每一張圖（PSD 是每一個圖層）都會套上同一組「整體調色」——色相、飽和度、亮度、對比、曝光、漸層對應（6 種混合模式）、RGB 曲線——
也可以替單一素材再加一組「個別調色」。預覽有兩種：圖片清單（縮圖格），以及照位置排出來的配置檢視（房間 ZIP 依 CCFOLIA 盤面的座標、PSD 依圖層位置）。
另外能把畫布四周補透明邊到 24 px 的倍數（CCFOLIA 一格＝24 px）、把 APNG 與大圖壓到不超過選定的大小（CCFOLIA 有上傳大小限制）、改 APNG 的播放次數。
最後打包成一個 ZIP 下載：房間 ZIP 會把改過的圖片依新內容重新命名、同步改好房間資料，匯回 CCFOLIA 就能用；PSD 會把每個看得見的圖層各存成一張 PNG；
一般圖片就是調好色的圖。也可以在單圖檢視器裡只下載一張。全部在瀏覽器內處理，不上傳；作業內容自動存在瀏覽器裡，重新整理後自動還原。

工具有四種狀態（下稱「模式」）：等待（還沒載入）、圖片模式、PSD 模式、房間模式。載入什麼決定模式（F06）。

靈感來源：fyam-hamu/F_Ccfolia-PSD-Studio（<https://github.com/fyam-hamu/F_Ccfolia-PSD-Studio>）。
舊版是依原作者寫在頁面上的條款收錄（`tools/psd-studio/TERMS.md`）；新版是無塵室重寫、不再散布原作程式，條款不再適用於新版，頁尾只放這一行靈感來源。

附件：[`psd-studio.examples.json`](psd-studio.examples.json)——在舊版上量到的結果：觀察者自製的量測圖在各種調色設定下的輸出顏色（灰階、色塊、純色、半透明像素；
整體、個別調色的疊加、處理順序）、APNG 的播放次數與延遲、容量壓縮的實際結果與嘗試順序、PSD 圖層的抽取規則、房間 ZIP 匯出前後的對照、補邊與檔名的例子。
**調色的對等以附件的數值為準**；本文寫規則與摘要。附件裡的設定組合、漸層色標、曲線控制點、測試檔都是觀察者自訂的。

本文用的控制項名稱是新版的名稱（觀察者自訂，實作者可再依用詞表調整），不是舊版介面上的字。

### 1.3 整體調色

整體調色套在所有素材上。改任何一項，所有預覽（清單縮圖、配置檢視、面板縮圖、素材摘要、單圖檢視器）在下一個畫面更新。處理規則見 3.8。

| 編號 | 功能 | 行為描述（看得到的結果） | 預設值／範圍 | 驗證方式 |
|---|---|---|---|---|
| F36 | 色相 | 滑桿＋數字欄。把所有顏色的色相轉一個角度（灰色不變；−180 與 180 一樣）。 | 0；−180～180 | 資料比對（附件「整體」） |
| F37 | 飽和度 | 滑桿＋數字欄（單位 %）。100 不變；0 變灰（灰的亮度是最亮與最暗通道的平均，例：(220,40,40) → 130）；200 加倍（超過上限就停在最鮮豔）。 | 100；0～200 | 資料比對 |
| F38 | 亮度 | 滑桿＋數字欄。每個通道直接加減這個數（+50：64 → 114），超出 0～255 就截掉。 | 0；−100～100 | 資料比對 |

## 2. 輸入

### 2.1 一般圖片

- 接受瀏覽器能解碼的圖片；選檔視窗限定圖片、`.zip`、`.psd`，拖放與資料夾選擇不限，由 F06 分流。沒有尺寸或檔案大小上限。
- 種類判斷見 F08。APNG 依 APNG 規格解析：`acTL`（格數、播放次數 `num_plays`，0＝無限）、每格的 `fcTL`（範圍、延遲 `delay_num/delay_den`、`dispose_op`、`blend_op`）；
  畫面要依 `dispose_op`（0 不處理、1 清成透明、2 回到前一格）與 `blend_op`（0 取代、1 疊上）逐格合成（匯出與試算都是用合成後的完整畫面，F76 的預覽例外）。
- 同名處理見 F07；資料夾載入的路徑見 F02。

### 2.2 PSD（以 ag-psd 讀出的意義描述）

- 以 ag-psd 讀取（讀圖層像素、不讀合成圖）。文件有 `width`、`height`；`children` 是圖層樹，**陣列由下到上**（第 0 個是最底層）。
- 每個圖層：`name`；`left`、`top`、`right`、`bottom`（文件座標，可以超出文件、可以是負的）；`hidden`；`opacity`（0～1）；`blendMode`（normal、multiply…；群組多為 pass through）；
  `clipping`（剪裁遮色片）；`mask`（圖層遮色片：自己的範圍與像素）；`canvas`（圖層像素，範圍＝left/top/right/bottom）。群組有 `children`，沒有像素。沒有像素的圖層 `canvas` 為空或範圍為 0。
- 舊版的抽取規則（附件「PSD」逐層列出）：
  - 隱藏的圖層略過；隱藏的群組連同裡面全部略過；群組攤平（不保留群組名與群組的不透明度、混合模式）。
  - 沒有像素的圖層略過。
  - **不透明度、混合模式、剪裁遮色片、圖層遮色片全部忽略**：素材就是圖層的原始像素，配置檢視以完全不透明、一般模式畫上去，匯出也是原始像素（見 5.）。
  - 名稱空白時給一個帶序號的預設名（新版自訂）。素材的檔名＝名稱裡的 `/ \ ? % * : | " < >` 換成「_」＋`.png`；**同名的圖層互相覆蓋**（見 5.）。
  - 沒有任何可用圖層時：F11。
- 只測過 8-bit RGB 的 PSD；ag-psd 支援的其他色彩模式依 ag-psd 的轉換（未實測）。

### 2.3 CCFOLIA 房間 ZIP（外部格式）

CCFOLIA「匯出房間」產生的 ZIP（本工具讀進來改圖再匯回）：

- **平面結構**：根目錄有 `__data.json`（房間資料）、`.token`（CCFOLIA 匯出時附帶的權杖檔；本工具原封不動保留）、所有圖片檔。
- **圖片檔名**＝圖片內容的 SHA-256（64 個小寫十六進位字）＋`.`＋副檔名（png、jpeg、webp、gif…）。JSON 裡以這個檔名引用圖片。
- `__data.json`：
  - `meta.version`（例：`"1.1.0"`）。
  - `entities.room`：`backgroundUrl`、`foregroundUrl`（背景、前景圖檔名，可為 null）；`fieldWidth`、`fieldHeight`（盤面大小，單位格，1 格＝24 px）；
    `markers`（`{ id: { x, y, z, width, height, angle, imageUrl, text, locked, … } }`，x、y 是左上角在盤面上的格座標，盤面中心為 (0,0)）；其他房間設定。
  - `entities.items`（畫面上的物件）：`{ id: { x, y, z, width, height, angle, imageUrl, coverImageUrl, memo, … } }`。
  - `entities.characters`：`{ id: { name, iconUrl, faces: [{ iconUrl, label }], x, y, z, width, height, angle, … } }`。
  - `entities.effects`（切入演出）：`imageUrl`；`entities.scenes`（場景）：`backgroundUrl`、`foregroundUrl`、`markers`、`fieldWidth`、`fieldHeight`…；
    `entities.notes`：`iconUrl`；`entities.decks`、`savedatas`、`snapshots` 等。
  - `resources`：`{ "<檔名>": { "type": "<MIME>" } }`——ZIP 裡每張被引用的圖片一筆。
- 舊版另外接受：資料檔叫 `data.json`／`room.json`、放在子資料夾、或任何 `.json`（F09）；房間資料在頂層、`data` 底下或 `entities` 底下都會找。
- **配置檢視找哪些物件**（F22）：房間的背景、前景，`room.markers`，`entities.items`、`entities.characters`（角色用 `iconUrl`）。
  場景、切入、角色表情、筆記的圖片不畫在配置檢視，只出現在面板的「沒被引用的素材」與清單裡（仍會調色、匯出）。
  舊版另外會找幾個非 CCFOLIA 的通用欄位與容器名稱，新版不需要。缺 z、寬高時舊版用自己的預設值（背景最下、前景最上），新版自訂。
- **引用對應到 ZIP 裡的圖**：CCFOLIA 的引用就是檔名，完整比對即可（必要時忽略路徑與大小寫）。舊版另外有幾層寬鬆的模糊比對（可能把不相干的圖對上），新版不需要。
- 判斷是不是房間（F09）：有任何帶圖片的物件，或 JSON 頂層有 `data`／`entities`。

### 2.4 錯誤

見 F06、F11。新版應指出是哪個檔案讀不到（改善，不需確認），而且壞掉的一張不應讓整批卡住（見 5.）。

## 3. 輸出

### 3.1 共通

- 輸出一律是一個 ZIP（DEFLATE 壓縮），檔名見 F94；或單張下載（F71）。
- 匯出前先確保素材都已處理：依載入順序逐張處理（處理中畫面顯示第幾個／共幾個；APNG 另顯示第幾格），最後打包。
- **看不見的素材**的處理見 F35。
- 調色結果＝單圖檢視器的大畫面（F70），逐像素相同（附件實測差 0）。

### 3.2 圖片模式

- 新 ZIP，每張素材以它的名稱（含資料夾路徑，例 `角色A/sub/b.jpg`）放入；資料夾會出現對應的目錄項目。
- **從 ZIP 進來的圖片模式**（F09 判定不是房間）：以原 ZIP 為底，同名的圖片換成處理後的內容，ZIP 裡的其他檔案（例如文字檔）原封不動保留；之後再加入的圖片也加進同一個 ZIP。
- 編碼見 3.5～3.7。

### 3.3 PSD 模式

- 新 ZIP，平面結構；每個看得見的圖層一個 `<名稱>.png`（名稱裡的 `/ \ ? % * : " | < >` 換成「_」）。
- 每張是**該圖層自己的範圍**（寬高＝圖層範圍，超出文件的部分也保留），沒有位置資訊、沒有合成圖。像素＝原始圖層像素套上調色（2.2 的忽略規則）。
- 同名圖層只剩一張（2.2）。

### 3.4 房間模式（外部格式的改寫規則）

以原 ZIP 為底（`.token` 與其他檔案原封不動）：

1. 每張**看得見的**圖片處理（3.5～3.7）後，算新內容的 SHA-256，新檔名＝`<新雜湊>.<原副檔名>`（**副檔名沿用原檔**，即使內容已是 PNG，例：`….jpeg` 的內容其實是 PNG）。
   舊檔從 ZIP 移除，新檔放在同一個資料夾。
2. 建一張「舊 → 新」對照：舊主檔名（64 字雜湊）→ 新雜湊；舊檔名 → 新檔名；含路徑的舊名 → 含路徑的新名。
3. 房間資料 JSON 裡**所有字串值與物件的鍵**：完全等於舊名的換成新名；包含舊名的把其中的舊名全部換掉。
   所以 `backgroundUrl`、`imageUrl`、`iconUrl`、`faces[].iconUrl`、場景、切入……所有引用與 `resources` 的鍵都跟著改；`resources` 的 `type` **不改**（JPEG 來源仍寫 `image/jpeg`）。
4. JSON 以**縮排 2 格**寫回原來的位置（第一個名為 `data.json`／`__data.json`／`room.json` 的檔；都沒有時寫在根目錄、用讀進來時的檔名）。欄位順序不變。
5. 沒被引用的圖片也照樣重新編碼改名（仍不在 `resources` 裡，與原檔一致）。
6. 看不見的圖片：不處理、保留原檔名與內容，JSON 對它的引用不變。
7. 縮小尺寸（3.6）不改 JSON 裡物件的寬高（CCFOLIA 會把圖拉回物件大小）。

附件「房間ZIP」有一組完整的輸入／輸出對照。

### 3.5 圖片的重新編碼

- **靜態圖**（含 JPG、WebP、GIF、單格 APNG）：一律以瀏覽器編碼成 PNG（8-bit RGBA），**名稱不變**（`photo.jpg` 的內容是 PNG）。GIF 動畫只剩第一格。
  沒調色也會重新編碼（房間模式因此每張都會改名）。原檔的中繼資料不保留。
- **APNG**：見 3.6。
- 3.7 的靜態壓縮只在 F84、F87 都開時發生。

### 3.6 APNG 輸出與容量壓縮

- **不壓縮時**（F84 關）：每一格都是合成後的完整畫面套上調色，無損編碼成 APNG（顏色不超過 256 種時自動用調色盤，仍無損）；編碼器可以只存與前一格不同的範圍。
  格數不變；延遲照原檔（毫秒），**延遲 0 的格變成 100 ms**；播放次數依 F88／F82（照原檔＝原檔的 `num_plays`）。
- **壓縮時**（F84 開，預設）：**每一個 APNG 都會走一次搜尋**，從最好的設定往下試，第一個不超過目標容量的就用：
  1. 尺寸比例 100% → 90% → 80% → 70% → 60% → 50% → 40%；每一種尺寸比例內，色數 256 → 192 → 128 → 96 → 64 → 48 → 32。狀態文字依序顯示正在試的組合。
     所以**即使原檔已小於目標，也會被減到 256 色以內**（原本超過 256 色的圖會有損，見 5.）。
  2. 都不行、F86 開著（而且格數不是太少；門檻由新版決定）：跳格——只留第 1、3、5…格，每格延遲＝自己＋下一格（100 ms 的動畫變成 200 ms），再從較高的尺寸比例往下找一次（只用較少的色數）。
  3. 還是不行：用尺寸比例 40%、32 色、全部格數輸出——**即使仍超過目標也照樣輸出、沒有任何提醒**（見 5.）。
  - 縮小以瀏覽器畫布縮放（平滑）；減色是有損的調色盤量化（含半透明）。播放次數同上。跳格成功的例子：1500×1500 雜訊 10 格、目標 2.0 MB → 尺寸 50%、32 色以內、5 格、每格 200 ms，約 1.77 MB，約 4.4 分鐘。
  - 實測（附件「容量壓縮」）：400×400 雜訊 5 格（約 2.62 MB）→ 100%、256 色、約 0.77 MB；1000×1000 雜訊 5 格（約 16.4 MB）、目標 2.0 MB →
    試了 25 種組合後落在 70%、96 色（約 1.91 MB），約 42 秒；1600×1600 雜訊 10 格、目標 2.0 MB → 49 種組合與跳格都不行，輸出 40%、32 色、10 格、約 2.58 MB（超過目標），約 5 分鐘。
- **容量壓縮試算**（F81）用同一套搜尋。

### 3.7 靜態圖容量壓縮（F84、F87 都開）

- 重新編碼後（3.5）不超過目標 → 不動（無損）。
- 超過 → 先在原尺寸減色（從 256 色往下），第一個不超過目標的就用。
- 還是不行 → 縮小尺寸並減色後直接輸出，不再檢查大小（依程式行為，未實測）。
- 不顯示狀態文字。實測：1400×1300 雜訊（重新編碼後約 5.97 MB）、目標 4.8 MB → 原尺寸 256 色約 1.74 MB；目標 10.0 MB → 不動。

### 3.8 調色的處理規則

#### 3.8.1 順序

每個（非完全透明的）像素依序：

1. **曝光**（乘倍率）→ **亮度**（加減）→ **對比**（以 128 為中心）→ 截到 0～255。
2. **曲線**：先三色一起的曲線，再該通道自己的曲線（紅／綠／藍）；有個別曲線時再接著套個別的三色曲線、個別的通道曲線。
3. **漸層對應**（開啟時）。
4. **色相、飽和度**（在色相／飽和度／亮度的色彩模型裡轉色相、乘飽和度，亮度不變）。
5. 四捨五入、截到 0～255；不透明度不變。

附件「組合與順序」逐項驗證了這個順序（例：漸層之後再降飽和度＝灰；亮度先加再查漸層）。

#### 3.8.2 曲線

- 每條曲線是控制點之間以直線相連的折線（F51），左右兩端以外照端點的值延伸；在 0～255 的整數上查表。
- 附件「曲線」：三色曲線一個點 (64→128)：灰 32 → 64、128 → 171；只有紅 (128→200)：灰 128 → (200,128,128)；藍反轉等。

#### 3.8.3 漸層對應

- **取色位置**＝像素在第 1、2 步之後的亮度（紅 0.299、綠 0.587、藍 0.114 加權，Rec. 601），0～255 對應漸層 0～100%。
  漸層在相鄰色標之間線性內插；第一個色標之前、最後一個之後照該色標的顏色延伸；色標順序以位置排序。
- **混合**（原色＝第 2 步後的顏色，漸層色＝取到的顏色）：
  - 一般：漸層色。
  - 色彩增值、濾色：標準的色彩增值與濾色。
  - 覆蓋：標準的覆蓋（依原色的明暗決定變暗或變亮）。
  - 柔光：接近常見的柔光（依漸層色的明暗決定變亮或變暗），暗部的變亮幅度略有不同；以附件為準。
  - 顏色：結果的亮度（同上的加權）等於原色、色調來自漸層色，超出範圍的通道被截掉，所以很亮或很暗的地方色調會偏；不是 Photoshop 的「顏色」模式，以附件為準。
- **強度**：依強度在原色與混合結果之間線性內插（附件有 100／75／50／25／0%）。
- 附件「漸層對應」有兩色標在六種模式、四種強度、三色標、色標不在兩端、開頁初始色標的取樣。

#### 3.8.4 個別調色與整體的疊加

- 色相：相加（整體 170 ＋ 個別 170 ＝ 340，等於 −20）。
- 飽和度：個別的百分比是在整體的倍率上再打折或加成（整體 150%、個別 −50% → 75%；個別 −100% 一定變灰；結果的飽和度不超過最大）。
- 亮度、曝光：相加（亮度可以加到 200）；對比：相加後夾在 −100～100。
- 曲線：整體之後再套個別（3.8.1）。
- 漸層對應：個別勾選套用（而且至少 2 個色標）時**用個別的漸層取代整體的**，否則用整體的。
- 附件「個別調整與整體疊加」逐項取樣。

### 3.10 對等驗證的比對方法

## 5. 容易做壞的地方

- **處理順序**（3.8.1）：先曝光、亮度、對比，再曲線，再漸層，最後色相與飽和度；順序錯了附件的組合取樣就對不上。
- **漸層取色用的是調整後的亮度**（Rec. 601 加權），不是原圖亮度、也不是 RGB 平均。
- **個別漸層是取代、不是疊加**；個別飽和度是乘、其他是加；對比相加後夾在 ±100。
- **曲線是折線**，不是平滑曲線。
- **完全透明的像素不動、不透明度不變**。
- **房間 ZIP 的改名**要同時改 JSON 裡所有出現舊名的地方（含 `resources` 的鍵），檔名必須等於新內容的 SHA-256，`.token` 與其他檔案原封不動。
- **壓縮開啟時所有 APNG 都會減色**（即使已小於目標）；搜尋順序是「先減色、再縮小」；最低設定仍超過目標時照樣輸出。
- **延遲 0 的 APNG 影格**輸出成 100 ms。
- **隱藏的素材在三種模式的匯出行為不同**（F35）。
- **PSD 只取原始圖層像素**：不透明度、混合、遮色片、剪裁都不套（目前的行為；是否改見下）。
- **ZIP 載入成圖片模式時會沿用原 ZIP**（其他檔案保留）。
