# 跑團紀錄簿（session-log）行為規格

## 0. 概要

玩家與 KP／GM 記錄自己玩過（帶過）的團的工具：每一團是表格的一列（日期、劇本、系統、身分、GM、PL、PC、狀態、時間、備註，
另可加最愛、HO、結局、生還／撕卡、長團、主題標籤、三種網址與自訂欄位）。上方有統計（跑團天數、劇本數、總遊玩時間、同團玩家人數），
可搜尋、依系統／身分篩選與排序；每一團可以在側欄寫詳細感想、結果、貼文與防雷連結，也能一鍵「送到團報產生器」。
資料可以從試算表（貼上或 CSV／TSV）、過去的團報文字、CCFOLIA 的房間資料與聊天紀錄、本工具的 JSON 匯入；
可以匯出成 JSON，或整理成「已通關劇本清單」文字（全部劇本、依系統、依 PL／KP、場次明細）。全部在瀏覽器內完成並自動存檔。

輸入：手動輸入、貼上的試算表或團報文字、CSV／TSV、CCFOLIA 房間資料（JSON／ZIP）與聊天紀錄（HTML）、其他跑團平台的文字紀錄、本工具的 JSON。
輸出：JSON 檔、範本 CSV 檔、清單文字（複製）、給團報產生器的交接資料（瀏覽器儲存空間）。

靈感來源：くま。的「TRPG WEBツール観測所」（<https://kumachansteps.github.io/trpg-web-tools/>）。原作未授權（作者站上規約另外禁止素材二次利用）：
範例資料、範本文字、長篇感想的範本、介面文案一律自寫；本規格只描述功能與規則。

用語：「列」＝表格中的一團；「正規值」＝存檔用的系統、狀態、生還的固定寫法（3.1）；「自己的名字」＝匯入時用來判斷身分、計算同團玩家時排除的名字（F71）；
「主要日期」＝一團日期清單中**最晚**的一天；「範例列」＝第一次開啟時放的示範資料（F34）。

## 2. 輸入

- **手動輸入**：任何文字（含引號、角括號、表情符號）原樣保存；畫面上不解讀 HTML。
- **試算表貼上／CSV／TSV**：第一行含 Tab 就當 TSV（每行以 Tab 切開，不處理引號），否則當 CSV（雙引號包住的欄位可含逗號、換行，`""` 是一個引號）。換行統一成 LF，結尾的空行去掉，整列空白的列略過，每格去頭尾空白，列長不一時補空格。
  CSV／TSV 檔以 UTF-8 讀（新版另自動辨認 Big5 與有 BOM 的 UTF-16，見 5.）。
- **團報文字**：任何文字（3.8.5）。
- **CCFOLIA・紀錄**：
  - JSON：副檔名 .json，或內容以「{」開頭且前 600 字內出現 `"kind"`、`"data"`、`"characters"`、`"name"`、`"params"` 其中之一的鍵。解析失敗的略過。
  - 其他（.html、.htm、.txt 或任何文字）：聊天紀錄。CCFOLIA 的舊格式與新格式由 `@/ccfolia` 的日誌解析讀；其他 HTML 以每個段落、表格列為一行；純文字以每行為一行（3.8.6）。
  - 新版另接受 CCFOLIA 房間 ZIP（取 ZIP 裡的房間資料）。
- **JSON 匯入**：任何含 `rows` 陣列的 JSON 物件（本工具新舊版的匯出都可以）；否則讀取失敗。
- **自己的名字**：以「、」「,」「/」或換行分隔。

## 3. 輸出與規則

### 3.1 一團的欄位與正規值

存檔與 JSON 中每一團是一個物件：識別碼、範例標記、日期清單（`YYYY-MM-DD`，排序、不重複）與第一天、劇本、系統、身分、GM、PL、PC、狀態、時間（小時數字字串）、備註、
長篇感想、團報勾選（是／否）、最愛（「★」或空）、HO、結局、生還、長團、主題標籤、跑團紀錄網址、劇本網址、感想網址、結果、貼文清單（種類、網址、說明）、
防雷連結（標籤、網址）、劇本計數鍵（3.6），以及自訂欄位。欄位名稱沿用舊版（舊版匯出的 JSON 可以直接讀入；新版匯出的 JSON 舊版也讀得懂），不認得的欄位照樣保留。

系統、狀態、生還以**日文正規值**存檔，畫面上換成繁中顯示名稱；輸入繁中顯示名稱（或正規值）都存成正規值，其他文字原樣保存：

| 種類 | 正規值 → 顯示名稱 |
|---|---|
| 系統（前 4 個是常用系統） | CoC 7版 → CoC 7版、CoC 6版 → CoC 6版、エモクロア → Emoklore、マダミス → 謀殺之謎、シノビガミ → 忍神、インセイン → Insane、ダブルクロス The 3rd Edition → 雙重十字 The 3rd Edition、ソード・ワールド2.5 → 劍世界2.5、フタリソウサ → 二人搜查 |
| 狀態 | 新規 → 新開、継続 → 延續、完結 → 完結、中止 → 中止、予定 → 預定 |
| 生還 | 生還 → 生還、ロスト → 撕卡、全生還 → 全員生還、全ロスト → 全員撕卡、継続 → 延續、不明 → 不明 |

身分：PL、KP、GM、DL（其他文字原樣）。「GM 組」＝ GM、KP、DL（不分大小寫）。

這組正規值與輔助規則（日期、人名、時間、劇本計數鍵、交接資料）是跑團紀錄簿與團報產生器共用的模組（`@/core/sessions`）。

### 3.2 統計（F10～F13）

範例列不算。跑團天數＝每列日期個數的總和。劇本數＝不重複的劇本計數鍵（大小寫視為不同）。總遊玩時間＝每列時間的第一個數字的總和；
畫面上整數照寫、有小數時四捨五入到一位並去掉「.0」，後面加「h」。同團玩家見 3.3。

### 3.3 人名

- 拆分：以「、」「,」「，」「/」「／」「&」「＆」「＋」「+」「;」「；」與換行分隔，也接受前後有空白的「と」與「and」（不分大小寫）；每段去頭尾空白、丟掉空的。**「・」不是分隔符號**（外文名字的間隔號）。
- 正規化（比對用）：Unicode NFKC、去頭尾空白、刪掉所有空白（含全形）、結尾的「。」「．」「.」換成一個「。」。
- 自己的名字＝內建的通用詞（新版：自己、自分、自分自身、GM、KP、DL，見 5.）＋F71 的名字，都經過正規化。
- 同團玩家：所有非範例列的 GM 欄與 PL 欄拆分後正規化，排除自己的名字，數不重複的個數。

### 3.4 日期與欄寬

- 整理：日期清單只留 `YYYY-MM-DD` 格式的值，去重複、排序；清單是空的而舊的「日期」欄有值時，先把它以「、」「,」「，」「/」「／」「・」「;」「；」與換行切開再整理。
- 主要日期＝清單最後（最晚）一天；表格日期欄、排序、清單輸出都用它。
- 彈性日期（匯入、側欄的日期欄）：含「→」「〜」「~」「–」「—」或單字「to」時當成範圍，取各段的日期（不補中間的日子）；否則有英文月份的寫法時以「、」「；」「;」或兩個以上空白分段，沒有時以「、」「,」「，」「;」「；」與空白分段。每段（NFKC 後）認得 `Month D, YYYY`（月份全名或縮寫，日可帶 st／nd／rd／th，逗號可省）與 `YYYY?M?D`（? 為 / . - 或 年、月）兩種寫法，都換成 `YYYY-MM-DD`；看不懂的段丟掉；結果去重複。
- 欄寬（px）預設／最小值：團報勾選 78／66、最愛 72／56、日期 136／112、劇本 310／180、系統 124／108、身分 96／78、GM 124／96、PL 170／110、PC 170／110、狀態 120／108、時間 84／72、備註 250／160、送出 116／116，其他欄 140／72；
  最大值劇本與備註 520，其他 360。

### 3.5 時間

去頭尾空白、NFKC。`H:MM`、`H：MM`、`H時MM分`（分可省）→ H＋MM÷60，四捨五入到小數兩位（例 3:30 → 3.5、1:20 → 1.33）；否則取第一個數字（`4h` → 4、`約 3.5 小時` → 3.5）；沒有數字時空白。表格顯示「N 小時」。

### 3.6 劇本計數鍵

有填劇本計數鍵（試算表可對應這一欄）時用它（去頭尾空白）；否則劇本名稱經過：NFKC → 底線（半形、全形）換成空白 → 刪掉「第 N 陣」「N 日目」（N 為阿拉伯、全形或中文數字）
→ 刪掉「前編」「後編」「上巻」「下巻」「作成会」「キャラシ作成会」「前篇」「後篇」「上篇」「下篇」→ 連續空白合併 → 去頭尾空白。
用途：劇本數（F11）、清單輸出的合併（3.7），以及清單上顯示的劇本名稱。

### 3.7 已通關劇本清單（F96～F101）

#### 3.7.1 共通

- 對象：非範例列，經 F95 篩選後，依主要日期由舊到新排列（沒有日期的排最後；同日維持存檔順序）。
- 合併成劇本：以劇本計數鍵（不分大小寫）合併；鍵是空的列不列入；每部劇本的「日期」＝其中最早的主要日期，代表列＝日期最早的那一列；依日期由舊到新排列。
- 顯示的劇本名稱＝代表列劇本名稱經 3.6 整理後的文字；是空的時用原名去頭尾空白；再是空的時「未設定」。
- 「PL 人數」＝代表列 PL 欄拆分（3.3）後的人數，至少 1，寫成「NPL」。
- 系統顯示名稱見 3.1；沒有系統的歸在「未設定系統」。系統的順序：CoC 6版、CoC 7版、エモクロア、マダミス 依序在前，其他依字串排序。
- 空白（全形 U+3000）是輸出的一部分；換行一律 LF；結尾沒有換行。沒有任何團時輸出空白。

#### 3.7.2 全部劇本

```
【全部劇本】共 {劇本數} 部（{團數} 團）

1. {劇本}　{日期}
2. {劇本}（×{次數}）　{日期}
```

次數＝合併到這部劇本的團數，大於 1 才寫。日期是 `YYYY-MM-DD`；舊版沒有日期時寫「9999-99-99」（見 5.）。團數＝篩選後的團數（含劇本計數鍵空白的）。

#### 3.7.3 依系統

每個系統一段，段落之間空一行：

```
【{系統}】共 {該系統的劇本數} 部
　{N}PL
　　1. {劇本}
　　2. {劇本}
　{N}PL
　　1. {劇本}
```

先合併成劇本（3.7.1），再依代表列的系統分組；組內依 PL 人數由少到多分小段，小段內依劇本日期排列、各自從 1 編號。

#### 3.7.4 依 PL／KP

把團依身分分成 PL、GM 組（標題寫「KP / GM」）、其他（標題寫「其他」，含沒有身分的），依此順序、沒有團的組不出現；組與組之間空兩行：

```
■ 以 {PL|KP / GM|其他} 身分通關（{該組的劇本數} 部）
【{系統}】
　{N}PL
　　1. {劇本}
（系統之間空一行）
```

### 3.8 匯入

#### 3.8.1 試算表的標題辨識（F73、F76）

- 第一列每格與「欄位別名表」比對：比對前把文字的小型大寫字母（Notion 標題常見的 ᴛɪᴛʟᴇ 等）換回一般字母、NFKC、轉小寫、刪掉空白、底線、「・」「／」「/」、括號與句點。
  完全等於某欄位的別名就對應該欄；都沒有時，別名（兩個字以上）是它的一部分就對應該欄（依欄位順序第一個符合的）。
  別名表涵蓋日文、英文、繁中的常見寫法（日期、劇本、系統、身分、GM、PL、PC、狀態、時間、備註、長篇感想、長團、主題標籤、結局、生還、三種網址、劇本計數鍵），以舊版的表為準，新版可以增補繁中別名。
- 標題是「KP」或「PL」，而且下面（最多 7 列）非空的值全部是是非值（yes／no、true／false、✓、✗、○、×、はい／いいえ、有／無、y／n、1／0 等）時，對應成「KP 欄」「PL 欄」（是非旗標，3.8.2）。
- 第一列辨識出的欄位數 ≥ min(2, 欄數) 時，第一列當標題（欄名用原文，空的寫「第 N 欄」）；否則全部當資料，欄名「第 N 欄」、全部不對應。

#### 3.8.2 一列 → 一團

1. 依對應取值（空的略過）；兩欄以上對應同一欄位時以「 / 」連接。KP 欄／PL 欄的值是肯定值（yes、true、✓、はい、有、○、●、y、1、kp、pl、参加、通過、済 等）而且還沒有身分時，身分設成 KP／PL。
2. 整理：日期依彈性規則（3.4）換成日期清單；系統先比對匯入別名（NFKC、小寫：エモクロアtrpg、マーダーミステリー、新クトゥルフ神話trpg、クトゥルフ神話trpg、coc6、coc 6版、新克蘇魯神話trpg、克蘇魯神話trpg、謀殺之謎、emoklore…，以舊版為準），否則顯示名稱換正規值；
   狀態、生還換正規值；身分比對別名（キーパー、kp、ゲームマスター、マスター、gm、ディーラー、dl、プレイヤー、pl、主持人、守密人、玩家）或轉大寫後在 PL／KP／GM／DL 裡；時間依 3.5；GM、PL、PC 欄的「｜」換成「、」（連續的合併、去頭尾）。
3. 沒有身分時依自己的名字推測：PL 欄有自己 → PL；否則 GM 欄有值時，GM 全部是自己 → KP，不然 → PL。
4. 補值：識別碼、日期整理（3.4）、狀態空白時「新規」、F107 的系統與身分整理。
5. 劇本、日期、PC、GM 都空的列不匯入。

#### 3.8.5 團報文字（F79、F80）

- 換行統一、去行尾空白、去頭尾空白。非空行中「數字＋.／．／) 開頭」的行有 3 行以上而且佔 40% 以上時，當成**清單文字**：

  編號行以「/」「／」切成 劇本／系統／身分／日期，缺的用分組的值；劇本去掉各種括號。
- 否則以「連續兩個以上空行」或「一行 3 個以上的 - = — ― ━ ─ _」分成多筆，每筆：
  - 長篇感想＝整筆原文；主題標籤＝所有 `#…`（去重複，以空白連接）；日期＝第一個 `YYYY?M?D`（年份 19xx／20xx）。
  - 系統：依序比對（新克蘇魯／new coc／coc7 → CoC 7版；克蘇魯神話TRPG／coc6 → CoC 6版；其他克蘇魯／Call of Cthulhu／coc → CoC 7版；エモクロア／emoklore；謀殺之謎／マダミス／murder mystery；忍神；Insane；雙重十字；劍世界；二人搜查，含日文寫法）。
  - 劇本：第一個「」『』【】《》〈〉 括號裡、不是系統名稱也不是身分標記的文字；沒有時用系統名稱那一行（30 字以內）的下一行。
  - GM：「KP：名字」「GM｜名字」「KPC/KP 名字」這類行（分隔可以是 ： : ┊ | ｜ ・ / ／ 或空白），以及單獨一行「KP」「GM」等的下一行；去掉敬稱（樣、さん、氏、桑），24 字以內、不是系統名稱；去重複後以「、」連接。
  - 參加者：「PC/PL」「PL・PC」等標題行之後（沒有標題行時從頭找）每行以「/」「／」「|」「｜」「┊」切成兩段的就是一組；標題寫 PL 在前時第一段是 PL，否則看哪一段帶敬稱決定順序；行首的 HO／PC＋數字記成 HO。
    遇到主題標籤、日期、END／生還／撕卡等結果行時結束。PC 以「 / 」、PL 以「、」連接（去重複）。

  - 劇本、GM、PL、日期都沒有的不算一筆。
- 每行比對前會去掉行首的裝飾記號（▶ ・ ★ ◆ ┗ 等）與行尾的裝飾。細節以舊版為準（對等驗證用隨機與實例比對）。

#### 3.8.6 CCFOLIA・紀錄（F81～F84）

- 房間資料 → 房間名稱與角色名稱：舊版在 JSON 裡找「種類是 room 的 data.name」或帶角色清單等特徵的物件的 name，以及「種類是 character 的 data.name」與所有 `characters` 陣列裡的 name。
  新版：CCFOLIA 房間資料用 `@/ccfolia` 的 `resolveRoomData`（房間名稱在 room.name 時採用；角色取 `entities.characters` 的每一筆，物件或陣列都可以）；角色剪貼簿 JSON 用 `parseCharacterClipboard` 的角色名稱；其他 JSON 照舊版的找法（見 5.）。
  房間名稱去掉系統標記（【CoC】等）、「/ KP: …」「KP: 名字」、「募集中／満卓／終了…」等字樣。
- 聊天紀錄 → 一場：標題（不是預設的「ccfolia - logs」時）去掉上述字樣當劇本，沒有時用檔名去掉副檔名、「[all]」「[ログ]」等標記與結尾的「第 N 回」「part N」「day N」等；
  每一行取發言者（CCFOLIA 格式由日誌解析得到；其他 HTML 以段落裡的 span；沒有時從「名字：內容」「[分頁] 名字: 內容」的寫法取），清掉開頭的記號與結尾括號裡的假名讀音；
  略過 system、BCDice、ダイス、情報等系統名稱，以及只有數字、以裝飾記號開頭、「HO1」「OP」「ED」「導入」「幕間」之類的名稱；超過 24 字的略過。
  每位發言者記發言次數與擲骰次數（內容含 `NdM`、`CCB<=`、`SCC`、`1d100`、判定結果字樣等）。
- 日期：行內出現 `YYYY-MM-DD HH:MM` 或 `YYYY/MM/DD HH:MM` 的時間戳記（行首的佔 40% 以上且至少 10 行，或任意位置至少 3 行）時採用；以「有擲骰的日子」為優先，沒有時用所有出現過的日子；
  都沒有時用第一個時間戳記的日子，再沒有時用檔案的修改日期。新版另讀 CCFOLIA 新格式的時間欄位（見 5.）。
- 系統：先看劇本名稱；再看內文：出現エモクロア → Emoklore；`CCB<=` 與 `CC<=` 的次數比較（CCB 多或相同 → CoC 6版，否則 CoC 7版）；六面骰池 6 次以上而且有成功數等字樣 → Emoklore；最後比對內文前 20,000 字的系統名稱。
- 發言者清單：房間資料的角色（「棋子」，一場時全部套用；多場時套到檔名相同的那一場）＋發言 2 次以上或擲骰 1 次以上的人；依擲骰次數、發言次數、是否為棋子排序。

- 表單（單場）：GM＝指定為 KP・GM 的名字（身分標籤除外，去重複，以「、」連接）；PL＝指定為 PL 的名字；PC＝指定為 PC 的名字（以「 / 」連接）；
  身分：KP・GM 中有自己，或有 KP・GM 而 PC 中沒有自己 → KP；PC 或 PL 中有自己 → PL；有 KP・GM → PL；否則空白。
- 多場轉成格線時每一列：日期（多個以「, 」連接）、劇本、系統、身分（KP・GM 中有自己 → KP；PC 或 PL 中有自己 → PL；有 KP・GM → PL）、GM、PL、PC，再經 3.8.2 第 2～4 步整理後的值。

### 3.12 對等驗證的比對方法

1. **資料比對（腳本）**：同一組輸入分別餵給舊版與新版（舊版在本機開 `tools/session-log/`，新版開 `next/session-log/`），比對：

   - 交接資料（3.9，識別碼與時間不比）；JSON 匯出的 `rows`（識別碼不比；新版多的欄位不比）。
   輸入至少包含：自編的試算表（Tab、CSV、Notion 小型大寫標題、是非旗標欄、多欄對應同一欄位、英文月份與範圍日期）、自編的團報 10 篇以上（日文與繁中寫法、各種分隔線與裝飾記號）、

2. **隨機比對**：至少 500 組隨機列（隨機系統、身分、狀態、生還、日期 0～3 天、PL／PC／GM 名字含各種分隔符號、劇本含「第 N 陣」等字樣、時間各種寫法），比對統計、四種清單輸出、交接資料逐字相同。
3. **互動**（F15～F69、F70～F91 的操作、F102～F113）以 Playwright 操作兩邊，比對表格的列、欄位順序與寬度、存檔還原後的結果。

## 4. 互動與手感

- 統計數字：從 0 跑到新值約 0.7 秒（ease-out，三次方）；減少動態效果時直接顯示。
- 提示訊息約 2.6 秒消失；匯入的列亮起約 2.2 秒；複製鈕的「已複製」約 1.4 秒。

- 側欄從右側滑出約 0.28 秒；寬約視窗的 70%（最多 1,320 px），窄螢幕約 94%（最多 430 px）。

## 5. 容易做壞的地方

- **正規值**：系統、狀態、生還一律存日文正規值；畫面顯示繁中。繁中顯示名稱（例如「謀殺之謎」「撕卡」「延續」）輸入時要存回正規值，而且「延續」在狀態與生還各自換成同一個正規值「継続」。
  團報產生器也依正規值判斷系統，所以交接資料的 `system` 必須是正規值。
- **主要日期是最晚的一天**：表格日期欄、排序、清單輸出的日期與排序都用它；但重複判斷（3.8.4）用的是**第一天**。
- **劇本數的大小寫**：統計（F11）大小寫視為不同；清單輸出的合併不分大小寫。兩者照舊。
- **清單輸出的小規則**：PL 人數至少算 1（PL 欄空白也是 1PL）；沒有系統的歸「未設定系統」（不是「未設定」）；劇本計數鍵空白的團不列入合併，但算進「全部劇本」標題的團數。
- **人名拆分不含「・」**，否則外文名字會被切成兩人。
- **時間「3:30」是 3.5 小時**，不是 3.3。
- **匯入的身分推測**要在所有欄位整理之後、補預設值之前做（範例：GM 欄全是自己 → KP）。
- **重複判斷包含同一批前面的列**，所以同一份試算表裡重複的兩列只匯入第一列。
- **試算表的「KP」「PL」欄**：值都是是非值時是身分旗標；有名字時是 GM／PL 欄。
- **CCFOLIA 分頁不能直接匯入**，一定要先轉成試算表格式（多場時自動轉）。
- **團報勾選的變更不取消範例標記**；在對話框儲存才取消。
- **編輯對話框的身分、狀態選單沒有空白選項**：原本空白的值一開對話框再儲存就變成 PL／新開（照舊）。
- **欄位面板只會同時開一個**；重設欄位不會刪掉自訂欄位的定義。
- **舊版的存檔鍵名**是 `sessionLogTool.state.v1`、自己的名字 `sessionLogTool.selfNames.v1`。新版上線後與舊版同網址，要在第一次開啟時把舊資料搬過來，否則使用者看起來資料不見了（新版做法：新版沒有存檔、而舊鍵有資料時搬入，舊鍵保留不刪）。
- **交接資料的鍵名與格式沿用舊版**，新版的團報產生器還沒上線時，舊版團報產生器也能讀。
