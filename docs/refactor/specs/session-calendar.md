# 團期行事曆（session-calendar）行為規格

## 0. 概要

把跑團的**場次**（劇本、時間、GM、參加者、準備事項）和其他**預定**（出差、旅行、空檔標記，可以跨好幾天）排在同一張月曆／年曆上的工具。
月曆標出臺灣的國定假日、補假與補行上班；右側列出今天的預定、準備事項清單（勾選完成、拖曳排序）與選取那一筆的詳細。
在月曆上按住拖過幾天就新增預定、拖曳色條換日子；「空檔日期」依條件列出沒有預定的日子（可以複製貼到揪團訊息）；
這個月或整年存成 PNG；匯出入 JSON 與 iCal（讀得懂兩個原作的 JSON，也讀得懂 Google 日曆匯出的檔案）；選取的場次可以送到跑團紀錄簿（記成一團）或團報產生器。
全部在瀏覽器內完成並自動儲存，另有共用的專案檔。

輸入：手動輸入、拖曳、JSON（本工具、卓準備カレンダー、taku_calendar、跑團紀錄簿、交接資料）、iCal（.ics、Google 日曆匯出的 ZIP）、背景圖片、專案檔。
輸出：JSON、iCal（.ics）、PNG（月曆、年曆）、空檔日期的文字（複製）、給跑團紀錄簿與團報產生器的交接資料（瀏覽器儲存空間）、專案檔（JSON；有背景圖片時 ZIP）。

靈感來源（兩個原作合成一個工具）：

- **卓準備カレンダー**（くま。／TRPG WEBツール観測所，v0.13 <https://kumachansteps.github.io/trpg-web-tools/tools/session-check-calendar/>；
  功能以 v0.11〔`880b00c`〕與 v0.13 的聯集為準，v0.13 只改了設計與說明文字）。下文記作 **K**。
- **taku_calendar**（utiyoso，<https://github.com/utiyoso/taku_calendar>）。下文記作 **T**。

兩個原作都**未授權**：只參考功能、選項與數值；程式、版面、外觀、範例資料、介面文字全部自己做（繁中），不放 `UPSTREAM_LICENSE`。
頁尾的靈感來源是卓準備カレンダー（registry）；taku_calendar 由主控寫進 ATTRIBUTION。

用語：「筆」＝行事曆上的一個場次或預定；「場次」＝跑團的一團（K 的セッション）；「預定」＝其他行程（T 的予定）；
「準備事項」＝屬於某個場次的待辦（K 的準備タスク）；「行事曆名稱」＝一筆所屬的分組（K 的 sourceCalendar，讀入時可以只選某幾個）；
「選取的日期」＝點過的那一天（K 的フォーカス日）；「色條」＝月曆上跨日畫的條；「小卡」＝月曆格子裡單日的場次與準備事項；「本週」＝今天所在的那一週（依週的第一天）。

## 2. 輸入

- **JSON**（F56）：UTF-8（開頭的 BOM 略過）。格式依內容判斷（3.7.2）；看不懂、不是 JSON 時「無法讀入」＋原因，不改資料。一次最多 5000 筆，多的不讀並說明；加上現有的超過 5000 筆時依日期早的先讀（F59）。
- **iCal**（F58）：`.ics`／`.ical`（文字以 `BEGIN:VCALENDAR` 開頭）；ZIP（Google 日曆匯出）裡副檔名 `.ics`／`.ical`／`.ifb` 的檔；ZIP 裡沒有時「ZIP 裡沒有 .ics 檔。」。
- **選檔**：JSON 一次一個；iCal 可以多選（合併成一次讀入）。拖進視窗（F08）不分種類，依內容判斷；同時拖 JSON 與 .ics 時一起讀。
- **背景圖片**（F69）：瀏覽器解得開的圖片；讀不到時「讀不到這張圖片。」；存不進瀏覽器時提醒重新整理後會不見。
- **專案檔**（F06）：共用的專案檔（JSON 或 ZIP）；內容整理（3.1）後看不懂、背景圖片不在 ZIP 裡也不在這個瀏覽器時，顯示原因、不改資料。
- **日期與時間**：日期欄是瀏覽器的日期欄（`YYYY-MM-DD`）；讀檔時日期要是存在的日子（1900～2200 年），時間接受 `H:MM`、`HH:MM`、`HHMM`（全形數字也可以），看不懂的時間當成空白。

## 3. 輸出與數值

### 3.1 資料模型（存檔、專案檔、JSON 共用）

一筆（場次與預定是同一種資料，以 `kind` 區分；預定不顯示場次的欄位，但照樣保留）：

| 欄位 | 內容 |
|---|---|
| `id` | 識別碼（讀入時與現有的重複就換新的；準備事項的也是） |
| `kind` | `session`（場次）／`plan`（預定） |
| `title` | 劇本名稱／標題（最多 300 字；空白時顯示「（未命名的場次）」「（無標題）」） |
| `start`、`end` | `YYYY-MM-DD`，`end ≥ start`（讀檔時顛倒的對調） |
| `startTime`、`endTime` | `HH:MM` 或空字串 |
| `color` | `{ mode: 'solid' \| 'gradient', c1, c2 }`（小寫 `#rrggbb`） |
| `memo`、`calendar` | 備註、行事曆名稱（空白時場次「跑團」、預定「預定」） |
| `system`、`gm`、`format` | 原文 |
| `status` | `scheduled`（確定）／`tentative`（調整中）／`completed`（完成） |
| `tags` | 主題標籤（不含 #） |
| `players` | `{ pl, pc }[]`（最多 50） |
| `links` | `{ label, url }[]`（最多 30；`url` 只留 http、https、mailto，沒有開頭的補 `https://`，其他的換成空白——讀檔也一樣） |
| `tasks` | `{ id, title, due（YYYY-MM-DD 或空）, done, order }[]`（最多 100） |
| `sample` | 範例（JSON 匯出時拿掉） |

行事曆：`title`、`weekStart`（0／1）、`showHolidays`、`showTasks`、`shotWidth`、`look`（3.5）、`entries`、`cpColors`（`{ id, name, c1, c2 }[]`，最多 40）。
讀回時缺的欄位補預設值、範圍外的夾住、看不懂的換成預設、不認得的欄位丟掉；一個行事曆最多 5000 筆。

### 3.2 日期

- 日期一律是本地（臺灣）的國曆日期字串；星期、加減天數用 UTC 的日序算，不受電腦時區影響。「今天」是電腦的本地日期。
- 寫法：「10月27日（二）」「2026年10月27日（二）」「10/27（二）」；範圍「10月27日（二）～10月29日（四）」（跨年時兩邊加年份）。
- 本週＝今天所在那一週（週的第一天起 7 天）。

### 3.3 月曆的版面

- 色條：預定（不論天數）與 `end > start` 的場次。一週裡依開始日 → 天數多的在前 → 開始時間 → 標題排序，放進第一個在這一段開始前已經結束的條；第 4 條以後不畫，算進經過的每一天的「另有 N 筆」。
- 小卡：單日的場次依開始時間（沒有時間的在後）排序，接著是期限在那天的準備事項（所有場次的，依場次的順序）；每天最多 3 張，多的算進「另有 N 筆」。
- 漸層被週（年曆被日子）切開時，每一段取整條漸層的那一段顏色（第 i 天到第 i＋n 天＝c1→c2 的 i/總天數 到 (i＋n)/總天數），拼起來是連續的。
- 拖曳：滑鼠移動超過 4 px 才開始；觸控按住 0.4 秒才開始、之前滑動超過 8 px 當成捲動。目標日子取指標下的格子（色條、小卡底下的也算）；放開時指標不在任何日子上（月曆外）＝取消。

### 3.4 準備事項

- 清單的順序：`order` 小的在前，同順序時期限早的在前（沒有期限的在後），再依名稱。新的準備事項排在最後（目前最大的順序取整到 10 的倍數再加 10）。
- 排序後所有準備事項的順序重新編成 10、20、30…。
- 狀態（今天＝電腦的本地日期）：完成 → 完成；沒有期限 → 不顯示；期限 < 今天 → 已過期；＝今天 → 今天；≤ 今天＋3 天 → 3 天內；其他不顯示。

### 3.5 外觀

- 介面配色：行事曆用頁面的設計 token（文字、次要文字、框線、surface、danger〔假日〕、accent〔星期六、強調〕）。
- 自訂背景：背景只套在行事曆區；格子的底色是「格子的底色＋不透明度」；格子（與背景依不透明度混合）的相對亮度 > 0.35 算亮：假日 #c93c3c、星期六 #3c5fc9、強調 #7b5ea7，暗時 #ff8f86、#93b2ff、#c9b3ea。
- 自動配色：背景的代表色（漸層三色、花紋的底色、圖片＝灰色以淡化的比例混白）平均相對亮度 > 0.4 時：主要文字＝第一個代表色混黑 78%、次要文字混黑 52%、框線混黑 16%、格子白色 80%；否則主要文字混白 90%、次要混白 62%、框線混白 30%、格子黑色 32%。
- 花紋一格是 48 × 48 的 SVG（本站自己畫），以「大小」的 px 並排（愛心、星星 1.4 倍）。

### 3.6 空檔日期

一天算空檔：在期間裡、不是被勾選種類的筆涵蓋的日子（調整中的場次依設定）、不在排除的日期與星期、（排除國定假日時）不是國定假日、符合對象（週末與放假日＝`isDayOff`；上班日＝不是）。依日期排序後依格式（F83）寫出。

| 有 `items` 陣列 | 交接資料 | 每個項目一個場次（`latestDate`，沒有時第一個日期）；行事曆名稱：`source` 是 `session-log-tracker` 時「跑團紀錄簿」，否則「卓準備カレンダー」 |

#### 3.7.3 匯出 iCal

- `BEGIN:VCALENDAR`、`VERSION:2.0`、`PRODID:-//TRPG Toolkit//session-calendar//ZH-TW`、`CALSCALE:GREGORIAN`、`METHOD:PUBLISH`、`X-WR-CALNAME:<標題>`（有標題時）；每一筆一個 VEVENT；行尾 CRLF。
- VEVENT：`UID:<id>@trpg-toolkit`、`DTSTAMP`（匯出的 UTC 時刻）、`SUMMARY`（顯示用的標題）；
  有開始時間：`DTSTART` 是本地時間換成 UTC（`YYYYMMDDTHHMMSSZ`），有結束時間時 `DTEND`＝結束日的結束時間（同一天而且不晚於開始＝隔天），沒有結束時間而且多日時 `DTEND`＝結束日的隔天 00:00，單日沒有結束時間時沒有 `DTEND`；
  整天：`DTSTART;VALUE=DATE:<開始日>`、`DTEND;VALUE=DATE:<結束日的隔天>`。
  `CATEGORIES`（行事曆名稱）、場次的 `STATUS`（TENTATIVE／CONFIRMED）、`DESCRIPTION`（場次：系統、GM／KP、形式、狀態、參加者、有網址的連結、準備事項〔☑／☐ 名稱（期限）〕、主題標籤；空一行後是備註）、
  `X-TRPG-CALENDAR`（整筆的 JSON，本工具讀回時完整還原；其他 App 忽略）。
- 文字跳脫 `\\`、`\;`、`\,`、`\n`；每行超過 75 位元組時折行（CRLF＋空白，不切開一個字）。

#### 3.7.4 讀入 iCal

- 展開折行（CRLF／LF＋空白或 Tab）；拆屬性（參數的引號裡可以有冒號）；`VALARM` 等巢狀的元件略過。
- 行事曆名稱：`X-WR-CALNAME` → 第一個 `CATEGORIES` → 檔名（不含副檔名）。
- 日期：`VALUE=DATE` 或只有日期＝整天（`DTEND` 是隔天，所以結束日＝DTEND−1）；`…Z`＝UTC 換成本地時間；`TZID=…`＝那個時區的牆上時間換成本地時間（用瀏覽器的時區資料，不認得的時區當成本地時間）；沒有時區＝本地時間。沒有 `DTEND` 時看 `DURATION`。
  有時間的事件結束在隔天而且不晚於開始時間（過午夜）時，日子算到開始那天；結束在 00:00 的多日事件算到前一天、沒有結束時間。
- `STATUS:CANCELLED` 略過（計數）；有 `RRULE` 的只讀第一次（計數）；`DTSTART` 看不懂的略過（計數）。`LOCATION` 加在備註後面（「地點：…」）；`STATUS:TENTATIVE`→調整中。
- 有 `X-TRPG-CALENDAR` 時用它完整還原（讀成場次／預定的選項不改它）。
- 讀成：自動＝有開始時間的當場次、整天的當預定；改種類時預設色換成那一種的預設色。

### 3.10 臺灣的國定假日（`@/core/holidays`）

- **2017～2027 年：公告**。行政院人事行政總處的「中華民國政府行政機關辦公日曆表」（政府資料開放平台 <https://data.gov.tw/dataset/14718>，依《政府資料開放授權條款－第 1 版》使用，相容 CC BY 4.0）；
  因為環境連不到政府網站，用 GitHub 上整理這份開放資料的 ruyut/TaiwanCalendar（CC BY 4.0；`data/<年>.json`，2026-10-27 取得），精簡成「不是平常的日子」的表：放假的日子（含落在週末、有名稱的國定假日）與週末的補行上班，名稱照公告原文（例如 2017～2020 年「調整上班」、2021 年起「補行上班」、2020-04-03「放假」）。
  單元測試把每一天放不放假、有說明的日子的說明和公告的資料逐日比對（`tests/fixtures/tw-calendar-official.json`）。
- **2028～2099 年：推算**（標示「推算」，F15）。依《紀念日及節日實施條例》（2025-05-28 公布）：
  - 放假的節日：開國紀念日（1/1）、小年夜（除夕前一天）、農曆除夕、春節（正月初一～初三）、和平紀念日（2/28）、兒童節（4/4）、清明節（清明當天）、勞動節（5/1）、端午節（五月初五）、中秋節（八月十五）、孔子誕辰紀念日／教師節（9/28）、國慶日（10/10）、臺灣光復暨金門古寧頭大捷紀念日（10/25）、行憲紀念日（12/25）。同一天兩個節日只放一天（名稱以「、」連接）。
  - 補假：逢星期六補前一個上班日、逢星期日補後一個上班日；春節連假（小年夜、除夕、初一～初三）逢週末的天數依序補在連假之後的上班日；補假可以落在前後一年（例：2033-01-01 是星期六 → 2032-12-31 補假）。
  - 兩個節日落在同一個週末日（例：2042-09-28 是星期日，中秋節與孔子誕辰紀念日／教師節同一天）時，**各補一天**：星期日往後補兩個上班日（2042-09-29、09-30），星期六往前補兩個上班日（2080-09-28 是星期六 → 09-27、09-26）。依據：2020 年兒童節與民族掃墓節同在星期六（4/4），補了 4/2（補假）與 4/3（放假）兩天；條例「放假日逢例假日應予補假」是每個節日各自適用。落在上班日時照放一天、不補。
  - 兒童節與清明同一天：「兒童節及清明節」，兒童節移到前一天（4/4 是星期四時移到後一天）以「補假」顯示；移過去的日子是週末時不顯示，改照上一條補。
  - 不推算調整放假與補行上班（每年另外公告）。
  - 用推算算 2026、2027 年，和公告逐日一致（單元測試）。
  - 同一套推算換上當年的規則（2025 年以前沒有小年夜、勞動節不放假，2024 年以前沒有孔子誕辰紀念日、臺灣光復節、行憲紀念日，2025 年以前叫「民族掃墓節」）算 2017～2027 年，和公告逐日比對：除了公告另外調整的「調整放假」「補行上班」（與它們換掉的日子）以外完全一致，包含 2020 年的雙補假（單元測試）。
- 農曆節日與清明：2017～2100 年的國曆日期表（以 lunar-javascript 1.7.7〔MIT〕的壽星天文曆算好、只存日期事實）；2017～2027 年與公告一致。不用瀏覽器的 `Intl` 農曆：ICU 78 在 2027、2030 年的正月初一差一天（官方 2027 年春節是 2/6）。
- 2016 年以前、2100 年以後沒有資料：只有週末算放假（F15 說明）。

## 4. 互動與手感

- 版面：寬畫面（≥ 1024 px）左邊行事曆區、右邊 22rem 的欄（今天的預定、詳細、準備事項、外觀與設定；今天的預定在最上面，選取時出現的詳細不推動它）；窄畫面上下排列（行事曆在上），390 px 寬不得橫向捲動（月曆的格子縮小、小卡的時間不顯示、假日名稱換行）。
- 選取：點日子選日期（聚焦列、詳細欄列出那天的筆）；點一筆選那一筆（同時選它的日期）；Esc 或 × 取消。選取不能讓雙擊的兩下之間版面移動（聚焦列一直都在、高度固定；詳細欄在今天的預定下面、日子清單下面）。
- 對話框：新增／編輯的對話框點外面不關閉（避免丟掉輸入）；Esc、×、取消不儲存。
- 提示（約 2.6 秒）：已新增、已儲存、已刪除、已移動、已調整順序、「名稱」完成、已讀入 N 筆、已匯出、已存成 PNG 等。
- 拖曳中整個月曆不選取文字；觸控按住後拖曳時不捲動頁面。

## 5. 容易做壞的地方

- **日期的時區**：日期字串的星期與加減一律用 UTC 的日序；`new Date('YYYY-MM-DD')` 是 UTC 午夜，在臺灣以西的時區會差一天。
- **iCal 的整天結束日是隔天**：讀寫都要 ±1 天。
- **過午夜的場次**：結束時間比開始早時，iCal 的 DTEND 在隔天，讀回時日子仍是開始那天（不能變成兩天）。
- **補假跨年**：1 月 1 日是星期六時補假在前一年 12 月 31 日——推算某一年時要連前後一年的節日一起算。
- **公告的「小年夜」**：2023～2025 年是調整放假（另有補行上班），2026 年起才是法定節日；推算只用在 2028 年以後。
- **`Intl` 的農曆不可靠**（3.10）。
- **拖曳與點擊**：拖過幾天放開時不能再觸發那一格的點擊（選取）；沒有離開那一天就是點擊。色條、小卡蓋在格子上，找目標日子要看指標下所有的元素。
- **一次的操作各自一步復原**：新增、刪除、移動、勾選在 0.4 秒內接連發生時不能併成一步（共用 store 的連續變更合併只給外觀與設定）。
- **第一下點擊讓版面移動**：雙擊的第一下會選取，選取時出現的東西（聚焦列、詳細）不能把第二下要點的東西推走。
- **「今天」會過期**：分頁開著過了午夜，今天、本週、準備事項的狀態要跟著換。
- **連結的網址**：讀檔與輸入的網址會變成 `<a href>`，`javascript:` 之類的不能留。
- **讀入的上限**：加入時要算上現有的筆，說明寫實際的筆數。
- **交接資料的鍵名與格式**：紀錄簿、團報產生器各自讀固定的鍵；團報產生器不看 `source`，紀錄簿只讀自己的鍵——兩個鍵不能搞混。
- **讀入時的識別碼**：同一份檔案讀兩次、或從本工具匯出又讀入時，筆與準備事項的識別碼要換新（準備事項的排序靠識別碼）。
