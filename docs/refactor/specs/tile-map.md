# 圖塊地圖產生器（tile-map）行為規格

## 0. 概要

手動擺圖塊畫 VTT 戰鬥地圖的編輯器：固定大小的方格地圖（4～200 格），好幾個圖層（地面、牆壁、物件…），
每個圖層的每一格放一張圖塊（或空的）。用畫筆、橡皮擦、填滿、圖形（長方形、橢圓、正圓、菱形、三角形、直線，可以只畫外框）、
滴管畫；選取工具框選之後跨圖層搬動、轉 90°、左右翻轉、刪除；整張地圖可以整個位移。圖塊來自內建的圖塊組
（本站的簡易地形、Kenney 的兩個 CC0 圖塊包），也可以匯入自己的圖塊表（切成 16、32 px 或自訂大小；拖曳框起好幾格變成一個「大圖塊」）
或一張張的圖，放在這個瀏覽器的「圖庫」裡，每一張地圖共用。畫好的地圖匯出 VTT 用的 PNG（每格幾 px），
或照實際尺寸（每格幾英寸）分頁的列印用 PDF；也可以直接交給地圖演出產生器（map-fx）。

輸入：滑鼠、觸控、鍵盤的編輯操作；自己的圖塊圖片（PNG、JPEG、WebP）；本工具的專案檔（ZIP）；圖庫備份（ZIP）。
輸出：PNG、列印用 PDF、專案檔（ZIP：地圖＋用到的自訂圖塊的圖）、圖庫備份（ZIP）、交給 map-fx 的圖。

靈感來源：**deukrezia／Trials — VTT Battlemap Maker**（<https://github.com/deukrezia/trials>；讀的是 `dd4f118`，2026-11-05）。
原作的程式**未授權**（README 與 package.json 寫「The software source is currently UNLICENSED」）：只參考功能、演算法與數值，
程式照本站的結構重寫；介面文字、說明、範例地圖都是本站自己做的；原作自己的預設圖塊（`assets/defaults/default-tiles.png`，作者的作品）不收。
原作附的 Kenney 圖塊包是 **CC0 1.0**，收進本站當內建圖塊組（`web/src/tools/tile-map/assets/kenney-*/`，各附 `LICENSE.txt`、`meta.json`，
建置時列進 THIRD_PARTY_NOTICES；分類與中文名稱是本站看圖寫的）。頁尾只放靈感來源。沒有 `UPSTREAM_LICENSE`（原作程式未授權）。

**和本站其他地圖工具的差別**（什麼時候用哪一個）：
- **地圖編輯器（map-editor）**：Fabric 的**向量物件**——在無限大的方格或六角格上畫地面、牆、房間（牆自動長出來）、圖形、手繪、文字，
  可以群組與布林運算，匯出 PNG／JPEG／SVG。要「畫」出房間形狀、六角格、文字標註時用它。
- **圖塊地圖產生器（tile-map，本工具）**：**點陣圖塊**——固定大小的方格，每格一張圖、分圖層疊起來（像 RPG Maker、Tiled 那樣用圖塊表拼地圖），
  支援自己的圖塊表與像素風素材，列印用 PDF 照實際尺寸分頁。手上有圖塊素材、想一格一格拼出地城，或要印出來放模型用時用它。
- **戰鬥地圖產生器（battlemap）**是一鍵程序生成；**室內平面圖產生器（floor-plan）**是房間＋家具的平面圖。

共用的東西：盤面（`@/ui/PanZoomViewport`：平移、縮放、捏合）、方格座標（`@/core/grid` 的 `squareCellAt`）、匯出區（`ExportPanel`）、
PNG 編碼的底層（`@/core/encode/png`）、PDF（站上已有的 pdf-lib；A4 與 mm／英寸換算用 `@/core/paged/units`）、圖片的讀入
（`@/core/image` 的 `loadImage`、`detectImageType`）與資產庫（`@/core/assets`，依內容產生 id、存 IndexedDB）、專案檔（`@/core/storage` 的 ZIP 專案檔）、
工具之間的交接（`@/core/handoff`）、復原（`createToolStore`）。匯入的圖塊**不縮小**（圖塊表要逐像素對齊），所以不用 map-editor 的「太大時縮小」。

**分批**：原作的程式約 165 kB（`app.js` 93 kB＋`model.js` 33 kB＋`library.js` 9 kB＋其他約 30 kB）。這一批做了第 1 節除了 **F55**（匯出／讀入單一圖塊組的檔案，
標「第二批」）以外的全部；F55 和原作舊地圖檔的讀入（D6）等主控裁定。

用語：「格」＝地圖的一格（畫面上 100% 時 64 px）；「圖塊」＝來源圖的一塊長方形；「大圖塊」＝佔好幾格的圖塊（例如 3 × 3），
地圖上每一格記著自己是大圖塊的哪一塊；「圖塊組」＝一組圖塊（內建或自訂）；「圖庫」＝這個瀏覽器裡所有自訂圖塊組（每張地圖共用）；
「可以編輯的圖層」＝顯示中、不透明度不是 0、沒有鎖定的圖層。

來源欄：TR＝照 Trials 的行為（本站改寫）；本站＝原作沒有、由本站決定；共用＝共用外框或元件提供。批次欄沒寫的都是第一批。

### 3.2 專案檔

共用的專案檔格式（`{ format: 'trpg-toolkit-project', tool: 'tile-map', version: 1, savedAt, data }`）存成 ZIP：`project.json`＋`files/<資產 id>.<副檔名>`
（地圖用到的自訂圖塊的圖；資產 id 依內容產生）。`data`：

- `map`：`name`、`width`、`height`、`background`（#rrggbb）、`layers`（由下到上）、`defs`（地圖用到的自訂圖塊的定義）。
  每個圖層：`id`、`name`、`visible`、`locked`、`opacity`、`keys`（這一層用到的放法：`[圖塊 id, 轉向 0～3, 翻轉 0/1]`，大圖塊另加 `[…, 放置編號, 第幾欄, 第幾列]`）、
  `runs`（由左到右、由上到下：`[序號（0＝空的）, 連續幾格, …]`，合計＝寬 × 高）。
- 圖塊定義：`id`、`name`、`src`（資產 id）、`rect`（來源圖上的 [x, y, 寬, 高]）、`span`（大圖塊的 [欄, 列]）、`gap`（大圖塊的小格間距）、`pixel`（像素圖）、`set`（圖塊組 id）。
- `sets`：用到的自訂圖塊組的名稱（開啟時新增圖塊組用）；`png`、`print`：匯出設定。
- 內建圖塊的 id 固定：簡易地形 `kb:<名稱>`、Kenney 塗鴉地城 `ks:<原檔名>`、Kenney 迷你地城 `kt:<0～131>`（圖上由左到右、由上到下的序號）。

### 3.3 列印用 PDF

一頁一塊地圖（點陣 PNG，透明背景除非勾「印背景色」）＋向量格線＋外框＋頁尾；文件標題＝地圖名稱、主旨「戰鬥地圖：每格 N 英寸，請用 100% 列印」。
頁的順序：先由左到右、再由上到下；最後一欄、一列的頁只放到地圖的邊。

### 3.4 圖庫備份

ZIP：`library.json`（`{ format: 'trpg-toolkit-tile-library', version: 1, library }`；`library`＝`sets`〔每組 `id`、`name`、`imports`〔`id`、`name`、`tiles`〕〕、
`removed`（刪過的圖塊組與圖塊 id）、`order`（圖塊組 id → 圖塊 id 的順序）、`names`（內建圖塊組改過的名字）、`hidden`（收起來的內建圖塊組））＋`files/<資產 id>.<副檔名>`。
檔名「tile-map-圖庫_YYYYMMDD.zip」。

### 3.5 內建圖塊

- 簡易地形（`kb:`）：石板地、碎石路、木地板、泥土、草地、沙地、淺水、深水、岩漿、冰面（地板）；石牆、磚牆、木牆、岩壁、黑暗（牆壁）；坑洞（物件）。64 px，開頁時用程式畫（同樣的程式每次畫出一樣的圖），不是像素圖。
- Kenney 塗鴉地城（`ks:`）：136 張 64 px；原作附的 136 個 PNG 由本站排成 12 欄的一張無損 WebP（`atlas.webp`，66 kB；每一格的像素和原檔相同）。附地板的版本名稱加「（附地板）」、和沒有地板的排在一起。
- Kenney 迷你地城（`kt:`）：`tilemap.png` 原樣（16 px、間隔 1 px、12 欄 × 11 列），像素圖。
- 分類：地板、牆壁、物件、角色、道具（門算牆壁、旗幟與獸首浮雕算牆壁、標記框算物件）；調色盤依分類排。

## 5. 容易做壞的地方

- 大圖塊：擦掉或蓋到任何一格都要整個拿掉；選取、搬動、轉向時整個一起動；轉向時每一塊的落點與每一塊自己的轉向要一致（先翻轉再轉向）。
- 一筆畫的中途不能寫進地圖（每一格都寫會讓復原變成一格一步，大地圖也會卡）：先寫工作副本，放開才交給地圖。
- 分段編碼的 PNG：每一段的第一列濾波要參考上一段的最後一列，不然解出來會錯。
- PDF 的座標原點在左下角；頁尾的中文不能用 PDF 內建的字型。
- 圖庫刪掉的圖塊：地圖上已經放的照樣畫得出來（地圖記著定義，圖片留在資產庫，開頁整理時「地圖、復原紀錄、圖庫都沒用到」的才刪）。
- 開專案檔時，刪過的自訂圖塊組與圖塊不能又被加回圖庫。
- 開頁時要先讀完上次的地圖才開始自動存檔，免得範例地圖蓋掉上次的地圖。
