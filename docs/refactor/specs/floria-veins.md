# 魔法脈繪製工具（翠緑のフローリア）（floria-veins）行為規格

## 0. 概要

同人 TRPG『翠緑のフローリア』（英文版 *Floria: The Verdant Way*；權利人：猫憑／六畳間幻想空間）的**魔法脈繪圖板**：
在方格上畫直線與多角形（折線）、把線圍出來的範圍塗色、標出受到傷害的格子。好幾張畫布（角色 11×11、隨從 6×6）放在同一份資料裡，
「全員」一次看全部；匯出 PNG（這張、全部排成一張、全部各一張）；可以讀寫原作的資料。**只有繪圖功能，不含規則書的內容**
（規則說明、魔法植物的名稱與形狀、數值表都不收）。

輸入：在方格上點（滑鼠、觸控）、畫布的名字與大小、原作的資料（貼上或檔案）、本站的專案檔。
輸出：畫面、PNG、剪貼簿的圖片、原作格式的文字、專案檔。

靈感來源：Nuts-ABCd／floria_canvas（<https://github.com/Nuts-ABCd/floria_canvas>，commit `5a9a582`，2026-09-12；單檔 `index.html`，
「魔法脈描画ツール」）。程式 **MIT**（Copyright (c) 2024 Nuts-ABCd；全文 `web/src/tools/floria-veins/UPSTREAM_LICENSE`）：參考原作的程式改寫；
原作的範例資料（「全員」分頁裡的 PC2～PC4、BOSS、Mob1、Mob2）沿用成本站的範例（F07）。原作寫明它是『翠緑のフローリア』的二次創作；
作品的二次創作規定本站還沒讀到（這個環境連不到日本的網站），照 TODO.md「其他系統的內容授權」的做法：只做繪圖、不內建規則書的文字，
頁面裡（設定欄最下面「關於這個工具」與使用說明）註明權利屬於猫憑／六畳間幻想空間、本工具是愛好者製作的非官方工具（F08）。頁尾只放靈感來源。

原作的「同期」（`js/net.js`、`js/sync.js`，不在 repo 裡，按鈕一直是停用的）與 GM 選單（敵情報公開、部屋削除）是線上同步房間的功能，不移植（F92）。
所以原作在本機只有一張可以畫的畫布（「自分」），「全員」「個別」看的是內建的範例；本站改成**每一張都可以畫**（D1）。

## 2. 輸入

### 2.1 點選

- 直線、多角形：吸附到最近的格點（四捨五入），超出畫布時夾在邊上；格子外 0.5 格以外按下去是平移。
- 塗色：吸附到最近的交點（3.2）；刪除塗色時另外加上現有塗色的頂點。
- 傷害格：指到的格子（無條件捨去）；畫布外按下去是平移。
- 滑鼠：按下到放開算點一下，位置是放開的地方；右鍵＝退一點。觸控見 F47。

### 2.2 原作的資料格式

原作存在瀏覽器（`localStorage` 的 `floria.data0`）與「データ保存」下載的 `CanvasData` 都是同一種字串：

```
GS:1200|GN:<格數>|NM:<名字，URL 編碼>|CD:<傷害格>|CF:<塗色>|CL:<線>
```

- 段落用 `|` 分開；段落裡的物件用 `~` 分開；物件裡的點用 `-` 分開，點是 `P:<x>_<y>`（單位：一格 1200）。
- 線 `L:P:x_y-P:x_y-<尾巴>`、塗色與傷害格 `F:P:x_y-…-<尾巴>`；尾巴是顏色（`#RRGGBB`）、`h`（看不見的線）、空白（預設色）或沒有（舊的寫法，範例資料就是）。
- `CL` 裡有看不見的線：四邊，以及每個傷害格的四邊（原作靠它們讓塗色吸附到傷害格的角）；預設的對角線沒有顏色。
- 傷害格是一格的四個角（左上、右上、右下、左下）。塗色封閉時最後一點和起點相同。
- 同步用的資料另外有 `CT:`（草稿），讀的時候略過。原作讀檔時檢查：字串經 `encodeURIComponent` 之後只能有英數與 `:|_-~%#`（所以名字裡不能有 `. ! * ' ( )`）。

讀進來時：去掉所有空白與換行；格數 2～24（不在範圍內、沒有 `GN` 時整段不收）；名字 URL 解碼（解不開時照原樣），取前 40 字；
看不見的線不收（本站自己從四邊、對角線與傷害格算）；沒有顏色的對角線是預設的那一條、不收；沒有顏色的線補 #0000ff、塗色補 #00c0ff（原作的預設色）；
線的端點要在格點上、在畫布裡；同一條線（不分方向）只留最後一條；塗色去掉重複的點與回到起點的那一點，少於 3 點的不收；傷害格要是對齊格線的一格、在畫布裡，重複的只留一個。
看不懂的物件略過並計數。

寫成原作的格式：`GS:1200|GN|NM|CD|CF|CL` 的順序；`CL` 最前面照原作放四邊（`h`）與對角線（尾巴空白），接著畫上去的線，最後是每個傷害格的四邊（`h`）；
傷害格的尾巴空白；顏色大寫。名字用 `encodeURIComponent`，另外把 `. ! * ' ( )` 也編成 `%XX`（原作讀得回去）。

### 2.3 專案檔

共用的格式 `{ format: 'trpg-toolkit-project', tool: 'floria-veins', version: 1, savedAt, data }`；`data`＝`{ canvases, stamps, draft: null }`（3.6）。
開啟時逐項整理（3.6）；一張畫布都沒有、不是這個工具的專案檔時讀不進來（共用的錯誤訊息）。

### 3.2 交點（塗色的吸附）

畫布上所有的線段兩兩的交點：四邊、預設的對角線、畫上去的線、每個傷害格的四邊（相鄰格子共用的邊只算一次）。
平行的、在同一直線上重疊的兩條線沒有交點；只碰到端點也算。交點座標四捨五入到整數單位；不重複，依 y、x 排序；
吸附到最近的一點（距離相同時取排在前面的）。空白的畫布只有四個角。原作的 `getCrossPos`（浮點數）與本站（整數的外積）的結果在 197,972 組
隨機的格點線段上完全相同（實作者用 Playwright 在原作頁面裡比對）。

### 3.3 草稿

- 點一下的規則見 F30～F33；完成一筆之後再點開始下一筆（塗色除外）。
- **可以決定的條件**：直線＝至少一條完成、沒有畫到一半的；多角形＝至少一筆完成且沒有畫到一半的，或正在畫的那一筆 2 點以上（決定時當成到此為止的折線）；
  塗色＝範圍完成，或正在畫的 3 點以上（決定時封閉）；傷害格＝至少一格（D5）。
- 換畫法、換畫布時草稿丟掉（一步復原；復原時回到那張畫布與畫法）。草稿跟著自動儲存，重新整理後還在。

### 3.4 移動、反轉、旋轉（以格為單位，和原作相同）

- 移動：所有的點（完成的與正在畫的）一起移 dx、dy 格；有任何一點超出 0～格數就不動。傷害格：格子要在 0～格數−1。
- 左右反轉：x → 格數 − x，再整個平移讓最左邊的 x 和反轉前相同。
- 旋轉：(x, y) → (格數 − y, x)；位移 dx＝trunc((反轉前 x 的最大＋最小)/2 − (轉後 x 的最大＋最小)/2)，超出時夾到 0 或格數（y 同樣）。
  例：11 格的 (1,1)–(4,1) → (3,0)–(3,3)。
- 實作者把 400 組隨機的格點（11 格與 6 格）分別旋轉、反轉、移動，和原作的 `rotate`、`mirror`、`shift`（在原作的頁面裡執行）比對，1,200 組完全相同。
- 圖形放上去：外框比畫布大時不能放；超出的一邊整格移進來。

### 3.5 決定（畫布的資料）

- 畫線：每一段一條（長度 0 的略過）；同一條線（不分方向）已經有了時換成新的顏色、移到最上面（D4）。
- 塗色：頂點相同（不論順序）的塗色已經有了時換成新的顏色、移到最上面；不到 3 個不同的頂點不加（D4）。
- 傷害格：已經標過的不重複。
- 刪除：見 F42～F45；預設的對角線刪不掉。

### 3.6 存檔與專案檔的資料

`data`：

- `canvases`：每張 `id`、`name`（0～40 字）、`size`（2～24）、`lines`（`{ a: [x, y], b: [x, y], color: '#rrggbb' }`，端點在格點上）、
  `fills`（`{ pts: [[x, y], …], color }`，3 點以上、不重複起點）、`damage`（`[[欄, 列], …]`，0 起算、不重複）。座標的單位和原作相同（一格 1200）。
- `stamps`：我的圖形，`{ id, name, figures: [{ pts, closed }] }`（點在格點上）。
- `draft`：草稿（只在自動儲存裡）`{ canvasId, kind: 'line'|'shape'|'fill'|'damage', erase, figures, current, cells }`。

整理：看不懂的畫布（格數不對）、線（不在格點上、超出畫布、長度 0）、塗色（點不對、少於 3 點）、格子（不是整數、超出、重複）、圖形略過；
顏色不是 `#rrggbb` 時線補 #0000ff、塗色補 #00c0ff；重複的畫布 id 換一個；同一條線只留最後一條；畫布最多 30 張、圖形最多 60 個；
一張畫布都沒有時整份不收（自動儲存回到預設、專案檔讀不進來）。草稿的畫布不存在時丟掉。

### 3.7 匯出

- 全部排成一張：照畫布的順序由左到右排，一列最多 4 張最大的畫布那麼寬（隨從的小畫布可以多放）、放不下換列；同一列靠上對齊；
  畫布之間空 0.5 格、四周 0.25 格（一格＝匯出的格子大小）；背景白色或透明。例：PC（11×11）＋隨從（6×6）的 1 倍＝1258 × 811 px。
- 一覽（F15）用同一種排法，欄數依畫面寬度。

## 5. 容易做壞的地方

- 草稿在復原紀錄裡：換畫法、換畫布時丟掉的草稿要能復原回來，而且畫面要跟著切回那張畫布與畫法（不然復原的東西看不到）。
- 傷害格的拖曳是一個手勢：拖曳中加的每一格合成一步；捏合（第二指）取消時草稿要回到拖曳之前、不留下一步沒有變化的復原。
- 交點的快取以畫布物件為鍵（Immer 改過的畫布是新的物件）；別在 draft 物件上算。
- 刪掉線之後，原本塗色的頂點可能不再是交點：刪除塗色時另外吸附塗色的頂點（D6）。
- 原作的名字不能有 `. ! * ' ( )`：寫回原作的格式時要另外編碼。
- 從一覽打開畫布時，窄畫面要捲回畫布（一覽很長）。

### 刻意的做法與待裁定（D 項，需主控確認）

- **D1 每一張畫布都可以畫**：原作在本機只有「自分」一張可以畫，「全員」「個別」看的是內建範例（同步時是其他玩家的資料）；本站沒有同步，

  「個別」併進畫布的切換。GM 可以把每位玩家的資料讀進來（F53）排成一張給大家看（F50）。
