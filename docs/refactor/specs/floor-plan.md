# 室內平面圖產生器（floor-plan）行為規格

## 0. 概要

探索場景用的室內平面圖編輯器。以 1 格＝0.5 m 的方格擺房間（整格）、門窗與家具（0.25 格），**牆由房間自動產生**：相鄰房間之間是內牆、
朝外的邊是外牆、陽台是欄杆、洞窟是岩壁、庭院等戶外房間彼此之間沒有牆；另外可以手畫隔間、圍籬、鐵欄杆、崩塌的牆等。
房間可以設成「只有 GM 看得到」（PL 檢視與 PL 用的圖裡只剩牆框、裡面蓋灰），家具與文字可以設成「隱藏線索」（和 GM／PL 檢視分開的開關），
房間可以鎖定、旋轉（連同裡面的東西）。多樓層（下一層淡淡地顯示）、範本（住宅、洋館、飯店、醫院、廢墟、命案現場；可以只載入格局、可以放入隱藏線索），
匯出 PNG（這一層／所有樓層排成一張／每層各一張；PL 用／GM 用；每格 24～96 px；太大時自動縮小）。

輸入：滑鼠、觸控、鍵盤；本工具的專案檔；原作存的地圖檔（`.trpgmap.json`）。輸出：PNG、專案檔（JSON）、瀏覽器裡的自動保存。

靈感來源：くま。／TRPG室内図メーカー（<https://kumachansteps.github.io/trpg-web-tools/>）。原作沒有授權條款，網站的利用規約禁止轉載與再散布站內的圖片素材，
所以只參考功能與做法：程式、介面文字、說明、範本、範例資料、家具圖形、圖示都是本站自己做的（不放 UPSTREAM_LICENSE）。原作的語言切換（日、英、韓）、
分享到 X、作者連結、分析碼、站內共用的主題快捷鍵不移植（D1）。

原作的程式：`/home/user/upstream/kumachansteps__trpg-web-tools/tools/indoor-map-maker/`（v1.04，2026-10-08）。

## 2. 輸入

### 2.1 座標與單位

- 世界座標的單位是「格」（1 格＝0.5 m），x 往右、y 往下。房間的 x、y、寬、深是整數；家具、門窗、文字是 0.25 格（數字欄可以輸入更細，四捨五入到小數 2 位）；手畫牆的端點 0.5 格。
- 門窗：方向 `o`（h＝在水平的牆線上、v＝垂直）、起點 x、y（在牆線上）、寬度 len；`side` 1／−1＝門往線的哪一側開；`hinge` 0／1＝鉸鍊在起點／終點那一端。
- 家具：外框 x、y、w、h（已經是轉過方向之後的外框）與方向 rot（0／90／180／270），`flip` 左右翻轉。

### 2.2 讀得進來的檔案

| 種類 | 判斷 | 處理 |
|---|---|---|
| 本工具的專案檔 | 共用的專案檔格式（3.5），`tool` 是 `floor-plan` | 讀 `data` 並整理（下面的規則） |
| 原作存的地圖檔（`.trpgmap.json`） | JSON 物件，`app` 是 `indoor-map-maker`，或有 `floors` 陣列且沒有 `format` | 欄位和本工具相同，整理後讀進來；面積顯示「帖」換成「坪」；家具種類代號和原作相同 |
| 其他 | — | F08 的錯誤通知 |

整理的規則（自動保存、專案檔、原作的檔共用）：只留認得的欄位；數值不是數字的那一筆丟掉；房間的寬深小於 1 的丟掉、座標四捨五入成整數；不認得的房間種類換成客廳類、牆的種類換成內牆；
不認得的門窗種類、方向、寬度 ≤ 0 的門窗丟掉；不認得的家具種類丟掉（計數，F07）；文字字級夾在 0.3～4；顏色換成小寫 `#rrggbb`（有透明度時 `#rrggbbaa`）；名稱長度上限（地圖 120、樓層 60、房間 200、文字 2000 字）；
同一類 id 重複或沒有時給新的；沒有樓層時給一層空白的 1F；目前的樓層夾在範圍內。

### 2.3 拖放

整個視窗都可以放檔案（共用的 WindowDrop，`.json`、`.zip`、`.trpgmap`）；素材面板的卡片拖到畫布上（F43、F47）。

## 3. 輸出

### 3.1 PNG 的版面

1. 每一層先依檢視（PL／GM）與隱藏線索算出「看得到的東西」（F160、F165），取外接範圍：房間、家具、手畫牆的端點、文字（約 4 × 1 格）、門窗（往牆的兩側延伸「開門的範圍」：單開門類＝寬度、雙開門＝寬度的一半、自動門＝寬度 × 0.35、折門＝寬度 × 0.42、牆洞＝1 格、其他 0.5 格）。這一層沒有東西時以 (0, 0)～(10, 8) 為準。
2. 好幾層排成一張時，每一層都用**所有樓層的共同範圍**（疊起來位置一樣），每層上方多留 2 格寫樓層名稱（字級 1.1 格、粗體、靠左），樓層之間空 1 格。只有一層時沒有名稱列。
3. 每一層的框＝範圍四周各加 2 格留白。橫排一列；整列的寬高比大於 5 時改成多列，選寬高比最接近 4:3 的欄數（每列靠左，列高＝最高的框）。
4. GM 用：最上方加一條字帶，字級＝clamp(總寬 × 0.025, 1.1, 4) 格，帶高＝字級 × 1.6，左側寫「GM 用」（GM 色、55% 不透明）。PL 用沒有字帶。
5. 尺寸：每格 px＝選的每格大小，但單邊超過 16,000 px 或總面積超過 4,000 萬 px（iPhone／iPad 約 1,677 萬 px）時等比縮小；寬高＝四捨五入（總寬格數 × 每格 px）。例：套房範本 PL 用、每格 48 px ＝ 1152 × 984。
6. 底色＝樣式的背景色（透明背景時不畫）；地圖照編輯畫面的畫法（F72～F92），但不畫格線（除非 F205）、分區線、選取、控制點、GM 筆記與鎖定的標記、線索的標記；PL 用的 GM 房間蓋灰。

### 3.2 檔名

`地圖名稱[_樓層名稱]_PL|GM[_無線索].png`：

- 地圖名稱：前後空白去掉、空白時「未命名地圖」；`\ / : * ? " < > |` 與空白（連續的算一個）換成 `_`；最多 60 字。
- 樓層名稱：好幾層而且是「只有這一層」或「每層各一張」時加上（同樣替換字元）；只有一層或「所有樓層排成一張」時不加。
- 隱藏線索選「藏起來」而且地圖裡有線索時加「_無線索」。

例：`山丘上的洋館_1F_PL.png`、`命案現場（套房）_GM_無線索.png`。

### 3.3 顯示樣式（本站自己配的顏色，D8）

彩色（白底、依種類上色）、黑白圖面（白底灰階）、藍圖（深藍底、淺藍線）、泛黃的舊圖面（米黃底、棕色線、襯線字）、恐怖調查（深色底、暗紅點綴）。每種樣式各有：背景、格線、牆、房間的種類色、家具的線與填色、名字與面積的字色與描邊、GM 色、線索色、蓋灰的顏色。

### 3.4 自動保存

- 地圖：`localStorage` 的 `trpg-toolkit:floor-plan`（共用的 createToolStore 格式：`{ state: { data: 專案 }, version: 1 }`），延後約 0.4 秒寫入、離開頁面或切到背景時立刻寫入。
- 偏好：`trpg-toolkit:floor-plan:preview`（格線、下一層、隱藏線索、素材分頁、匯出設定）。
- 原作的瀏覽器存檔（`indoorMapMaker.v1` 等）：**不搬移（不同網域）**。要接著用原作的地圖，請在原作「存檔」後用 F06／F07 匯入。

### 3.5 專案檔（`<地圖名稱>.floor-plan.json`）

共用格式 `{ "format": "trpg-toolkit-project", "tool": "floor-plan", "version": 1, "data": 專案 }`。專案：

| 欄位 | 內容 |
|---|---|
| `name` | 地圖名稱 |
| `theme` | `clean`／`mono`／`blueprint`／`paper`／`horror` |
| `showSize` | `none`／`ping`／`m2`／`m` |
| `showNames` | 顯示房間名字（boolean） |
| `active` | 目前的樓層（索引） |
| `floors[]` | `{ id, name, rooms[], walls[], openings[], items[], texts[] }` |
| `rooms[]` | `{ id, x, y, w, h, name, cat, plName?, note?, color?, gm?, hideLabel?, noWall?, locked?, lx?, ly? }`（lx、ly＝名字的位移） |
| `walls[]` | `{ id, x1, y1, x2, y2, kind, gm? }` |
| `openings[]` | `{ id, kind, o, x, y, len, side, hinge, gm? }` |
| `items[]` | `{ id, t, x, y, w, h, rot, flip?, label?, color?, gm?, clue? }` |
| `texts[]` | `{ id, x, y, text, size?, bold?, color?, gm?, clue? }`（bold 只在 false 時寫） |

欄位和原作的地圖檔相同（除了 `showSize` 的 `ping`），所以原作的檔案可以直接整理後讀進來（2.2）；本工具的專案檔原作讀不了（外面多包一層）。

## 4. 互動與手感

- 倍率：100%＝每格 24 px；範圍 3～140 px／格；顯示全部時最多 64 px／格。滑鼠滾輪每格（deltaY 100）約 ×0.84；捏合（Ctrl＋滾輪）較敏感（×e^(−0.012·deltaY)）；觸控板兩指捲動（deltaX ≠ 0 或 |deltaY| < 40 的像素捲動）是平移。
- 點選的容許距離：約 5 px（換算成格）；門窗沿線兩端各放寬 5 px、垂直方向 max(0.32 格, 7 px)；手畫牆 max(0.25 格, 5 px)；文字依量到的字寬；畫面上小於 12 px 的家具四周放寬 5 px。控制點是 7 px 的方塊（圓形的直徑 11 px），在 ±7 px 內都抓得到，螢幕上大小固定。
- 拖曳：選取工具超過 4 px 才算移動；房間工具超過 4 px 才算畫（沒到＝點一下）。
- 線寬：最細 1／22 格、至少 0.8 螢幕 px。文字以放大 64 倍量字與畫字，再縮回來（小於 1 px 的字量出來的寬度才準，D12）。
- 方向鍵連按 0.7 秒內算一步；打字、拖曳顏色到離開欄位或放開算一步；切換樓層、檢視、隱藏線索、格線不算復原步驟。
- 通知：一般約 2.8 秒、警告約 3.6 秒；有「復原」按鈕的通知按了就復原並關閉。
- 迷你工具列、提示列、倍率、隱藏線索的開關都在畫布裡；手機（390 寬）時版面依序是畫布、屬性、素材（素材面板最高約 75% 視窗高、裡面捲動），不能橫向捲動；工具列與迷你工具列可以觸控操作。

## 5. 容易做壞的地方

- **牆的主人是「最後一個」蓋在格子上的房間**，不是最小的：巢狀的房間（客房裡的浴室）要後放；改「移到最下層」會改變牆。
- **門窗的厚度看所在的牆**：同一條線上一半外牆、一半內牆時，看門窗中點那一格；在分區線上的門窗看手畫牆，都沒有就當內牆。
- **PL 檢視的暗門不切牆**、也不畫；GM 房間邊上的門窗要留著（只藏中點在房間「裡面」的）。
- **移動房間時「裡面」的判斷**用中心點（家具中心、門窗中點、文字位置、手畫牆中點、巢狀房間完全包住），房間邊上的門窗也算（中點在邊上時包含邊界）。
- **旋轉房間**：以所有選取房間的外接範圍為中心順時針 90°，門窗的 o 與 side 跟著換，家具的 rot＋90、外框寬深對調；轉完左上角要回到整格（不然牆會歪）。
- **匯出好幾層用共同範圍**；寬高比 > 5 才折行；GM 字帶的高度跟總寬有關。
- **小於 1 px 的字**：canvas 在某些環境（Linux 的 Chrome 等）會把字寬量大、字距拉開，房間名字被誤判放不下而變成直書或縮到看不見；要放大量字（D12）。
- **自動保存要延後**：大地圖拖曳時不能每一格都寫 localStorage。
- **鍵盤**：在輸入欄裡、對話框開著時不攔截；空白鍵在按鈕上時照常按下按鈕；方向鍵沒有選取時讓頁面捲動。
