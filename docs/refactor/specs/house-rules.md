# CoC 房規表產生器（house-rules）行為規格

## 0. 概要

把克蘇魯的呼喚（CoC）6 版／7 版團的房規整理成一張表：從常見的規則裡勾選要放進表的條目、選擇做法（○ 採用、× 不採用、
各規則自己的選項、※ 有修改）、調整數值、寫注記，也能加入自己團的規則；再把表匯出成 **PNG 圖片**、**純文字**（貼到 Discord）
或 **Markdown**（GitHub、Notion）。表的內容自動存在瀏覽器，另有專案檔。全部在瀏覽器內完成，不連任何伺服器。

輸入：版本、預設集、表的資訊（標題、KP、規則系統、適用劇本、更新日期、其他備註）、每條規則的設定。
輸出：PNG（橫式寬 1920 px／直式寬 1200 px）、純文字、Markdown（複製或下載）；專案檔（JSON）。

靈感來源：くま。／CoCハウスルール表メーカー（<https://kumachansteps.github.io/trpg-web-tools/>，原作 v1.00／2026.10.01，以下稱【原作】）。
**原作沒有授權條款**，網站的利用規約禁止轉載、再散布站內的素材：本站只參考功能與做法，程式、介面文字、說明、規則的名稱與說明、
預設集的文字、PNG 的版面與配色、圖示全部自己做；不放 `UPSTREAM_LICENSE`。規則與選項的 **id** 沿用原作（存檔的鍵，不是文字），
所以同一份狀態可以餵給兩邊、比對輸出（3.8）。原作在本機的路徑：`/home/user/upstream/kumachansteps__trpg-web-tools/tools/house-rule-table/`。

用語：「區塊」＝6 版、7 版、各版通用三組規則；「分類」＝區塊裡的小標（檢定與技能、理智與瘋狂…）；
「內建規則」＝規則清單裡的條目（3.1）；「自己加的規則」＝使用者用「新增規則」加的條目；「放進表」＝這一列會出現在輸出裡
（原作與新版都用眼睛圖示切換）；「預設集」＝一次填好所有內建規則的值（照規則書／線上團常見／全部清空）。

## 2. 輸入

- 文字欄：標題、KP、規則系統 120 字，適用劇本 200 字，其他備註 4000 字，規則名稱 200 字，注記 2000 字，自由填寫 400 字（超過的打不進去；讀檔時截斷）。

- 沒有檔案以外的輸入（不讀圖片、不連網路；字型從 Google Fonts 載入，載不到時用系統字型）。

### 3.2 表的模型（三種輸出共用）

- **標題**：標題欄去頭尾空白；空白時「房規表」。
- **表頭資訊**（依序，空白的不寫）：`KP`、`規則系統`（**一律寫**；空白時寫版本的名稱：CoC 6 版／CoC 7 版／CoC 6 版／7 版）、
  `適用劇本`、`更新日期`（YYYY.MM.DD）。都去頭尾空白。
- **區塊**：依版本（F01）；每個區塊裡依分類順序，每個分類先列內建規則（清單順序）、再列自己加的規則（加入的順序），**只列放進表的列**；
  沒有任何列的分類不列，沒有任何分類的區塊不列。各版通用的區塊用另一個顏色（PNG）。
- **一列**＝名稱、值、值的種類、注記：
  - 名稱：改過的名稱或原本的名稱（去頭尾空白）；自己加的規則空白時「新規則」。
  - 值：選項的文字（帶數字的選項把 n 換成目前的數字）；○ × ※ 照符號；未設定「—」；自己加的規則的自由填寫是內容（去頭尾空白；空白時「—」）。
  - 種類：○、×、※、一般選項、自由填寫、未設定（決定 PNG 的顏色）。
  - 注記：去頭尾空白（中間的換行保留）。
- **其他備註**：去頭尾空白；空白時不寫。
- 沒有任何區塊時＝「表上沒有規則」（F47），不輸出。

- 最後：連續三個以上的換行縮成兩個、去頭尾空白、補一個換行（所以備註裡連續的空行最多留一行）。

### 3.5 PNG

- **尺寸**：邏輯寬度 橫式 960、直式 600；下載的 PNG 是 2 倍（1920／1200 px），高度依內容（邏輯高度無條件進位 × 2）。
  表很長、2 倍高度會超過 32,000 px 時倍率降低到高度剛好 32,000（寬度跟著變小）。不透明（RGBA，alpha 255）。
- **字型**：Noto Sans TC（Google Fonts，只下載表裡用到的字；400 與 700 兩種字重）；載不到時用系統字型（`FALLBACK_STACK`）。
- **排版**（邏輯 px；外距 橫式 40、直式 24）：
  - 最上面一條 6 px 的主色帶。
  - 標題（橫式 28、直式 24 px 粗體，行高 1.35，超過寬度自動斷行）→ 表頭資訊（13 px，`標籤：內容`；橫式以「　／　」連成一段、直式一項一行）→ 分隔線。
  - 每個區塊：淡色底的圓角標題帶（高 34，左邊 4 px 色條；6 版、7 版主色，各版通用青綠色）→（橫式）欄名「規則／設定／注記」（11 px，淡色；沒有注記欄時沒有「注記」）→
    每個分類：分類名稱（13 px 粗體，區塊的顏色）＋分隔線 → 每一列（奇數列淡色底）→ 分隔線。
  - **橫式的一列**：三欄（有注記欄時 34%／20%／46%，沒有時 56%／44%）；名稱 14 px 粗體、值置中（○ × ※ 18 px，其他 14 px，粗體）、
    注記 13 px；各欄垂直置中，列高＝最高的那一欄＋18。值是 ※ 而且有注記時，注記欄是淡橘底＋左邊 3 px 橘線、字是一般顏色（其他注記是淡色字）。
  - **直式的一列**：名稱靠左、值靠右（值最寬佔 46%），注記在下一行（12.5 px，縮排；※ 的注記左邊有橘線）。
  - 其他備註：左邊 4 px 色條＋「其他備註」（15 px 粗體）→ 備註原文（13.5 px，行高 21）。
  - 圖例：分隔線下方，12 px 淡色。最後留外距。
  - 斷行：中文逐字，英數以詞為單位（比一行還長時才從中間斷），行首不放「，。、」等標點，行尾不放開括號；原本的換行保留。
- **配色**（本站自訂，不是原作的配色）：

  | 用途 | 深色 | 淺色 |

### 3.6 檔名

`<標題>_<更新日期 YYYYMMDD>.<副檔名>`（png、txt、md、json）。標題空白時「房規表」；標題經過共用的 `safeFileName` 底線模式
（去頭尾空白、空白換成 `_`、刪掉 `\ / : * ? " < > |`、最長 60 字）；更新日期空白時用今天。例：標題「週五 團/房規?」→ `週五_團房規_20261009.png`。

### 3.7 存檔與專案檔

- **自動存檔**：localStorage `trpg-toolkit:house-rules` ＝ `{ state: { data }, version: 1 }`；`data`：
  ```
  {
    edition: '6' | '7' | 'both',
    info: { title, kp, system, scenario, date: 'YYYY-MM-DD' 或 '', remarks },
    secs: {
      '6' | '7' | 'common': {
        rows: { <規則 id>: { val: <選項 id> | null, n?: 整數, note, vis: 布林, name?: 改過的名稱 } },
        custom: [ { id, cat: <分類 id>, name, val: 'o' | 'x' | 'm' | 'text' | null, text, note, vis } ]
      }
    }
  }
  ```
  （與原作的 `state` 結構相同，只少了原作放在裡面的收合狀態。）
- **畫面狀態**：`trpg-toolkit:house-rules:preview` ＝ `{ collapsed: { '<區塊>:<分類>': true }, format: 'png' | 'txt' | 'md', theme, layout: 'wide' | 'narrow' | null, notes, legend }`（不算復原、不進專案檔）。
- **專案檔**：`{ format: 'trpg-toolkit-project', tool: 'house-rules', version: 1, savedAt, data }`（`data` 同上；共用 ProjectMenu）。
- **讀檔整理**（自動存檔與專案檔共用；不是物件時讀不進來）：先做一份「照規則書」的表，再把讀到的值蓋上去——版本只認 6／7／both；
  表的資訊只認字串（截斷到上限），日期不是 YYYY-MM-DD 時用今天；每條內建規則：值不是這條規則的選項時用規則書的值（null＝未設定照讀），
  數字夾到目前選項的範圍、四捨五入，`vis` 不是布林時用預設集的值，名稱去頭尾空白後和原本一樣就不算改名；不認得的規則丟掉、
  缺的規則補上照規則書的值；自己加的規則：分類不屬於這一區的丟掉、每區最多 200 條、值不認得時未設定、`vis` 只有 false 才是不放進表、
  id 重複時換新的 id。

## 4. 互動與手感

- 所有修改立刻自動存檔；輸出的文字即時更新，PNG 預覽約 0.2 秒後重畫，字型載入後再畫一次。
- 復原：點選項、眼睛、預設集、新增／刪除規則、改版本各一步；文字欄從進入到離開一步（共用 `historyGesture`）；收合、輸出設定不算。
- 數字欄：↑／↓ 加減 1（Shift ×10）、PageUp／PageDown、Home／End；Enter 或離開時夾到範圍；Esc 還原。
- 選項按鈕是一般的切換按鈕（Tab 移動、空白鍵／Enter 按），`aria-pressed` 表示選中；一列是一個 `role=group`（名稱＝規則名稱）。
- 目錄：點了平滑捲動（減少動態效果時直接跳），收合的分類先展開；目前位置跟著捲動更新。
- 通知：套用預設集、刪除規則（約 4 秒，取代前一則）；手機滑動切換（約 1.6 秒）；下載、存檔、複製。
- 版面：≥ 1280 px 三欄（目錄 170～200 px｜編輯｜輸出 340～400 px，目錄與輸出固定在畫面上）；1024～1279 px 兩欄（編輯｜輸出 320～380 px），
  目錄是編輯區上方黏在頁首下方的橫向列；更窄時一欄由上而下（目錄列黏在畫面頂端、輸出在最後）。390 px 寬不能橫向捲動。
- 規則的一列依編輯區的寬度（container query）：≥ 48rem 一列五欄（眼睛｜名稱與說明｜選項｜注記｜刪除）；32～48rem 注記排到第二行；
  更窄時名稱與眼睛、刪除一行，選項一行，注記一行（不放進表的列只留第一行）。
- 快捷鍵：Ctrl（⌘）＋Z 復原、Ctrl＋Shift＋Z／Ctrl＋Y 重做、Ctrl＋S 存成專案檔（文字欄裡也可以）、? 快捷鍵一覽、Esc 關閉選單與對話框。

## 5. 容易做壞的地方

- **點已選的選項＝未設定**，不是「不放進表」；未設定的列放進表時寫「—」。點沒選的選項**一定放進表**。
- **預設集「全部清空」不改放不放進表**，而且會清注記；其他兩個預設集保留注記、決定放不放進表（`core` 或常見值不同）。三個預設集都不碰自己加的規則與改過的名稱。
- **帶數字的選項共用一個數字**：從「合計 n 次」換到「整組不限、單項 n 次」時沿用原本的數字（不是換成那個選項的預設值）；還沒有數字時才用預設。
  沒選的數字選項按鈕顯示預設值。讀檔時數字夾到「目前選的」選項的範圍。
- **規則系統空白時表上仍寫版本的名稱**，其他空白的表頭資訊不寫。
- **純文字最後的換行整理**：連續三個以上的換行縮成兩個（備註裡的多個空行會被縮）；結尾一定有一個換行。
- **Markdown 的注記欄是整張表一起決定**：有任何注記時每個分類的表都有注記欄。
- **PNG 的注記欄**同樣是整張表一起決定；不包含注記時連欄名都沒有、欄寬改成 56％／44％。
- **7 版的「其他房規」分類沒有內建規則**：編輯區照樣列出（0／0 條）讓人加自己的規則；沒有自己加的規則時輸出不列這個分類。
- **改名的判斷**：清空、或去頭尾空白後與原本相同時算沒改；打字中欄位不要跳回原本的名稱（離開欄位才整理）。
- **※ 的符號**：有些系統字型把 ※ 畫成裝飾性的圖形；介面加了 `font-variant-emoji: text`，PNG 用 Noto Sans TC。
