# 先攻與戰鬥追蹤（combat-tracker）行為規格

## 0. 概要

跑團戰鬥時記先攻順序、輪數、HP 與狀態的 GM 工具。**系統通用**：CoC、5e、PF2e、DX3 等有先攻或行動順序的系統都能用；
5e 專用的死亡豁免與 SRD 5.2.1 的狀態做成可以關掉的選項。另開「玩家視圖」視窗給玩家看（分享畫面、投影），
敵人的 HP 可以不顯示或只顯示概略。5e 速查計算（5e-calc）的遭遇與快速怪物可以一鍵送過來（`@/core/combat`）。

輸入：參戰者（名字、陣營、先攻或先攻加值、HP 上限、AC、數量）、HP 的增減、狀態；原作的 JSON、本站的專案檔、別的工具送來的參戰者。
輸出：畫面上的先攻表、玩家視圖、剪貼簿的文字（Discord 的 Markdown）、原作格式的 JSON、專案檔。

靈感來源：Sly Flourish／Lazy GM Tools（[mshea/lazy_gm_tools](https://github.com/mshea/lazy_gm_tools) 的
`5e_artisanal_database/tools/combat_tracker/`，commit `89290732`，2026-10-08；單檔 HTML，檔頭寫明程式以 **CC0 1.0** 釋出，
`web/src/tools/combat-tracker/UPSTREAM_LICENSE`）。本站加的功能（臨時 HP、狀態與持續回合、拖曳與鎖定、0 HP 的處理、玩家視圖、
復原、自動儲存、專案檔）參考 TODO.md 第二節的評估與 [M-ybeme/Initiative-Tracker](https://github.com/M-ybeme/Initiative-Tracker)
（MIT，只參考功能，沒有用它的程式）。

規則內容（狀態的名稱與說明、死亡豁免、臨時 HP、專注、先攻）取材自 **SRD 5.2.1**（Wizards of the Coast，CC BY 4.0），
本站翻譯成繁體中文、有修改；放在共用模組 `@/core/srd5/srd52/`（出處與署名見同資料夾的 `LICENSE.txt`，建置時列進 THIRD_PARTY_NOTICES），
頁面上「關於規則內容」的對話框照原文放署名（第 1 節 F70）。頁尾只放靈感來源。

## 2. 輸入

- 數字欄：全形數字照樣接受（共用 NumberInput 的規則）。先攻 −99～99、先攻加值 −20～20、AC 0～99、HP 上限 1～99,999、臨時 HP 0～99,999、狀態的持續 1～999 輪。
- 清單最多 200 位（滿了「加入」不能按）；名字 60 字、備註 500 字、自訂狀態每個 20 字、每位最多 30 個狀態。
- 原作的 JSON（F67）：看不懂時的訊息「這不是 JSON 檔（格式錯誤）」「這個 JSON 裡沒有參戰者的清單（combatants）」「這個 JSON 裡有看不懂的參戰者（要有 id、name、initiative）」。
- 別的工具送來的資料（F16，`@/core/combat`）：`{ "format": "trpg-toolkit:combatants", "version": 1, "seeds": [{ name, count?, side?, init?, initMod?, rollInit?, hp?, ac?, note? }] }`，數值夾在上面的範圍、看不懂的那一筆略過、最多 200 筆。

## 3. 輸出與數值

### 3.1 排序與名字
- 依先攻由高到低的穩定排序（同分保持原本的順序），沒有先攻值的排最後。
- 同名多隻：見 F13；`Goblin` 已存在時再加一隻：原本的改成 `Goblin A`、新的是 `Goblin B`；`Goblin A`、`Goblin C` 存在時再加是 `Goblin D`。

### 3.2 擲骰
- 1d20：1＋⌊亂數 × 20⌋；1d10 同理；2d6 兩顆相加。結果加上先攻加值後夾在 −99～99。

### 3.3 回合
- 見 F30～F34。目前輪到的人記的是那位參戰者（不是位置），改先攻、拖曳、刪除別人都不會換人。

### 3.4 HP 與 5e 的規則（SRD 5.2.1）
- 傷害 n：臨時 HP 先扣 min(臨時, n)，剩下 r 扣 HP（最低 0）。玩家角色＋死亡豁免開著時：原本就 0 HP → r ≥ 上限死亡，否則失敗 +1（重擊 +2），到 3 死亡；
  從 h > 0 降到 0 → r − h ≥ 上限時死亡。
- 治療 n：HP ＝ min(上限, HP＋n)；從 0 回到 1 以上時死亡豁免歸零；死亡的不回復。
- 死亡豁免：d20 ≥ 10 成功、1 兩次失敗、20 回復 1 HP（並歸零）。3 次成功＝穩定（次數歸零）、3 次失敗＝死亡。
- 專注 DC ＝ min(30, max(10, ⌊傷害 ÷ 2⌋))。

### 3.5 玩家視圖的內容（`@/core/mirror` 的 topic `combat-tracker`）
`{ v: 1, round, rows: [{ id, name, side, init, current, status, hp: { kind: 'exact', hp, max, temp } | { kind: 'rough', level } | null, conds: [{ label, rounds }] }] }`；
概略：滿＝無傷、超過一半＝輕傷、一半以下＝重傷、0＝倒下。

### 3.6 存檔與專案檔
`data`：`{ list: [{ id, name, side, init, initMod, ac, hp, maxHp, temp, conds: [{ id, kind: 'srd'|'custom', key, rounds, level? }], death: { ok, ng, stable, dead }, hidden, note }], turn, round, settings, customConds }`。
讀的時候整理：看不懂的參戰者、狀態丟掉；重複的 id 換新的；HP 夾在 0～上限；看不懂的設定用預設值。

## 4. 互動與手感

- 加入後通知「已加入 N 位」（同一類只留最新一則）；新的一輪、狀態結束、專注、死亡、0 HP 受傷都用通知。
- 先攻、AC、HP 上限、臨時 HP 的欄位：打字時不立刻排序，按 Enter、離開或 ↑↓ 時才套用（不會打到一半整列跳走）。
- 拖曳只能從把手開始（列上有很多輸入欄）。

## 5. 容易做壞的地方

- 兩個 GM 分頁：沒有 F07 的同步時，從 5e 速查計算送來的參戰者會被另一個舊分頁的自動儲存蓋掉。
- 玩家視圖不能收到 GM 才看得到的資料（備註、AC、隱藏的參戰者）：由 GM 這邊算好再送（單元測試檢查送出的 JSON）。
- Immer 的 draft 物件不能拿到 produce 外面用（狀態結束的通知要先複製一份）。
- 鎖定順序時，加入的參戰者放最後；解鎖後要按「依先攻排序」才會重排。
