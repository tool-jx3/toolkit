# PL 自介卡與地雷表（pl-profile）行為規格

## 0. 概要

揪團、開團前用的**跑團自我介紹卡**＋**地雷表**。自介卡：暱稱、帳號、一句話、頭像、跑團經驗（PL／KP）、玩過的系統、喜歡的風格、
團的形式、平台與工具、可以的時段、聯絡方式、想說的話，每個欄位可以開關（眼睛）。地雷表：跑團常見的題材（7 類 59 個主題，
另有預設不顯示的成人向 5 個；3.2）× 五級（★ 盡量來、✓ 有就開心、～ 沒差、？ 先問我、✕ 地雷），可以加自訂主題與分類、每個主題補一句。

輸出：**卡片 PNG**（合成一張或分成兩張、6 種配色＋主色）、**純文字**（貼到 Discord 或揪團貼文）、**分享連結**（內容放進網址的 `#`，
不經過伺服器；打開是唯讀的檢視）、**專案檔**（JSON；有頭像時 ZIP）。**KP 對照表**：讀入幾個 PL 的分享連結或專案檔，合成一張表，
有人填「地雷」的主題標紅、有人填「先問我」的標黃。全部在瀏覽器內完成，內容與頭像自動存在這個瀏覽器。

群組 G7（介紹圖與宣傳）。工具 id `pl-profile`，名稱「PL 自介卡與地雷表」（D1）。

**主題清單與用語（2026-10-29 主控裁定）**：第一版的主題清單、分類順序、五級的名稱、對照表的判定名稱和未授權的原作太像（驗證時發現），
已整份換掉。新的內容（五級的名稱、符號與說明，分類與主題，對照表的判定名稱，系統的熟悉程度，團的形式，主題補充的提示）由**沒看過任何原作
與舊清單的人**另外寫成，本工具照原樣使用、不改字；設計說明摘要在 D4。

靈感來源（**五個原作都沒有授權條款**：只參考功能與做法；程式、介面文字、題目清單、範本、範例、版型、配色全部本站自己做，
不放 `UPSTREAM_LICENSE`）。原作在本機：`/home/user/upstream/<owner>_<repo>/`。

- PM＝**sonata9x/trpg-profile-maker**（<https://github.com/sonata9x/trpg-profile-maker>，讀的是 `d48734c`，2026-08-21）：單檔的韓文／日文
  TRPG 自介卡。暱稱、ID、委託出處、圓形頭像、年齡分級（只有日文版）、活動標籤、遊玩傾向（線上線下、語音、人數、長短團、GM／PL、RP 方式、
  閒聊、時段）、使用工具、聯絡方式、NG 的文字欄、MEMO、持有的規則書（熟練度、能不能當 GM）、規則書另成一張、8 個主色＋色碼、
  html2canvas 的 PNG。**頁尾的靈感來源是 PM**（registry）。
- JC＝**Jara03mofu/trpg-jirai-check**（<https://github.com/Jara03mofu/trpg-jirai-check>，`c80fae9`，2026-08-27）：日文的地雷確認表。
  大項目＋項目自己編、四級量表、再點一次取消、備註欄、自動存檔、範例資料；共享網址是計畫中（要接後端）。
- SM＝**Tetoriapot/sosaku-sheet-maker**（<https://github.com/Tetoriapot/sosaku-sheet-maker>，`c32e5d6`，2026-10-05）：通用的問卷
  （創作、TRPG）製作與回答，8 種題型（其中有四級量表）、範本、每題的補充、PNG（1080 寬，正方形／4:5／限時動態／自動高度、7 種配色、太長自動分頁）、
  回答 JSON、共享檔、**2～12 份回答的比較**（只看不同的、搜尋、選題目）。
- DM＝**dearmysn1p3r/DearMySn1p3r_25**（<https://github.com/dearmysn1p3r/DearMySn1p3r_25>，`b05cb61`，2026-09-16）：韓文的
  「Profile & Pair Maker」（同人創作帳號的自介卡）：名字＋表情符號、帳號、頭像（縮放、拖曳、方向按鈕）、一句話、NG／注意、
  帳號屬性等勾選標籤、配對圖庫（9 張）、12 種配色、3 種字型、PNG、**分享連結**（文字與勾選放進查詢參數，圖片不放）。
- TC＝**OEC309/trpg-consensus**（<https://github.com/OEC309/trpg-consensus>，`15cf1ae`，2026-10-05）：有伺服器與帳號的題材共識表。
  **只參考結構**：五級量表、分類＋項目、一般與成人向分開、自訂項目（名稱正規化後比對）、共享網址並排比較最多 12 人、列依大家的回答上色。

**和既有工具的差別**：角色介紹圖產生器（pair-maker）、角色分析圖（char-chart）是**角色**（PC）的介紹；CoC 房規表（house-rules）是 KP 的團規；
團期行事曆（session-calendar）是排時間。這個工具是**玩家本人**的介紹與題材的尺度，KP 用對照表確認一團的人能不能接受。

用語：「主題」＝地雷表的一列；「程度」＝五級之一；「內建主題」＝本站的清單（3.2）；「自訂主題／分類」＝使用者加的；
「眼睛」＝欄位放不放在卡片上；「成員」＝KP 對照表裡的一個人。

## 2. 輸入

- 文字欄：上限見第 1 節（以字〔碼位〕計）；單行欄位的換行換成空白；**控制字元（C0）與雙向文字的控制字元（U+202A～U+202E、U+2066～U+2069）
  拿掉**——打字時、讀存檔、專案檔、分享連結都一樣（多行欄位只保留換行）。
- 頭像：瀏覽器解得開的圖片（PNG、JPEG、WebP、GIF…；類型空白時看檔頭）；解不開時通知「讀不了「檔名」」。長邊 > 1024 px 時縮小（JPEG 存 JPEG、其他 PNG）。
- 專案檔：本站的專案檔格式（`format: 'trpg-toolkit-project'`、`tool: 'pl-profile'`）；JSON 或 ZIP（`project.json`＋`files/<頭像的 id>.<副檔名>`）。
- 分享連結：`#p=…`（3.5）；KP 對照表從一段文字裡找所有 `#p=`（前面可以有別的參數 `#a=1&p=…`）。
- 讀存檔、專案檔、分享連結一律整理（不丟錯）：不認得的選項用預設、清單截到上限、id 重複換新的、主題的 key 不認得的丟掉、
  自訂主題的分類不存在時放到第一個自訂分類（沒有時第一個內建分類）、頭像的範圍夾在蓋滿的範圍、主色只收 `#rrggbb`。

## 5. 容易做壞的地方

- **分享連結不能帶出關掉眼睛的欄位**：使用者關掉的通常是不想公開的（例如 LINE）；連結的內容任何人都看得到。KP 對照表的「加入我自己的」也用同一套規則。
- **網址是任何人都能編的輸入**：讀回一律整理；畫面上的文字只用 textContent／canvas；解壓縮有上限（3.5）。
- **再點一次清掉**：radiogroup 的按鈕要自己處理（原生 radio 不能取消）；鍵盤也要能清（Delete）。
- **字型載入後要重新排版**：量字寬會變；下載前先等字型、重新排一次，不能直接放大預覽。
- **復原的步數**：預設 400 ms 內的變更會合成一步，連續點幾個程度會被一次復原；這個工具用 `coalesceMs: 0`，文字欄與調色盤自己包手勢。
  打字中直接點分頁：Radix 在 mousedown 就換掉內容，欄位被卸載時不會送 blur，手勢不結束、之後的變更全部併進同一步——共用的 Tabs 已處理（DESIGN.md 4.1）。
- **KP 對照表的判定**：有人填地雷時就算有人沒填也要標紅（D9）；沒有人填的列不列，不然整張都是灰的。
- **成人向**：關掉時輸出、分享、對照表都看不到，但存檔裡的程度留著（打開又回來）。
- **頭像在 IndexedDB**：狀態只存 id；重新整理後讀回、讀不到時提醒；專案檔要把圖一起存成 ZIP；開專案檔時圖不在就開成沒有頭像（不要整個失敗）。
- **對照表的第一欄固定在左邊**：列的淡底是半透明的 token，第一欄要疊在不透明的底上，不然左右捲動時會透出後面的格子。
- **很長的圖**：iOS Safari 的畫布超過約 1,677 萬像素就畫不出來（下載變空白）；下載、複製、預覽都先算實際的倍率（F33）。
- **Discord 的 markdown**：使用者的字裡的 `*`、`_`、`||`、行首的 `#` 會變成粗體、劇透、標題；Discord 寫法一定要跳脫（3.4）。
