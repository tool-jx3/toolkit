# 房間 ZIP 產生器（room-zip）行為規格

## 0. 概要

把自己準備的圖片整理成 CCFOLIA 可以直接匯入的**房間 ZIP**。使用者先把圖片放進工具（素材），在工具裡設計房間的共用部分
（盤面大小、背景、前景，跨場景共用的標記、螢幕面板、立繪的對齊基準），再建立多個場景（每個場景的前景、背景、登場的立繪、
只在這個場景出現的演出圖、切入、與共用部分的差異），另外可以做棋子（敵方、友方 NPC，以及主持人流程用的聊天面板）、整理劇本文字；
最後按一下就得到 ZIP，在 CCFOLIA 開新房間後於房間設定裡讀入。工具內還附有小型的素材製作功能（單色圖、淡入淡出動態圖、
文字與圖形合成圖、圖片加工）。全部在瀏覽器內處理，不上傳任何東西。

- 輸入：圖片檔（多張、可拖放）、工具自己的專案檔、場景清單文字（貼上或 CSV／TSV 檔）、範本檔。
- 輸出：CCFOLIA 的房間 ZIP（`<專案名稱>.zip`）；工具自己的專案檔；範本檔；製作出來的素材（留在工具裡，隨 ZIP 輸出）。

靈感來源：johnko00/ccfolia-room-zip-maker-demo（<https://github.com/johnko00/ccfolia-room-zip-maker-demo>）

附件：[`room-zip.examples.json`](room-zip.examples.json)——自製測試圖的製作方法與雜湊、11 組操作序列（Z01～Z11）在舊版匯出的 ZIP
結構化摘要（檔案清單、`__data.json` 全部欄位值；圖片以「來源測試圖＋格式＋像素尺寸＋位元組數＋SHA-256」代表；ID 換成可讀的代稱），
以及 7 組素材製作功能（M01～M07）的輸出特徵。**輸出的數值以附件為準**；本文寫規則與摘要。

名詞（本規格自訂，新版介面文字照 DESIGN.md 用詞表另訂）：

| 本文用語 | 意思 |
|---|---|
| 素材 | 放進工具的一張圖片。工具內以「內容雜湊＋副檔名」識別，同內容只算一張。 |
| 標籤 | 素材的用途分類，可複選，共 7 種：前景／立繪／面板／外框／棋子圖示／演出／其他。 |
| 盤面 | CCFOLIA 房間的前景區域，以「格」為單位（CCFOLIA 的 1 格＝24 px）。座標原點在盤面中央，往右、往下為正。 |
| 共用標記 | 房間層級、所有場景都出現的圖片部件（輸出成 CCFOLIA 的「マーカーパネル」）。 |
| 螢幕面板 | 房間層級的圖片部件（輸出成 CCFOLIA 的「スクリーンパネル」），不隨場景切換。 |
| 部件 | 共用標記、螢幕面板兩者的合稱。 |
| 立繪庫 | 登錄的立繪（主立繪）與其表情差分；在場景裡勾選才登場。 |
| 演出 | 某一個場景專屬的圖或字（全畫面或自訂大小），輸出成該場景的マーカーパネル。 |
| 切入 | CCFOLIA 的カットイン；工具只做「名稱＋圖片」，聲音在 CCFOLIA 再加。 |
| 場景差異 | 某個場景對某個共用標記的換圖、移位、改大小、改堆疊順序或隱藏。 |
| 共用設定 | 立繪、部件、演出、切入本身（跨場景共用）的設定。 |

本文的控制項名稱是觀察者自訂的描述，不是舊版介面上的字。

## 2. 輸入

- **圖片**：瀏覽器能辨識為 `image/*` 的檔案都收（PNG、JPEG、WebP、GIF、BMP、AVIF…）；多選、拖放、在選圖面板裡載入、拖到拖放建立區都可以。
  處理規則見 F037～F046 與 3.3.1。解碼失敗或不是圖片→計入「無法讀取」。
- **動態圖的判斷**：GIF 一律算動態；PNG 在前 256 KiB 內、影像資料區塊之前出現動畫控制區塊（APNG）；WebP 在前 256 KiB 內有動畫區塊或擴充標頭的動畫旗標。
  （判斷依檔頭內容，不看副檔名；PNG／WebP 以 MIME 或副檔名決定要不要檢查。）
- **專案檔**：本工具自己的格式（新版自訂；不做舊版存檔的匯入，見 5.）。
- **場景清單文字**：貼上或讀 `.csv`／`.tsv`／`.txt`（UTF-8，開頭的 BOM 會去掉）。規則 3.2.13。
- **範本檔**：工具自己的範本匯出檔（新版自訂格式）。
- **數字欄**：舊版是瀏覽器原生數字欄；寫進資料時，位置與大小類一律取整數格（3.2.1），其餘以數字解讀，非數字時多半回到預設值（各欄已在第 1 節註明）。
  注意：介面上寫「每 0.5」的欄位，舊版實際的微調間隔是 1，而且資料一律被取整數（見 5.）。

## 3. 輸出

### 3.1 外部格式事實：CCFOLIA 的房間 ZIP

CCFOLIA 的「房間資料」匯出／匯入使用的 ZIP 格式。本節的欄位、值與限制依舊版的實際輸出整理；舊版原始碼註明這些常數已用 CCFOLIA 的實際資料驗證過
（`.token` 的值不被檢查、resources 必須與圖片檔一一對應否則匯入失敗、BGM 交叉淡化的值與畫面相反等）。
新版的格式讀寫集中在 `web/src/ccfolia/`（CCFOLIA 改版時只改那裡）。

#### 3.1.1 ZIP 結構

- **完全平坦**：不可以有任何資料夾。
- 必要檔案：
  - `__data.json`：房間資料（UTF-8 JSON；舊版不縮排、不換行）。
  - `.token`：必須存在；內容是「`0.`＋64 個小寫十六進位字元」的亂數字串，CCFOLIA 不檢查值。
  - 圖片檔：每張用到的圖一個檔。
- 圖片檔名＝**檔案內容的 SHA-256（64 個小寫十六進位字元）＋「.」＋副檔名**；副檔名依 MIME：`image/webp`→`webp`、`image/png`→`png`、`image/jpeg`→`jpeg`（不是 jpg）、`image/gif`→`gif`。
  內容相同就是同一個檔名，所以同一張圖在 ZIP 裡只出現一次。
- 舊版的項目順序：`__data.json`、`.token`、圖片（依 resources 的順序）；壓縮方式 DEFLATE；項目時間＝匯出當下。順序、壓縮等級與時間不影響匯入（對等時不比）。

#### 3.1.2 `__data.json` 的最上層

```json
{ "meta": { "version": "1.1.0" }, "entities": { … }, "resources": { … } }
```

- `meta.version`：固定 `"1.1.0"`。
- `entities`：九個物件，`room`、`items`、`decks`、`notes`、`characters`、`effects`、`scenes`、`savedatas`、`snapshots`。
  除了 `room` 以外，每個都是「ID → 內容」的對照；ID 是任意不重複字串（舊版用時間戳的 36 進位字串，部分用短亂數），只要同一類內不重複。
  `decks`、`savedatas`、`snapshots` 舊版一律是空物件 `{}`。
- `resources`：「圖片檔名 → `{ "type": MIME }`」，**必須與 ZIP 裡的圖片檔完全一一對應**（多一個或少一個都會匯入失敗）。

### 3.2 工具資料 → 房間 ZIP 的換算規則

#### 3.2.1 座標、大小與取整

- 工具內所有位置都是**物件中心**的座標（格，原點在盤面中央），大小是寬高（格）。
- 工具內的位置與大小一律是**整數格**：輸入、拖曳、方向鍵、對齊之後都以「四捨五入，剛好 .5 時往絕對值大的方向」取整（2.5→3、−2.5→−3）。寬高最小 1。
- 輸出到 CCFOLIA 時換成**左上角**：`x = 取整(中心x − 寬/2)`、`y = 取整(中心y − 高/2)`，取整規則同上（例：中心 0、寬 9 → −4.5 → −5；中心 −5、寬 9 → −9.5 → −10）。
- 盤面寬高輸出時取整、至少 1。

#### 3.2.2 房間

- 背景、前景＝房間設計的兩個選圖欄；盤面寬高＝房間設計的值。
- `markers`＝所有**可見、有圖片**的共用標記（螢幕面板除外），依工具內部件清單的順序（新加的在前）。
- `hidden3dDice`、`enableCrossfade` 依 F271；`sceneId`＝第一個場景。其他欄位見 3.1.3 的固定值。

#### 3.2.3 場景

- 依場景一覽的順序輸出，`order`＝1、2、3…。
- `foregroundUrl`＝場景自己的前景（沒有就是 null）。
- `backgroundUrl` 依背景模式：沿用房間背景→房間背景；與前景相同→場景前景，場景沒有前景時用房間前景；個別素材→該場景選的圖（沒選就是 null）；沒有背景→null。
- `fieldWidth`、`fieldHeight`＝場景的前景尺寸（建立時複製當時的盤面寬高）；`fieldObjectFit`＝自動裁切開→`cover`、關→`fill`；`displayGrid`＝場景的格線勾選。
- `text` 見 3.2.9。
- `markers`＝（1）所有可見、有圖的共用標記，套用這個場景的差異後的結果（被隱藏的不輸出）；接著（2）這個場景的立繪與演出中「有圖或有文字」的；最後（3）空白演出格（3.2.8）。

新建場景的初始值：背景模式＝沿用房間背景、前景尺寸＝當時盤面、自動裁切開、格線關、切換文字空白、沒有差異、沒有立繪與演出、沒有切入。

#### 3.2.4 共用標記、場景差異

- 場景差異可以覆蓋：圖片（含「無」）、x、y、寬、高、堆疊順序；或整個隱藏。沒覆蓋的項目用共用值。
- 換算後的值依 3.2.1；`text` 用共用值；`locked` 一律 true。
- 工具內的「鎖定（畫布上不能拖）」「固定長寬比」「預覽暫時隱藏」都不影響輸出。
- 沒有圖片的部件（即使有盤面文字）**完全不輸出**；顯示關閉的部件也不輸出。

#### 3.2.5 螢幕面板

- 所有可見、有圖片的螢幕面板輸出到 `items`，依部件清單順序，`order` 從 1 起算；`memo`＝盤面文字。
- 螢幕面板不屬於場景：場景差異（含預覽圖層的「此場景徹底隱藏」）**不影響**輸出（見 5.）。

#### 3.2.6 立繪（場景的登場立繪）

- 每個登場的立繪是那個場景的一個マーカーパネル：圖＝立繪（或差分）的圖，寬高＝立繪庫算出的寬高，堆疊順序＝該立繪的堆疊值（沒設定時用專案的立繪初始值，預設 30），位置＝場景裡的位置（換算見 3.2.1），文字空白。
- 立繪寬＝四捨五入(高 × 圖片寬高比)（至少 1），沒有圖片時比例當 0.72。
- **登場時的垂直位置**（中心 y）依房間設計的對齊方式，L＝基準線、H＝高度、D＝腳底抬升（差分沿用主立繪的 H 與 D，除非另外設定）：
  - 靠下、指定位置：y＝L − H/2 − D；靠上：y＝L＋H/2＋D；置中：y＝L＋D（皆取整）。
  - 預設 L＝15、H＝18、D＝0 → y＝6，輸出的左上 y＝−3。
- **等距排列**（登場、退場、貼上、套用範本、按等距排列時）：把這個場景的立繪依清單順序由左到右排開，總寬＝各寬度合計＋間隔×(數量−1)，整排的中心在 x＝0（指定位置模式時在指定的水平位置），每個的中心取整。
  例：寬 9 與 6、間隔 2 → 中心 −4 與 6（附件 Z04）。
- 之後改立繪庫的高度或抬升、改基準線或對齊方式，**已登場的位置不會重算**（寬高與堆疊順序會跟著變，見 5.）。

#### 3.2.7 演出

- 有圖或有盤面文字的演出才輸出；名稱不輸出。
- 調整大小：照位置與寬高。固定長寬比時改寬或高另一邊依圖片比例重算。
- 全畫面（位置固定在中心 0,0）：設 W、H＝場景的前景尺寸，a＝圖片寬高比（沒有圖時＝W/H）：
  - 等比蓋滿（預設）：寬＝W、高＝取整(W/a)；若高 < H，改成高＝H、寬＝取整(H×a)。
  - 拉伸：寬＝W＋1、高＝H＋1（多出 1 格以免邊緣露縫）。
  - 舊資料的「完整放入」：寬＝W、高＝取整(W/a)；若高 > H，改成高＝H、寬＝取整(H×a)。
  - 例（40×30）：900×800 的圖蓋滿→40×36（左上 −20,−18）；拉伸→41×31（左上 −21,−16）；沒有圖→40×30。
- 演出的位置大小在場景的前景尺寸改變後，下次畫面更新時自動重算（全畫面的）。

#### 3.2.8 空白演出格

工具設定勾選時，**每個場景**的 `markers` 最後追加 N 個（1～3）空白面板：中心 (0,0)、寬高＝房間的盤面寬高（不是場景的）、沒有圖、沒有文字，堆疊順序＝設定值、設定值＋1…。只在匯出時加入，工具畫面上看不到。

#### 3.2.9 切入與切換時文字

- `effects`＝切入清單中「有名稱或有圖」的，依清單順序（新加的在前；從場景「新建」的在最後），`order` 從 1；名稱空白的用「預設名＋這個順序號」。
- 場景的 `text`＝（指定了切入且該切入存在並有名稱時）「@切入名稱」一行，接著換行與切換時文字；沒有切入時就是切換時文字本身；兩者都沒有時是空字串。
  例：切入「A」＋文字「開場」→ `@A\n開場`；只有切入→ `@A`。

#### 3.2.10 棋子

- 依棋子清單順序輸出，欄位見 3.1.7。只有名稱、備忘、HP、MP、圖示、差分、聊天面板會寫進 ZIP；種類、裝甲、迴避、技能等工具內欄位不輸出（技能經由 KP 棋子之聊天面板間接輸出）。
- **KP 聊天面板的組成**（F250）：把下列 6 段（去掉頭尾空白後是空的段略過）以「空一行」接起來，最後再接 KP 自己的技能：
  1. 目前系統的「通用骰子與進行」範本；CoC 時把其中 `sCCB<=`、`sCC<=` 換成「`s`＋目前判定指令」。
  2. 「場景與切入」範本。
  3. PC 區：區塊標題一行；每個非空白的 PC 名稱（第 n 個，從 1 起算）兩行 `//HOn=名稱`、`/var HOn 名稱`。沒有 PC 時只有標題。
  4. 敵方區：區塊標題一行；每個敵方 NPC 接一段（段與段之間空一行；標題與第一段之間不空行）：
     「敵方標記：名稱」一行；每個技能（名稱與值都空白的略過）一行判定——CoC 為 `判定指令＋值 【技能名】 @名稱`、Emoklore 為 `值DL 【技能名】 @名稱`
     （值空白當 0、技能名空白用預設名）——有傷害時再一行 `傷害 【傷害標示】 @名稱`；沒勾「沒有迴避」時一行迴避判定（同判定格式，值空白當 0，技能名位置是迴避標示）；
     一行 `:名稱_HP-1`（名稱中的連續空白換成一個底線）；有裝甲時一行「裝甲標示＋`+值`」；有備忘時一行「★＋備忘」。段尾有換行。沒有敵方 NPC 時只有標題。
  5. 友方區：同敵方，只是標題與標記不同。
  6. 「備忘」範本。
  - 最後：若 KP 自己有技能（有名稱且有值），換行後每個一行 `判定指令＋值 【技能名】`（Emoklore 也用判定指令格式，舊版行為）。

  區塊標題、敵我標記、傷害／迴避／裝甲的標示文字與技能預設名由新版自訂（附件 Z07 以〈代稱〉表示）；指令語法（`CCB<=`、`CC<=`、`DL`、`@名稱`、`:名稱_HP-1`、`/var`、`//`）照上面。
- 新增的 NPC 預設帶一列空白技能；一般棋子沒有種類，不會出現在 KP 面板。

#### 3.2.11 不輸出的東西

劇本文字、場景備忘、整體備忘與待辦、暫用立繪、部件的鎖定／固定長寬比、預覽暫時隱藏、場景範本、演出預設、切入範本、立繪庫本身（只有登場的會輸出）、
沒有圖的部件、顯示關閉的部件、沒圖也沒字的演出、沒名稱也沒圖的切入、沒有被任何地方用到的素材。

#### 3.2.12 圖片集合

- ZIP 只收 `__data.json` 實際引用到的圖片（掃描所有字串欄位中的圖片檔名），一張一檔；`resources` 與之一一對應。
- **圖片遺失**：引用的檔名在工具內沒有圖片資料時（例如自動儲存還原、資料損毀），匯出前先修復（F279、F280）。
- 舊版一旦載入過的圖片，即使從素材一覽刪除，工具內仍保有資料：**被引用中的素材刪除後，匯出時照樣收進 ZIP**（但預覽上已顯示不出來；見 5.）。

#### 3.2.13 貼上建立場景的解析

- 逐行處理（`\r\n` 或 `\n`），空白行略過。
- 一行中有 Tab 就以 Tab 分欄（不處理引號）；否則以逗號分欄，支援雙引號包住含逗號的欄位、`""` 代表一個引號。
- 第一欄是場景名（去頭尾空白；空白則略過這行），第二欄是切換文字（去頭尾空白），第三欄是用來找前景的素材名。
- 第一行的第一欄若是常見的表頭字（例如中文的「場景名稱」「名稱」、英文的 name、scene，不分大小寫；舊版也認日文與韓文的同義字）就略過。新版至少要認得繁中與英文的表頭。
- 素材名稱的查找：去掉副檔名、不分大小寫；依素材一覽順序，第一個「名稱完全相同」或「雜湊檔名主體相同」或「名稱包含這個字」的素材；找不到→沒有前景。
- 建立的場景加在最後，其他設定同新建場景。附件 Z10。

#### 3.2.14 場景範本

- 登錄時保存：前景、背景模式與個別背景、前景尺寸、自動裁切、格線、切換文字、共用部件差異、立繪與演出（完整複製）、切入的指定。名稱與備忘不存。
- 套用（全部）：以上全部換成範本的值；「保留前景」時前景不換（範本沒有前景時也不換）。立繪與演出換新 ID，套用後立繪重新等距排列。
- 用範本建立：新場景（名稱＝範本名）再套用全部。
- 範本裡引用的立繪若已從立繪庫刪除，套用後該立繪仍以舊資料存在於場景中（舊版行為）。

### 3.3 素材的處理與製作輸出

#### 3.3.1 匯入時的處理（F037～F046）

1. 動態圖（2.）→ 原檔原樣保留。
2. 轉檔開啟且不是動態圖 → 解碼後等比縮到長邊 ≤ 上限（不放大；寬高四捨五入、至少 1），以 WebP 品質 0.8 編碼；**結果比原檔小才採用**，否則保留原檔（尺寸也保留原尺寸）。
3. 轉檔關閉 → 原檔原樣保留。
4. 副檔名與 MIME 依 3.1.1；原檔不是那四種格式而又保留原檔時（例如轉檔關閉時放 BMP），舊版會以 `.png`／`image/png` 的名義存放原始位元組（見 5.）。
5. 以處理後的內容算 SHA-256 決定識別名；已有同名素材→合併。

附件 Z09：長邊上限 800 時 1600×900 的 PNG → 800×450 WebP；動態 GIF、APNG 原樣；320×240 的 JPEG 轉檔開啟時變 WebP、關閉時保留為 `.jpeg`；同一張 GIF 再放一次被合併。

#### 3.3.2 淡入淡出動態圖（F095～F102）

- 尺寸：有原圖時＝原圖（長邊超過 1024 就等比縮到 1024，四捨五入）；沒有原圖時 128×128。
- 影格數 n＝四捨五入(秒 × 12)，夾在 2～15；第 i 格（0 起算）的進度 p＝i/(n−1)（第一格 0、最後一格 1）。
- 每格延遲（毫秒）：總長 T＝秒×1000，基本＝T/n 無條件捨去，前（T − 基本×n）格各多 1 毫秒（例：1 秒 12 格→前 4 格 84、其餘 83；2 秒 15 格→前 5 格 134、其餘 133）。
- 每格內容（原圖像素 RGBA、顏色 RGB，比例依 p）：
  - 透明↔圖片：RGB＝原圖，A＝原圖 A × 圖片比例（結束是圖片時＝p，開始是圖片時＝1−p），四捨五入。
  - 透明↔顏色：RGB＝顏色，A＝255 × 顏色比例（結束是顏色時＝p，否則＝1−p）。
  - 圖片↔顏色：顏色以比例 c（結束是顏色時＝p，否則＝1−p）蓋在原圖上：A＝c＋原圖A×(1−c)，RGB＝(顏色×c＋原圖RGB×原圖A×(1−c))÷A（A 為 0 時全 0），A 乘 255 四捨五入。
- 輸出 APNG：播放次數＝循環時 0（無限）、否則 1；結束是透明時，最後一格以「取代」方式繪製（確保最後完全透明）。
- 加入素材（不轉檔），標籤「演出」、動態圖；名稱＝原圖原始檔名去副檔名（沒有原圖時用預設名）＋「_淡入」或「_淡出」類的後綴（新版自訂文字），`.png`。
- 附件 M02～M04：T3 圖片→透明 1 秒＝12 格、播放 1 次、256×256；無原圖 透明→紅 2 秒循環＝15 格、播放 0 次、128×128；T1（舊版縮成 1200×675 後）圖片→黑 4 秒＝15 格、1024×576、約 1.1 MB。

#### 3.3.3 文字＋圖形合成圖（F105～F117）

- 由畫布背景開始，**清單最下面的元素先畫**（清單上方＝前面）；隱藏的元素不畫；每個元素以自己的不透明度繪製。
- 文字：字級 ≥ 1；字型＝類別對應的字型堆疊、粗細只有 400／700；文字頂端對齊 Y；每行 y＝Y＋行號×字級×行距倍率（行距倍率最小 0.5）；
  每行起點依對齊（左＝X、中＝X−行寬/2、右＝X−行寬），行寬＝各字寬合計＋字距×(字數−1)。描邊為圓角接合。
- 圖片：畫在 (X, Y)、寬高拉伸；圖形：方形、內切橢圓、三角形（上中、右下、左下三點）以單色填滿。
- 輸出 WebP（品質依選項），寬高＝畫布寬高。附件 M05（400×300 單色背景＋預設方形與圓形）。

#### 3.3.4 圖片加工（F120～F130）

在原圖原尺寸上依序處理，最後裁切、翻轉、旋轉：

1. 依亮度、對比、飽和度、色相、黑白、復古褐、模糊（與 CSS 濾鏡同義、同順序）繪製原圖。
2. 雜訊（> 0 時）：固定（依素材決定、每次相同）的灰階雜訊圖樣平鋪，以「疊加（overlay）」混合，不透明度＝雜訊% ÷ 220。圖樣新版自訂。
3. 色彩濾鏡（強度 > 0 時）：整面塗上濾鏡色，不透明度＝強度%；範圍「只有圖案部分」時只塗在不透明處。
4. 漸層（開啟時）：整面一條線性漸層（方向依設定；0～起點＝起點色、中間點＝兩端顏色與透明度的平均、終點～100%＝終點色），塗法同 3。
5. 透明度（< 100% 時）：整體不透明度乘上透明度%。
6. 範圍「只有圖案部分」時，最後把每個像素的不透明度改成「原圖不透明度 × 透明度%」（所以模糊等不會長出新的半透明邊）。
7. 裁切掉四邊的 px；勾了翻轉時先以原本的方向左右翻轉，再順時針旋轉（0／90／180／270，90 與 270 時寬高互換）。
8. 存成 WebP（品質 0.9）。舊版為了讓結果一定不同於原圖，會在左上角 1 個像素做極小的改變（紅色值 +17，超過 255 時繞回）；新版只要保證「加工結果一律成為新素材」即可（方法自訂，需主控確認是否保留這個像素差異）。

附件 M06（亮度 120%、左裁 100 px、轉 90°：1200×675 → 675×1100）、M07（不改設定也成為新素材）。

### 3.4 劇本文字的分割與標題

- 批次：先把 `\r\n` 換成 `\n`，逐行掃描：「去頭尾空白後等於分隔字串」的行、或（勾選時）空白行，當作分割點（分割點本身丟掉）；分隔字串去頭尾空白後為空時不以它分割。
- 每段：找第一個非空白行；若它是「# 標題」（`#` 前後可有空白），標題＝`#` 後的文字並把這一行從正文移除；否則標題自動產生。去掉後正文全空白的段不登錄。
- 自動標題＝第一個非空白行去頭尾空白後；若以 `#` 開頭取其後文字，否則取前 10 個字（UTF-16 單位）；整段空白時＝預設名＋序號。
- 一筆模式：標題欄去頭尾空白後非空就用它，否則自動標題。

### 3.5 工具自己的檔案（格式新版自訂）

`.ccproj` 是**原作自訂的專案檔**（JSON；最上層有原作自己的格式識別字串與版本號，CCFOLIA 不認得、也不會產生這種檔案；CCFOLIA 只讀房間 ZIP），
因此本規格不描述其欄位；新版用自己的專案檔格式（可沿用 `@/core/storage` 的專案檔），**不提供舊 .ccproj 的匯入**（需主控確認）。新版專案檔必須涵蓋：

- 專案名稱、房間設計頁的內容（含立繪基準、本專案初始值、房間輸出設定、暫用立繪）、部件、立繪庫、場景（含差異、立繪、演出、切入、備忘）、棋子、切入、場景範本、劇本文字、
  KP 設定（系統、判定、PC、技能、各系統的範本文字）、整體備忘、待辦、素材清單（名稱、標籤、原始與處理後大小、寬高、是否動態）**與圖片本體**；
- 舊版也把工具設定一起寫進去（跨專案 KP 範本不寫）；讀取時若瀏覽器已有工具設定就以瀏覽器的為準，沒有時才採用檔案裡的。新版可以不寫工具設定（屬可接受差異）。

範本匯出檔同樣是原作自訂格式（新版自訂）；舊版涵蓋：場景範本、舊格式的部件組合、演出預設與排列、切入範本與排列、跨專案 KP 範本、找圖網站、場景名稱符號、新建時的初始值；
**不含**圖片本體，也不含新版式的單一部件範本與棋子範本（那些只存在瀏覽器）。讀入時全部追加、換新 ID。

### 3.6 對等驗證的比對方法

1. **房間 ZIP**：附件每一組（Z01～Z11），在新版用相同的測試圖做相同的操作後匯出，解開比對：
   - 檔案集合：`__data.json`、`.token`、圖片檔；`.token` 的形狀；沒有資料夾；圖片檔名＝內容 SHA-256＋正確副檔名；resources 一一對應。
   - `__data.json`：把 ID 依附件的代稱規則換掉後，**所有欄位與值完全相同**（`playTime` 與 ID 字串本身除外；物件的鍵順序不比）。
   - 圖片：格式、寬高相同；PNG、GIF、JPEG 原檔保留的應與測試圖位元組相同（SHA-256 相同）；WebP 是瀏覽器編碼，同一版 Chromium 下應相同，不同時容許位元組不同，但寬高相同且位元組數差 ≤ 10%。
2. **素材製作**：附件 M01～M07 比對格式、寬高、影格數、播放次數、每格延遲、指定像素（±2）。文字元素因字型不同不比像素。
3. **介面與互動**：Playwright 依第 1 節逐項操作；匯出相關的結果以 1. 的方式比對。
4. **刻意差異**（第 5 節裁定後）在驗證紀錄寫明，並以修正後的規則比對。

## 5. 容易做壞的地方

- **座標是中心、輸出是左上角**，取整一律「.5 往絕對值大的方向」（3.2.1）；寫錯會讓奇數寬的物件左右差 1 格。附件的每個マーカーパネル都可以驗證。
- **圖片檔名＝內容的 SHA-256**，副檔名 `jpeg` 不是 `jpg`；resources 要與圖片檔**完全一一對應**；`.token` 一定要有；ZIP 不可有資料夾。
- **`enableCrossfade` 與畫面的開關相反**；`hidden3dDice`＝舊式骰子。
- **場景的 `markers` 是整組**：要把共用標記（套用差異後）、立繪、演出、空白演出格都放進每個場景；房間的 `markers` 只有共用標記。螢幕面板放 `items`，不放 markers。
- **場景沒有自己的前景時輸出 null**，但背景模式「與前景相同」時用的是房間前景（3.2.3）。
- **新場景複製當下的盤面尺寸**，之後改盤面不影響既有場景；要用「同步房間設計」（F190），它還會清掉共用部件的場景差異。
- **全畫面演出的大小依「場景」的前景尺寸**，空白演出格卻用「房間」的盤面尺寸（3.2.7、3.2.8）。
- **全畫面的拉伸模式是盤面 +1 格**，蓋滿模式依圖片比例可能超出盤面。
- **全畫面切換成調整大小後，「固定長寬比」是關的**：之後改寬不會連動高（附件 Z05 的第二個演出是 6×30）。
- **立繪的寬由高與圖片比例算出**，差分沿用主立繪的高度與抬升（除非另外設定），登場、退場、貼上、套用範本時整排重新等距排列。
- **立繪預設大小（F141）會改掉所有立繪的高度**，拖暫用立繪的右下角也會。
- **沒有圖的部件不輸出**（即使有文字），但只有文字的演出會輸出。
- **貼上建立場景**的 CSV 引號、Tab 優先、表頭略過、素材名稱模糊比對（3.2.13）。
- **匯入時「轉完比較大就用原檔」**：所以小的 PNG 會以 PNG 保留、尺寸也不縮；比較的是位元組數。
- **動態圖一律不轉檔**，判斷看檔頭（APNG 要在影像資料之前找到動畫控制區塊）。
- **切入名稱空白時的預設名用「輸出順序」編號**，被濾掉的空切入不佔號碼（附件 Z06）。
- **KP 聊天面板**的段落與空行規則（3.2.10）；敵我區塊的標題在沒有 NPC 時也會出現。
- **記住場景設定的「切換」語意**：再按一次同一個場景的書籤才是取消；按別的場景會改成記住那個場景。
- **場景詳細的「共用部件差異」展開狀態是全域的**（換場景後同一個部件仍展開）。
