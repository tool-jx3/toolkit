# 環境音混音器（ambience-mixer）行為規格

## 0. 概要

把雨聲、風、雷、海浪、溪流、營火、時鐘、心跳、蟲鳴、遠方的人聲等**環境音疊在一起**，做出跑團場景的背景聲：
點聲音卡片加入、各自調音量與參數（強度、距離、音色…），也可以一鍵套用本站設計的場景（雨夜洋館、地下墓室、暴風雨的船上…）、
隨機組合、存成「我的組合」、用網址分享；再把整個組合**匯出成可以無縫循環的 WAV**，放進 CCFOLIA 當 BGM（開「重複播放」）。
使用者也可以加入自己的音檔當作一軌（只在瀏覽器裡處理，不會上傳）。

**所有內建的聲音都是本站的程式即時合成的**（沒有收錄任何錄音檔，D1）：合成在共用模組 `@/core/audio/ambience`（純函式，Node 也能跑），
播放與混音用瀏覽器的 Web Audio，匯出用 OfflineAudioContext（節點和預覽相同）。

輸入：點選的聲音與參數、預設組合、分享連結（網址的 #）、自己的音檔（MP3、WAV、OGG…）。
輸出：喇叭（即時播放）、WAV 檔（PCM 16-bit，10 秒～3 分鐘，首尾相接）、分享連結。

靈感來源：**remvze/moodist**（<https://github.com/remvze/moodist>，程式 MIT；讀的是 `11c0be2`，2026-09-27）。
參考它的混音器做法改寫（聲音卡片的格狀清單、點了就加入並播放、各自的音量、全部播放／暫停與總音量、播放／暫停的淡入淡出 0.25 秒、
「起伏」〔Swell：10 秒週期、音量 40%～100%〕、組合的存取、隨機組合、網址分享、定時停止）；原作的授權全文在
`web/src/tools/ambience-mixer/UPSTREAM_LICENSE`。**原作的音效檔一個都不拿**：README 寫有的是 Pixabay Content License、有的是 CC0，
repo 裡沒有逐檔的出處（分不出哪個是 CC0），Pixabay 的授權不允許單獨再散布（主控已查，D1）。原作的介面文字（英文）、圖示、版面都不沿用，
預設組合是本站自己設計的跑團場景（D12）。

**和既有工具的差別**：音樂播放畫面產生器（music-frame）是幫一首音樂做「正在播放」的畫面與影片；這個工具做的是聲音本身（環境音的混音與循環 BGM）。

用語：「軌」＝混音裡的一個聲音（合成的或自己的音檔）；「參數」＝每個合成聲音自己的選項（強度、距離…）；「變化」＝同樣的聲音與參數、
不同的亂數（換一種變化＝換種子）；「循環」＝匯出的 WAV 從頭播到尾再接回開頭；「首尾相接」＝接回開頭時沒有跳動。

## 2. 輸入

- **聲音卡片、預設組合、隨機組合、我的組合**：見 F02、F15～F17。
- **自己的音檔**：瀏覽器的 Web Audio 解得開的（MP3、WAV、OGG、M4A、AAC、FLAC、Opus、WebM 的聲音…）；類型空白的看檔頭補上。
  解碼後的取樣率是瀏覽器音訊系統的取樣率（44.1 或 48 kHz），聲道照原檔。
- **分享連結**：網址的 `#s=…`（3.5）；網址是任何人都能改的輸入，讀回來一律整理（3.6）。
- **存檔**：localStorage，讀回來同樣整理（之後的版本存的、或被改壞的也不會讓工具壞掉）。

## 3. 輸出與數值

### 3.1 合成的聲音（`@/core/audio/ambience`）

每個聲音是一個純函式：給參數、長度（整數秒，10～600）、取樣率與種子，算出一整段**首尾相接**的取樣（立體聲或單聲道）。
同樣的輸入在 Node、瀏覽器、Worker 裡結果完全一樣（e2e 逐取樣比對）。做法（`dsp.ts`）：

- **環狀處理**：濾波器、殘響先跑過最後一段（濾波器 0.5 秒、殘響 2～6 秒）暖機再從頭跑，第 0 個取樣看到的狀態就是從尾巴接回來的狀態；
  隨機曲線（陣風、浪、起伏）的控制點環狀內插；事件（雨滴、雷、滴答）超出結尾的部分繞回開頭；正弦的頻率調成整段剛好整數個週期。
- **雜訊**：白（均勻）、粉紅（Paul Kellet 的近似濾波）、棕色（有漏的積分）；濾波器是 RBJ 的雙二階（低通、高通、帶通、峰值）。
- **最後**：22 Hz 高通、去掉直流、乘上校準的音量（連續的聲音預設參數時約 −14～−20 dBFS RMS），超過 0.6 的瞬間柔和地壓下來（3.4 的曲線，門檻 0.6）。

### 3.3 自己的音檔的循環

- **循環**（接縫淡化 X 秒，最多檔長的一半）：長度 F 的音檔 → 長度 F − X 的循環，開頭 X 秒＝原本的開頭（淡入）＋原本最後 X 秒（淡出），
  等功率（sin／cos）交叉淡化；預覽直接循環播放它。**匯出**時把它鋪滿 L ＋ X 秒、把多出的 X 秒以同樣的方式疊回開頭（循環長度剛好整除 L 時直接鋪），
  接縫淡化是 0 時以 0.05 秒計。
- **只播一次**：淡入（線性）、淡出（線性）後放在 L 秒的開頭，之後是靜音（比 L 長時截斷，在截斷處至少淡出 0.5 秒）。

### 3.4 混音（預覽與匯出相同）

每一軌：聲音 → 音量（增益＝(音量 ÷ 100)²）→ 起伏（開：增益 0.7 ＋ 0.3 × sin(2π t ÷ 10)）→ 總音量（2 × (總音量 ÷ 100)²）→
柔和限幅（WaveShaper，不 oversample：輸入先 × 0.5，曲線把 |u| ≤ 0.7 原樣輸出、以上 0.7 ＋ 0.3 × tanh((|u| − 0.7) ÷ 0.3)，最大不超過 1）→ 喇叭／匯出。
- **預覽**：合成的軌是 60 秒、32 kHz 的循環（＝匯出的預設），在最多 2 個 Worker 裡合成；播放／暫停淡入淡出 0.25 秒；換掉聲音時新舊交叉淡化 0.3 秒、
  接在同一個位置；拿掉時 0.25 秒淡出。切到別的分頁再回來時，若瀏覽器把聲音暫停了就恢復。
- **匯出**：OfflineAudioContext（聲道 1 或 2、匯出的取樣率），每一軌都是首尾相接、長度剛好 L 秒的循環（合成的在匯出的長度與取樣率合成），
  多算前面 2 秒、取 [2, 2 ＋ L) 秒（所有東西的週期都整除 L，所以結尾接得回開頭）；單聲道由 Web Audio 左右平均。結果編成 PCM 16-bit WAV。

### 3.5 分享連結

`#s=` ＋ deflate 壓縮的 JSON `{ v: 1, d: { m: 總音量, n: 組合名稱, t: [[聲音 id, 音量, 參數, 起伏 0／1, 種子], …] } }` 的 base64url（共用的 `core/share`）。
讀回時整理（3.6）；不認得的聲音丟掉、一個都不認得時算壞掉；超過 8,000 字、版本不符時算壞掉。

### 3.6 整理（存檔、網址）

- 合成的軌：聲音要認得；同一個聲音只留第一個；音量 0～100 整數；參數只留這個聲音有的、夾在範圍、對齊間隔、選項夾在選項數內、缺的補預設；起伏是布林；種子 0～999,999。
- 音檔的軌：id `f<n>`、資產 id 字串；名稱 200 字內；長度、接縫（0～5）、淡入淡出（0～10）夾住、四捨五入到 0.1 秒（長度 0.001 秒）；循環預設開。
- 最多 12 軌、音檔最多 6 個；總音量 0～100；匯出設定只收清單上的值；組合名稱 40 字。

### 3.7 檔名

`環境音-〈組合名稱，沒有時是前三個聲音的名稱以「・」連接（音檔去掉副檔名），都沒有時「混音」〉-〈秒數〉秒.wav`，經共用的 `safeFileName` 清理
（例：`環境音-雨夜洋館-60秒.wav`、`環境音-風・貓頭鷹・時鐘-30秒.wav`）。音量 0 的軌不算。

## 4. 互動與手感

- 預設：沒有聲音、總音量 100%、匯出 1 分／32 kHz／立體聲、定時停止關、各區塊展開（我的組合收合、使用方式收合）。
- 快捷鍵：空白鍵（播放／暫停）、Ctrl／⌘＋Z、Ctrl／⌘＋Shift＋Z、Ctrl＋Y、?（快捷鍵表）；焦點在輸入欄、滑桿、開關時不攔截（共用規則）。
- 存檔：`trpg-toolkit:ambience-mixer`（混音）、`trpg-toolkit:ambience-mixer:preview`（我的組合）、音檔在 IndexedDB；區塊的展開狀態另外記。
- 匯出的進度：每一軌合成完一格、混音一格（約 1 分鐘 32 kHz 的 4 軌組合，預覽已經合成好時 0.5 秒左右）。
- 一個聲音合成 60 秒約 0.1～1.2 秒（人聲最久），在 Worker 裡做，畫面不卡。

## 5. 容易做壞的地方

- **無縫循環不能靠事後的頭尾交叉淡化**：雜訊、濾波、殘響、陣風的曲線、雷聲的尾巴都要環狀處理，否則接縫一定有跳動或音色突然改變（單元測試把環狀處理和「連續處理兩次的穩態」逐取樣比對）。
- **預覽＝匯出**：合成要是決定性的純函式（同一個種子、Node 與瀏覽器結果一樣），混音只能是增益與無記憶的限幅；WaveShaper 開 oversample 時 Chrome 會多 128 個取樣的延遲、
  結果也不再逐取樣相同（驗證時發現），所以不 oversample。
- **起伏的週期要整除匯出的長度**：所以匯出的長度都是 10 秒的倍數；合成的聲音裡的週期（60 Hz 的嗡嗡聲、蟲鳴的起伏、唱片一圈）也要整數秒裡整數個。
- **瀏覽器要使用者操作才能出聲**：AudioContext 在第一次按播放（或點卡片、預設組合）時才建立；開分享連結、重新整理後都不自動播放。
- **大量的取樣很佔記憶體**：60 秒 32 kHz 立體聲一軌約 15 MB；快取只留 AudioBuffer（不另外留一份 PcmAudio），用不到的只留最近 4 個；最多 12 軌。
- **改參數時不要每一格都合成**：停下 0.15 秒才合成，還在排隊的舊要求丟掉；新的好了才換，換的時候交叉淡化、接在同一個位置。
- **展開運算子不能用在幾十萬個取樣上**（`Math.max(...陣列)` 會堆疊溢位），一律用迴圈。
- **共用的提示與確認在 ToolShell 裡面**：通知、分享連結的確認透過 ToolShell 裡的元件接上。

### 刻意的做法與待裁定（D 項，需主控確認）

| # | 項目 | 本站的做法 |
|---|---|---|
| D1 | 音源 | moodist 的 91 個音效檔（117 MB）一個都不拿（Pixabay 授權不可再散布、repo 沒有逐檔的授權）；內建的聲音全部由本站的程式合成，可以自由使用（匯出的檔案也是）。之後若要內建真實錄音，要另找**逐檔標明 CC0** 的來源（例：Freesound 上標 CC0 的個別錄音、OpenGameArt 的 CC0 分類），逐檔記下出處與授權再收錄；這次不收。 |
| D2 | 合成的方式 | 派工寫「用 Web Audio 程式合成」：本站把合成寫成 JS 的純函式（算成一整段首尾相接的 PCM），播放、混音、匯出才用 Web Audio（AudioBufferSourceNode 循環、GainNode、OscillatorNode、WaveShaper、OfflineAudioContext）。理由：首尾相接可以由構造保證（Web Audio 的即時節點做不到環狀濾波）、結果是決定性的（預覽＝匯出、分享連結的對方聽到一樣的）、可以在 Node 裡測頻譜與接縫；代價是改參數要 0.1～1 秒重新合成。 |

| D4 | 聲音的品質 | 合成的近似：數值（頻率、包絡、密度）參考常見的程序音效做法自己定的，**實作者沒有辦法實際試聽**，只用頻譜、音量、接縫的量測與頻譜圖檢查；請主控試聽（每個聲音可以單獨加入、匯出 WAV），覺得不好聽的再調參數或拿掉。 |
| D5 | 預覽的長度 | 預覽固定 60 秒、32 kHz（＝匯出的預設，照預設匯出時和預覽一模一樣）；匯出其他長度或取樣率時重新合成，同樣的設定、細節（雷的時間等）不同。60 秒的循環在跑團時聽得出重複的是雷、嘎吱聲這類事件；要更少重複就匯出 2～3 分鐘。 |
| D6 | 音量的曲線與限幅 | moodist 的音量是線性、沒有限幅；本站每一軌與總音量都是平方（聽感比較平均），總音量再乘 2（每個聲音單獨都留了餘裕，幾軌混在一起才是適當的音量），主輸出柔和限幅（3.4）。預設總音量 100%。 |
| D7 | 起伏 | 照 moodist 的 Swell（10 秒、40%～100%），匯出時也有（所以匯出的長度是 10 秒的倍數）；moodist 是每 50 ms 改一次音量，本站用 OscillatorNode。 |
| D8 | 定時停止 | moodist 自己輸入時、分，到時淡出 1 秒；本站是選單（15～120 分），淡出 8 秒（跑團散場、休息時比較自然），不存檔。 |
| D9 | 隨機組合 | moodist 從 84 種隨機挑 4 個（音量 20～100%），常常是不相干的聲音疊在一起；本站一個背景＋一兩個點綴並排除不合理的搭配（3.2），參數也隨機。 |

| D12 | 預設組合 | moodist 的 3 個 starter mixes（Deep focus 等，專注用）換成本站的 10 個跑團場景（3.2）；套用時保留自己的音檔。 |
