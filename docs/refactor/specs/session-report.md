# 團報產生器（session-report）行為規格

## 0. 概要

跑完團之後在 X（Twitter）發「團報」用的文字產生器：輸入系統、劇本名稱、作者、結果、主持人（KP／GM／DL…）、參加者（標記、HO、PC、PL）、
日期與主題標籤，選一種團報範本與文字樣式，就即時產生一篇排好版的團報文。預覽本身可以直接編輯（之後再改輸入時，手動改過的部分會保留），
可以插入文字裝飾（分隔線、符號）、復原／重做、計算 X 的字數，最後複製或直接開啟 X 的發文畫面。
跑團紀錄簿可以把一團「送到團報產生器」，開頁時讀入。全部在瀏覽器內完成，不連任何伺服器。

輸入：表單、跑團紀錄簿的交接資料（瀏覽器儲存空間）。輸出：預覽的文字（剪貼簿）、X 的發文網址（新分頁）。沒有下載檔案。

靈感來源：くま。的「TRPG WEBツール観測所」（<https://kumachansteps.github.io/trpg-web-tools/>）。原作未授權（作者站上規約另外禁止素材二次利用）：
**17 種範本的文字、文字裝飾、範例值、介面文案一律自寫**，不翻譯原文；本規格只描述功能與規則（3.2 只寫每個範本放了哪些資料、順序如何）。

用語：「預覽」＝右邊可以編輯的團報文字欄；「部件」＝範本裡的一段文字，分成固定文字（裝飾、括號、換行）與資料（系統、劇本、名字…）；
「樣式部件」＝會套用文字樣式的資料（3.3）；「手動編輯」＝使用者直接在預覽裡改的內容；「交接資料」＝跑團紀錄簿寫在瀏覽器裡、給本工具讀的一團（3.10）。

## 2. 輸入

- **文字欄**（系統、作者、劇本、結果、主持人與參加者的名字、HO 補充、日期、主題標籤、備註）：任何文字（含表情符號、全形字、換行只在備註）。產生團報時去頭尾空白（備註不寫進團報）。不做 HTML 跳脫。
- **交接資料**：瀏覽器儲存空間的固定鍵名（3.10）；格式由跑團紀錄簿決定（`docs/refactor/specs/session-log.md` 3.9）。
- **預覽**：任何文字。

### 3.2 17 種範本放的資料

每種範本由固定文字與資料部件組成。**舊版與新版第 n 種範本的資料部件序列相同**（去掉固定文字後，資料的種類與順序一樣；例外見下方說明與 5. D3），
固定文字（裝飾、括號、分隔符號、縮排、換行）新版全部自做。符號說明：

- 主持人×n＝每位主持人依序寫「身分、名字」；參加者×n＝每位參加者依序寫「標記（＋HO 補充）、兩個名字（依名字順序）」，標記不寫時只有名字；

### 3.3 文字樣式

樣式部件：系統、身分、PC／PL 標題（含「KPC／KP」）、標記、HO 補充、結果、日期。劇本、作者、名字、主題標籤與固定文字不轉換。轉換步驟：

1. 把小型大寫字母換回一般大寫：ᴀ ʙ ᴄ ᴅ ᴇ ꜰ ɢ ʜ ɪ ᴊ ᴋ ʟ ᴍ ɴ ᴏ ᴘ ꞯ ʀ ꜱ ᴛ ᴜ ᴠ ᴡ ʏ ᴢ → A～Z（沒有 X）。
2. 「不轉換」到此為止（只做第 1 步）。
3. 整段做 Unicode 相容分解（NFKD）：全形英數變半形、「①」變「1」、全形標點變半形、帶重音的字母拆成字母＋附加符號、日文濁音拆開…
4. 半形英文字母、數字依下表換成 Unicode 的數學英數字（碼位＝表中的起點＋與 A／a／0 的距離），其他字元不變。
5. 【新版】整段做 Unicode 標準組合（NFC），把第 3 步拆開、但沒有被轉換的字（例如濁音、韓文）組回去（見 5. D7）。

### 3.4 作者行

作者欄去頭尾空白後：

1. 空白 → 沒有作者行。
2. 名字與結尾的敬稱之間的空白拿掉（敬稱：様、さん、氏、先生、樣、桑、老師；例「王小明 老師」→「王小明老師」）。
3. 以「作:」「作：」「作者:」「作者：」開頭 → 原樣使用，只把開頭的半形冒號換成全形（「作者:王」→「作者：王」）。
4. 否則 → 「作者：」＋名字＋（不是以上述敬稱結尾時）「老師」。例：「王小明」→「作者：王小明老師」、「米可さん」→「作者：米可さん」。

插入：範本產生並整理（3.5）之後，劇本不是空的、而且團報裡還沒有這一行文字時，插在**第一個含有劇本名稱的行**的下一行；找不到就不插。插入後再做一次 3.5 的第 2、3 步。

### 3.5 整理

範本的部件接起來之後：

1. 每一行行尾的半形空白與 Tab 拿掉（全形空白保留）；
2. 連續 3 個以上的換行縮成 2 個（最多一個空行）；
3. 整段去頭尾空白（含全形空白）。

資料是空字串的部件不輸出（例如主題標籤空白時，範本最後的那一行就不見了）。

### 3.6 X 的字數

預覽的文字先做 Unicode 標準組合（NFC），再一個碼位一個碼位計算：U+0000～U+10FF、U+2000～U+201F、U+2032～U+2037 算 1，其他（中日韓文字、全形符號、數學英數字、表情符號的每一個碼位…）算 2。
上限 280。這是簡易計算：網址、表情符號組合等和 X 實際的計算可能不同（畫面上有說明）。例：「abc」3、「團報」4、「𝘼」2、「👍🏻」4。

### 3.7 X 的發文網址

`https://twitter.com/intent/tweet?text=` 加上預覽去頭尾空白後的文字（URL 編碼，空白編成 `%20`、換行 `%0A`），在新分頁開啟（不帶來源頁的參照）。

### 3.8 手動編輯的保留

記住「上一次產生的團報」（基準）與「有沒有手動編輯」。輸入改變、重新產生團報時：

- 沒有手動編輯 → 預覽換成新的團報。
- 有手動編輯 → 比較基準與目前的預覽：找出兩者相同的開頭（長度 s）與相同的結尾（不與開頭重疊；基準剩到 b、預覽剩到 e），
  手動改的那一段＝預覽的 [s, e)。新的預覽＝新團報的前 s 個字元＋手動那一段＋新團報的最後（基準長度 − b）個字元（起點不小於 s）。基準或預覽與基準相同時直接用新團報。
- 之後基準＝新團報；「有手動編輯」＝新的預覽與新團報不同。

字元以 UTF-16 碼元計（與瀏覽器文字欄的游標位置相同）。「有手動編輯」在打字（F31）、插入裝飾（F29，新版，見 5. D9）、清除預覽（F37）時設為是；重新產生（F53）、清除輸入（F39）時設為否；復原、重做不改變它。

### 3.9 預覽的復原紀錄

- 「記一步」：目前的預覽和紀錄最後一筆不同時才加進紀錄（最多 80 筆，超過丟最舊的）；**不論有沒有加，重做紀錄都清空**。
- 會記一步的操作：在預覽打字（每次輸入前）、F11 快速切換列、插入裝飾、清除預覽、重新產生、讀入交接資料（新版記的是讀入前的預覽，見 5. D23）。改輸入、改選單、快捷鍵換範本／樣式不記（但會重新產生預覽）。
- 復原：紀錄是空的就不做事；否則目前的預覽放進重做紀錄，預覽換成紀錄的最後一筆。重做反過來。只改預覽的文字，不改輸入。
- 清除輸入（F39）時兩個紀錄都清空。紀錄不保存（重新整理就沒有）。

### 3.11 對等驗證的比對方法

舊版在本機開 `tools/session-report/`，新版開 `next/session-report/`（介面切成繁中）。範本的固定文字兩版不同，所以團報全文不逐字比，改比資料：

1. **資料部件序列（3.1、3.2）**：每個欄位填互不相同、容易辨認的標記值（系統用自行輸入、2～3 位主持人用不同身分、2～4 位參加者、HO 補充、作者、結果、日期、主題標籤），
   文字樣式選「不轉換」，對 17 種範本各產生一次，依每個標記值在團報中出現的位置排出序列，兩版逐範本比對（3.2 的例外：15、17 的身分；標題只比 PC、PL 的先後）。
   至少 300 組隨機輸入（隨機敬稱、名字順序、第一列標記、空白欄位〔改用範例值〕、刪光主持人或參加者、名字已帶敬稱）。範例值的字樣不比，只比位置。
2. **文字樣式（3.3）**：把隨機字串（英數、全形英數、小型大寫字母、帶重音的字母、日文濁音、韓文、圈號數字、表情符號）填進自行輸入的系統，10 種樣式各取團報中系統那一段，兩版逐字比對（新版多做的 NFC：比對前兩邊都先 NFC）。至少 1,000 組。
3. **作者行與整理（3.4、3.5）**：作者欄各種寫法（空白、帶各種敬稱與空白、作／作者開頭、半形冒號）與帶行尾空白、Tab、全形空白的欄位，檢查作者行的內容、插入位置，以及沒有行尾半形空白、沒有連續兩個空行、頭尾沒有空白。
4. **手動編輯與復原（3.8、3.9）**：以本規格寫成的參照演算法，對兩版各做 200 組隨機操作序列（在預覽隨機位置打字或刪字、改輸入、換範本、快速切換列、插入裝飾、清除、復原、重做、重新產生），每一步檢查預覽是否等於參照演算法的結果。
5. **字數（3.6）**：隨機字串（含 3.6 各範圍的邊界碼位、表情符號組合、組合用附加符號）填進預覽，兩版的「N / 280」與狀態一致。至少 1,000 組。
6. **交接資料（3.10）**：同一份交接資料（系統用正規值、各種別名、對不上的文字；主題標籤陣列與文字；日期清單；多位參加者）讀入兩版，比對表單的值（系統、自行輸入欄、劇本、日期、主題標籤、備註、主持人身分與名字、參加者）與交接資料是否被刪除；5. D8、D11 的差異除外。
7. **發文網址（3.7）**：攔截新分頁的網址，兩版對同一段預覽文字（含頭尾空白、換行、表情符號、`&`、`#`、`%`）解析出的 `text` 參數相同。

## 4. 互動與手感

- 每個操作立即反映到預覽，沒有延遲。
- 預設：範本第 1 種、文字樣式粗斜體（無襯線）、系統 Call of Cthulhu、敬稱不加、名字順序 PC → PL、主持人一列（KP）、參加者一列（HO1），其他欄位空白；開頁時預覽是用範例值產生的團報。
- 舊版的提示用瀏覽器的訊息框（複製、沒有內容可以發、讀入完成約 3.2 秒的通知）；新版用本站的通知（複製成功約 2 秒）。
- 插入裝飾後焦點在預覽、游標在插入的文字後面；清除預覽、重新產生、Ctrl／⌘＋E 後焦點也在預覽。
- 快速切換列的按鈕：滑鼠停留或鍵盤聚焦時顯示樣式名稱。
- 交接資料的詢問在開頁、預覽產生之後出現。

## 5. 容易做壞的地方

- **只有第一位參加者的標記可以選**，其他人的標記跟著它；標記是 PC/PL、PL/PC、自由時**連 HO 補充也不寫**。
- **名字順序由第一列的標記優先決定**：第一列標記 PL/PC 時，即使輸入順序是 PC → PL，團報也是 PL 在前、標題 PL/PC。
- **敬稱**只加在主持人與 PL，不加在 PC；名字已經以那個字結尾時不重複；「一列都沒有時的範例值」不加敬稱，但「列裡名字空白而用範例值」會加。
- **第一位主持人名字空白時用範例值；第二位以後空白就整列不寫**。
- **文字樣式只轉換樣式部件**，而且轉換前先做相容分解：樣式部件裡的全形英數、全形標點（！？（）：）、全形空白都會變成半形；「不轉換」不做分解。
- **小型大寫字母會被換回一般大寫**再轉換（所以範本裡寫小型大寫沒有意義；使用者打的小型大寫也一樣）。
- **作者行插在第一個含劇本名稱的行下面**；團報裡已經有完全相同的文字時不插（第 14 種範本自己寫了作者行）。
- **整理只拿掉行尾的半形空白與 Tab**；行首的空白、全形空白保留（範本的縮排）。
- **手動編輯的保留**是「相同開頭＋相同結尾」的簡單比對：改到資料所在的位置時，新的資料可能被手動那一段蓋掉或重複，這是舊版的行為，照舊。
- **清除預覽之後再改輸入，預覽仍是空的**（3.8 的結果），要重新產生才會回來。
- **復原、重做只改預覽的文字**：復原到換樣式前的文字時，選單仍是新的樣式，下一次改輸入就會依選單重新產生。
- **快捷鍵在文字欄裡也有效**（F46、F47、F50～F53）；Ctrl／⌘＋Z 只在預覽區內取代瀏覽器的復原，在其他文字欄照常是瀏覽器的復原。
- **X 字數是簡易計算**，畫面上要說明。
- **交接資料讀完要刪除**（讀入或捨棄時），稍後時保留；`system` 是跑團紀錄簿的正規值（日文），要對得上 3.10 的表。
- **讀 localStorage 一律包 try/catch**（被封鎖、隱私模式時當作沒有交接資料）。

## 7. 主控裁定（審查者，2026-10-02）

- 規格審查通過：原作未授權（くま。的站上規約另外禁止素材二次利用），17 種範本的裝飾與文字、範例值、文字裝飾、示範帳號一律自做；**資料部件的序列**（哪些欄位、什麼順序、條件）屬於功能，照舊版，驗證時逐範本比對部件序列。
