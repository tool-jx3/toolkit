# PDF 壓縮器（pdf-compress）行為規格

## 0. 概要

在瀏覽器裡縮小 PDF：劇本、手冊、角色卡、handout 的 PDF 要傳 Discord（免費帳號 10 MB）、上傳 BOOTH 或雲端之前先縮小。
一次可以放好幾個 PDF（批次），逐檔顯示進度與結果，可以單檔下載或打包成 ZIP。**檔案不會上傳**：所有處理都在瀏覽器的
Web Worker 裡（qpdf、mozjpeg、pdf.js、pdf-lib 都打包在本站），畫面不會卡住、可以取消。

做法照兩個原作合起來：

- **多個候選、取最小**（QC）：結構壓縮（qpdf 的物件串流、zlib 9、重新壓 Flate）、快速網頁檢視、移除重複的串流、
  影像重新壓縮，每個候選都要通過檢查（`qpdf --check`、頁數），取最小、而且比原檔小的；都沒有比較小時**保留原檔**。
- **影像依解析度縮小、重新壓成 JPEG**（WP 的 low／recommended、QC 的 balanced／maximum）：本站量影像在頁面上畫多大，用**真正的有效 DPI**
  決定縮多少（兩個原作都只看像素的長邊）。
- **整頁轉圖**（WP 的 maximum）：每頁畫成一張 JPEG，最小，但文字不能選、不能搜尋。

輸入：PDF（可以多個；要開啟密碼的輸入密碼）。輸出：壓縮後的 PDF（單檔下載或 ZIP）。設定（等級、進階設定）存在瀏覽器；PDF 不存。

靈感來源（兩個原作合成一個工具，都是 MIT，可以參考程式改寫；授權全文在 `web/src/tools/pdf-compress/UPSTREAM_LICENSE`）：

- QC＝**mrflamingchad67/qcompress**（<https://github.com/mrflamingchad67/qcompress>，讀的是 commit `d60a155`，2026-10-18）：
  SvelteKit 的單檔工具，qpdf 12.4.2 的 WebAssembly（vendored）＋jSquash（mozjpeg）。三種模式（Lossless／Balanced／Maximum）、密碼、結果報告。
- WP＝**ECgear/wise-pdf**（<https://github.com/ECgear/wise-pdf>，讀的是 commit `0fe3907`，2026-10-24）：函式庫＋示範頁，pdf.js＋pdf-lib＋mozjpeg。
  三個強度（low／recommended／maximum）；另外的「PDF 轉 JPG」「圖片轉 PDF」**不收**（不在這次範圍；本站目前沒有同類工具，
  之後要做時可以直接用 `core/pdf` 的 `renderPage` 與 pdf-lib）。

頁尾的靈感來源是 QC（registry）；WP 由主控寫進 README／ATTRIBUTION。兩個原作的介面文字（英文、日文）與說明都不沿用（本站自己寫繁中）；
QC 的版面（convert.to.it 風格的置中卡片）、圖示、頁尾的版權與原始碼連結、WP 的分頁與自動下載都不移植。

用語：「原作」＝上面兩個；「候選」＝同一個檔案用不同做法壓出來的結果；「有效 DPI」＝影像的像素 ÷ 它在頁面上畫出來的英吋數
（一張圖畫在好幾個地方取最大的那一個）；「自訂」＝原作沒有、數值由本站決定。

## 2. 輸入

- PDF：選檔、拖放、貼上。認檔頭（`%PDF-` 在前 1024 位元組內），不看副檔名與類型。PDF 1.0～2.0、物件串流、交叉參照串流、增量更新都可以（qpdf 先攤平）。
- 密碼：要開啟密碼的檔案在那一列輸入。AES-256、AES-128、RC4 都可以（qpdf）。
- 壞掉的檔案：qpdf 能修好的（`--warning-exit-0`：只有警告）照常處理；修不好的顯示錯誤（F04）。**注意**：qpdf 會「修好」一些輕微損壞，壓縮後的檔案可能比原檔乾淨（QC 也這樣）。

## 3. 輸出與數值

### 3.1 等級的參數

| 本站等級 | 影像 | JPEG 品質 | 有效 DPI 上限 | 量不到大小時的長邊上限 | 另外試（每張取最小） | 來源 |
|---|---|---|---|---|---|---|
| 無損 | 不動 | — | — | — | — | QC 的 Lossless |
| 高畫質 | 重新壓縮 | 82 | 200 | 2340 px（200 × 11.7 英吋） | — | WP 的 low |
| 平衡（預設） | 重新壓縮 | 72 | 150 | 1755 px | 品質 78、長邊 2480 px（不看 DPI） | WP 的 recommended＋QC 的 Balanced |
| 最小 | 重新壓縮 | 55 | 120（自訂：取 WP 最強一級的 120） | 1700 px | 品質 72、150 DPI、長邊 1755 px（平衡的設定） | QC 的 Maximum（QC 也另外試 Balanced） |
| 整頁轉圖 | 每頁一張 JPEG | 60 | 起始 120，比原檔大時往下降（最低 50） | — | — | WP 的 maximum |

- 「另外試」的設定一定比等級本身輕（品質不低、解析度不低），所以結果不會比等級本身的品質差；只是有時候輕的設定反而比較小（QC 的觀察：壓過頭的影像重新取樣反而費位元）。
- 有效 DPI 只超過上限 10% 以內時不縮（自訂；重新取樣的損失比省下的多）。
- 縮小用面積平均（每個輸出像素是它涵蓋的來源範圍的加權平均；自訂，D2）。
- 進階設定（F09、F10）填了就只用那一組。
- 有效 DPI 的量法：每一頁（含表單 XObject、註解的外觀串流、/UserUnit）掃內容串流的 q／Q／cm 與 `Do`，影像的單位正方形畫成的寬、高（pt）÷ 72 ＝ 英吋；
  同一張畫在好幾個地方取最大；量不到的（圖案、Type3 字型裡的影像、內容超過 500 萬個記號）用長邊上限。

### 3.2 qpdf 的參數（qpdf 12.2.0；QC 用的 12.4.2 的參數都接受，單元測試實際跑過）

| 用途 | 參數 |
|---|---|
| 每次產生檔案 | `--no-warn --warning-exit-0` |
| 結構壓縮 | `--object-streams=generate --compression-level=9 --stream-data=compress --decode-level=generalized --recompress-flate` |
| 快速網頁檢視 | `--linearize` |
| 攤平（給 pdf-lib 讀） | `--object-streams=disable --stream-data=preserve` |
| 檢查 | `--check`（結束碼 0 或 3 才算過；qpdf 會解開 DCT 影像，壞掉的 JPEG 會被抓到）、`--show-npages`（頁數要和原檔相同） |
| 檢視 | `--json=latest --json-key=encrypt --json-key=pages`（加密、使用者／擁有者密碼對不對、頁數） |
| 密碼 | 密碼寫在 qpdf 的記憶體檔案系統，`--password-file=<暫存檔>`；要使用者密碼的檔案輸出時加 `--decrypt`；只有權限設定的不解密（qpdf 保留原本的加密） |

每次執行都開新的 qpdf 實例（QC：qpdf 的全域狀態、`--json` 不能用第二次）；暫存檔名不含使用者的資料，執行完刪掉。

### 3.3 影像：JPEG（QC 的規則）

重新壓縮的條件（全部符合）：`/Filter /DCTDecode` 或 `[/FlateDecode /DCTDecode]`；`/BitsPerComponent 8`；色彩空間 DeviceRGB、DeviceGray，
或 `/N` 是 3（`/Alternate` 沒有或是 DeviceRGB）、1（DeviceGray）的 ICCBased；JPEG 檔頭的成分數（3／1）與寬高和字典一致；
DCT 的 /DecodeParms 沒有 /ColorTransform；/Mask 不是顏色範圍的陣列；不是被別的影像當成 /SMask 或 /Mask 的影像；不是 /ImageMask。

換掉時：/Filter 換成 /DCTDecode、刪掉 /DecodeParms、/Width、/Height 照新的、/BitsPerComponent 8；色彩空間（含 ICC 描述檔）、/Decode、
/SMask、/Intent、/Interpolate 等都留著。軟遮罩（/SMask）不動（遮罩的解析度可以和影像不同，PDF 允許）。
JPEG 用 mozjpeg（漸進式、最佳化霍夫曼表、4:2:0），灰階存成單一成分。比原本小才換。

### 3.4 影像：Flate 轉 JPEG（本站，D5）

條件：/Filter 沒有或只有 /FlateDecode（預測器 PNG 10～15、TIFF 2 都可以，參數要和影像一致）；8 位元；RGB 或灰階（同 3.3）；
沒有 /SMask、/Mask；不是遮罩；至少 90,000 像素（約 300 × 300）；看起來像照片：取樣（最多 16,384 點）裡至少 256 種顏色，
而且（Flate 壓縮的）壓縮後至少是原始大小的 0.15 倍（圖表、截圖壓得很小）。轉成 JPEG 後要小到原本的 0.8 倍以下才換。數值都是自訂。

### 3.5 影像沒有動的原因（結果裡的文字）

| 原因 | 說明 |
|---|---|
| 壓縮方式不支援 | JPEG 2000、JBIG2、CCITT、LZW 等（QC 也不動） |
| 不是 8 位元 | |
| 色彩空間不支援 | CMYK（QC：Adobe 的 APP14 反相做錯會換色，不碰）、Indexed、ICC 4 色、Lab、Separation… |
| 有透明遮罩或是遮罩 | 顏色範圍遮罩、被當成遮罩的影像、ImageMask；Flate 影像有遮罩 |
| 特殊的顏色轉換 | DCT 的 ColorTransform |
| 太大 | 超過 5,000 萬像素 |
| 不是 JPEG | F11 關掉時的 Flate 影像 |
| 太小、看起來像圖表 | Flate 轉 JPEG 的條件不符 |
| 讀不出來 | 解不開、和字典不一致 |
| 沒有變小 | 重新壓縮的結果沒有比較小 |

### 3.6 檢查與比對

每個候選：至少 32 位元組、`%PDF-` 檔頭在最前面、最後 4 KB 有 `%%EOF`、`qpdf --check` 結束碼 0 或 3、`qpdf --show-npages` 和原檔相同（QC＋本站的頁數）。
比對（F23）：pdf.js 讀原檔與候選，每頁的文字（getTextContent 的字串接起來）、每頁的註解（種類、網址、目的地頁碼、欄位名稱）、書籤的標題（含子書籤，依序）、
表單欄位的名稱（排序）都要一樣。不比對的：中繼資料（qpdf 會保留）、標籤 PDF 的結構、JavaScript、字型的 ToUnicode 對照表本身（QC 另外測；本站內容串流與字型都不改）。

### 3.7 檔名

- 單檔：`<原檔名去掉 .pdf>_壓縮.pdf`（檔名清理照 `core/files` 的 `safeFileName`）；保留原檔時用原檔名。
- ZIP：`壓縮後的PDF.zip`；裡面的檔名同上，同名時 `_2`、`_3`…（`uniqueFileName`）；PDF 不再壓縮（level 0）。

### 3.8 整頁轉圖的輸出

新的 PDF（pdf-lib）：每頁一張 JPEG，頁面大小＝pdf.js 的頁面大小（裁切框、含旋轉，pt），圖片鋪滿；白底（JPEG 沒有透明）；
再經過一次結構壓縮。文字、連結、書籤、表單、中繼資料都沒有了。

## 4. 互動與手感

- 開頁：等級是上次用的（第一次是平衡）；清單是空的，拖放區寫「選擇或拖放 PDF（可以多個）」。
- 加入檔案：立刻出現在清單（縮圖讀取中），在另一個 Worker 裡讀頁數、加密與第一頁的縮圖；要密碼的檔案出現密碼欄。
- 開始壓縮：一次處理一個（記憶體），處理中的那一列：進度條＋階段：讀取檔案 → 整理結構 → 試快速網頁檢視 → 攤開物件 → 找重複的圖片與字型 →
  重新壓縮影像（第 i／n 張）→ 寫出檔案 → 檢查結果 → 比對文字與連結；整頁轉圖：畫成圖片（第 i／n 頁，降 DPI 重畫時接著算）。
  階段文字最多每 0.1 秒更新一次。完成時那一列換成結果，螢幕閱讀器念出「完成：檔名，X MB → Y MB」。
- 壓縮中可以繼續加檔案（排在後面，這一輪也會處理）、改設定（下一個檔案開始用新的設定）；不能移除處理中的檔案。
- 取消：立刻停（Worker 結束），通知「已取消」。
- 前後比對：Esc 關閉；← → 換頁（焦點不在輸入欄時）。
- 快捷鍵：Ctrl＋Enter 開始壓縮（`?` 看快捷鍵表）、Ctrl＋V 貼上。

## 5. 容易做壞的地方

- **qpdf 的輸出要攔 console**：這一份 Emscripten 建置在第一次執行時就把 console.log／console.error 綁住、不理會 `print`；
  要先換上攔截的 console，再 `import()` 膠水程式（靜態 import 會先執行）。每次執行都開新的實例；Node（單元測試）裡 qpdf 會寫 `process.exitCode`，要改回來。
- **wasm 只下載一次**：qpdf 每個實例都要重新載 wasm（不支援 `wasmBinary`），先讀成 blob: 網址；QC 用攔截 fetch 的做法曾經把 qpdf 的 wasm
  交給 mozjpeg（依副檔名比對），兩個失真的模式都靜靜地沒有作用——本站不攔 fetch。
- **pdf.js 會把交給它的位元組轉移走**：一律給複本；原檔留給「沒有變小時回傳原檔」與重試。
- **pdf-lib 存檔**：`updateFieldAppearances: false`（不然會重畫表單欄位的外觀）、`addDefaultPage: false`、讀檔 `updateMetadata: false`（不改 Producer、日期）。
  pdf-lib 寫出來之後一律再做 qpdf 的結構壓縮（物件串流、刪掉沒用到的物件）。
- **灰階 JPEG 要存成單一成分**：QC 把 DeviceGray 的 JPEG 重新壓成 3 個成分的 YCbCr、字典仍寫 DeviceGray（D7）。
- **遮罩不能壓成 JPEG**：被當成 /SMask 的灰階 Flate 影像看起來像「大張的灰階圖」，轉成 JPEG 會讓透明的邊緣出現雜訊；先找出所有被當成遮罩的影像再判斷。
- **顏色範圍遮罩（/Mask 陣列）**：重新壓縮會改到顏色，遮掉的範圍就不對了，不動。
- **JPEG 的檔頭要和字典一致**：寫著 RGB 其實是 CMYK 的 JPEG 解碼會換色；寬高不一致的也不動。
- **一張圖畫在好幾個地方**：取最大的顯示大小（最需要像素的地方），不能取第一個。
- **頁面的內容串流不合併**：一模一樣的內容在兩頁可能畫出不同的東西（資源在各自的頁面字典裡）。
- **只有權限設定的檔案不能轉成圖、不能解密輸出**：會拿掉原作者的權限設定（D4）。
- **大小的比較用位元組**：「減少 %」用原始 − 結果 ÷ 原始；結果和原檔一樣大時算「沒有變小」（不是成功）。
- **Worker 裡沒有 document**：pdf.js 的畫布、濾鏡、字型都要換成 Worker 能用的（WP 的經驗：只在有透明群組、軟遮罩、圖案的頁面才會出錯）。
  沒有內嵌的標準字型（Helvetica 等）要 pdf.js 的標準字型檔、舊的日文 PDF（90ms-RKSJ-H 等編碼）要 CMap，都打包在本站。
- **非內嵌的 CJK 字型在 Worker 裡畫不出來**：預覽與整頁轉圖用的 pdf.js 在 Worker 裡不能用電腦的字型；比對文字不受影響（兩邊一樣）。見 7.。
