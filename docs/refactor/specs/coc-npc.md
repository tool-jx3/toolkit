# CoC NPC 產生器（coc-npc）行為規格

## 0. 概要

一次管理多個克蘇魯的呼喚（CoC）NPC：7 版或 6 版、8 項屬性用骰子算式擲（7 版自動 ×5）、HP／MP／SAN／DB／體格自動算也可以手改、
技能與攻擊指令、備註；輸出可以直接貼進 CCFOLIA 的**角色剪貼簿 JSON** 與 BCDice 的**聊天面板**文字。
由舊版 trpg-lab 的「CoC NPC 製作／管理工具」（`tools/trpg-lab/coc_npc_token.*`，以下稱【舊版】）改寫；
共用的 `common.js` 提供深淺色與說明對話框。主控已裁定：**獨立成一個工具，不併進 character-editor**。

輸入：NPC 的各欄位、骰子算式。輸出：CCFOLIA 角色 JSON、聊天面板文字（剪貼簿）；NPC 清單存在瀏覽器；新版另有專案檔。
規則（骰子算式、DB／體格表、衍生值）在共用模組 `@/core/coc`（DESIGN.md 4.2），JSON 用 `@/ccfolia` 的 `serializeCharacterClipboard`。

靈感來源：ihoukentiku/ihoukentiku.github.io（<https://github.com/ihoukentiku/ihoukentiku.github.io>），授權 MIT（Copyright (c) 2025 ihoukentiku），
授權全文在 `web/src/tools/coc-npc/UPSTREAM_LICENSE`。

用語：「目前的 NPC」＝清單裡選中、正在編輯的那一個；「衍生值」＝HP、MP、SAN、DB、體格。

## 2. 輸入

- 屬性的算式：共用的骰子算式（coc-dice 規格 2.2）：「骰子數 D 面數」與整數用 + 或 - 連接，可以用全形；7 版不用寫 ×5。
- 數值欄：整數；超出範圍時離開欄位會夾回範圍內（新版）。MOV 是原生數字欄的值（可以空白）。
- 專案檔：本站的專案檔（3.5）；不是這個工具的資料時顯示「專案檔的內容無法使用。」，目前的內容不變。

## 3. 輸出

### 3.1 新的 NPC

名稱「新 NPC」、版本同目前的 NPC、8 項屬性算式空白、值 0、HP／MP／SAN 0、SAN 開、DB「0」、體格 0、MOV 空白、
技能一列（空白名稱、0）、指令一列（空白）、CC、備註空白。**衍生值不先算**（全部 0 的屬性照表其實是 DB −2，但新 NPC 顯示 0）。

### 3.2 DB／體格表（`@/core/coc`）

- 7 版（STR＋SIZ，×5 的值）：≤64：DB −2、體格 −2；≤84：−1、−1；≤124：0、0；≤164：+1D4、1；≤204：+1D6、2；≤284：+2D6、3；≤364：+3D6、4；
  ≤444：+4D6、5；≤524：+5D6、6；之後每 80 點 DB 多 1D6、體格多 1（525～604：+6D6、7）。
- 6 版（STR＋SIZ）：≤12：−1D6；≤16：−1D4；≤24：0；≤32：+1D4；≤40：+1D6；≤56：+2D6；≤72：+3D6；≤88：+4D6；≤104：+5D6；≤120：+6D6；
  ≤136：+7D6；≤152：+8D6；≤168：+9D6；≤184：+10D6；之後每 16 點多 1D6（185～200：+11D6）。

### 3.3 CCFOLIA 角色剪貼簿 JSON

`{ "kind": "character", "data": { … } }`，2 格縮排、LF、結尾沒有換行、中文不跳脫；`data` 的欄位依序：

| 欄位 | 內容 |
|---|---|
| `name` | 名稱；空白時「無名氏」 |
| `initiative` | DEX 的值（數字） |
| `externalUrl` | 參照網址（新 NPC 是空字串） |
| `status` | `[{ label: "HP", value, max }, { label: "MP", … }, { label: "SAN", … }]`，value＝max＝目前的值；SAN 關掉時沒有 SAN |
| `params` | STR、CON、POW、DEX、APP、SIZ、INT、EDU 各 `{ label, value: "<值>" }`（值是字串），接 `{ label: "DB", value }`（空白時 "0"）；7 版再接 `{ label: "體格", value: "<體格>" }`；MOV 有填而且讀得出整數時再接 `{ label: "MOV"（6 版「移動力」）, value: "<整數>" }` |
| `commands` | 聊天面板全文（3.4） |
| `memo` | 備註 |

在 CCFOLIA 的房間畫面按 Ctrl＋V 貼上就會新增這個角色（缺的欄位由 CCFOLIA 補預設值）。

### 3.4 聊天面板

每行一個，LF 連接，依序：

1. SAN 開時：`<檢定><=<SAN> 理智檢定`（例：`CC<=50 理智檢定`）。
2. 8 項屬性：`<檢定><=<值> STR`…；6 版的值 ×5（`CCB<=65 STR`）。
3. 名稱不是空的技能：`<檢定><=<成功率> <名稱>`。
4. 算式不是空的指令：算式的 DB 換成 `{DB}`；有名稱時 `<算式> <名稱>`，沒有名稱時只有算式。
5. `//HP=<HP>`、`//MP=<MP>`；SAN 開時 `//SAN=<SAN>`；`//DB=<DB>`；7 版 `//體格=<體格>`；MOV 不是空白時 `//MOV=<MOV>`（6 版 `//移動力=`）。
6. `//STR=<值>`…`//EDU=<值>`（6 版是原始值，不 ×5）。

`<檢定>`：7 版 CC；6 版依 F19（CC 或 CCB）。

### 3.5 存檔、專案檔與對等驗證

- 自動存檔：localStorage `trpg-toolkit:coc-npc`（NPC 清單 `{ npcs: [...] }`，每個 NPC 的欄位：`id`、`edition`（7／6）、`name`、`externalUrl`、
  `abilities`（各項 `{ dice, value }`）、`hp`、`mp`、`san`、`sanEnabled`、`db`、`build`、`mov`（字串）、`skills`（`{ id, name, value }`）、
  `commands`（`{ id, name, expr }`）、`commandType`、`memo`）；`trpg-toolkit:coc-npc:preview`（`{ currentId, output }`）。讀回時整理（壞掉的欄位用預設值）。
- 舊版：`iklab_coc_npc_token_v1`＝`{ npcs: [{ id, version: '7'|'6', name, externalUrl, abilities, hp, mp, san, sanEnabled, db, build, mov, skills: [{ name, value }], commands: [{ name, expr }], commandType, memo }], currentId }`。
- 專案檔：`{ format: 'trpg-toolkit-project', tool: 'coc-npc', version: 1, savedAt, data: { npcs, currentId } }`，檔名「CoC NPC_日期.json」。
- 亂數：一顆 N 面骰＝⌊亂數 × N⌋＋1；全部擲骰依 STR→EDU、每項的算式依序取用（與舊版相同）。頁面上設 `window.__cocRandom` 時新版用它；
  對等驗證時舊版換掉 `Math.random`（注意舊版新增 NPC 時產生 id 也會取用 `Math.random`，要在填好欄位、按擲骰前才換）。
  實作者已用四組設定（7 版、6 版、6 版 CCB 且 SAN 關、7 版 SAN 關）與 `fixtures/coc-npc-legacy.json` 的三組比對，JSON 與聊天面板逐字相同（指令都沒有名稱）。

## 4. 互動與手感

- 所有輸出即時更新（舊版存檔延遲 0.4 秒；新版改了就存）。
- 數值欄：↑／↓ 加減 1（Shift ×10）；離開欄位時夾回範圍。
- 快捷鍵：R 全部擲骰、Ctrl／⌘＋Z 復原、Ctrl／⌘＋Shift＋Z 或 Ctrl＋Y 重做、? 說明。
- 複製的通知約 2 秒。

## 5. 容易做壞的地方

- **7 版是整個算式 ×5**（`2D6+6` → (2D6+6)×5），最少 0；6 版不乘。聊天面板的 6 版檢定值才 ×5，`//STR=` 寫原始值。
- **全部擲骰一定重算衍生值**，即使沒有任何算式（新 NPC 按全部擲骰後 DB 變成 −2、體格 −2）；新 NPC 本身不先算。
- **切換版本不換算屬性**，只重算衍生值；6 版切回 7 版時體格依表重算，7 版切到 6 版時體格保留（不輸出）。
- **手改的衍生值**在下一次改屬性、擲骰、切換版本時被蓋掉（舊版如此）。
- **名稱空白的技能、算式空白的指令不輸出**；名稱只有空白字元時算有名稱（舊版如此）。
- **DB 的值本身帶正負號**（`+1D4`、`-2`），指令寫 `1D6+DB` 時 CCFOLIA 會代入成 `1D6++1D4`；這是舊版的提示寫法，照舊。
- **MOV**：JSON 只在讀得出整數時輸出（`8.5` → `8`），聊天面板寫欄位的原值。
- **JSON 欄位順序固定**（name、initiative、externalUrl、status、params、commands、memo），status、params 項目的鍵順序也固定。

### 舊版的問題與新版的做法（需主控裁定）

| # | 舊版 | 建議（新版目前的做法） |
