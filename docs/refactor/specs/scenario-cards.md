# 劇本資訊卡片產生器（scenario-cards）行為規格

## 0. 概要

KP／GM 帶團前整理劇本用的工具：左邊放劇本全文（直接貼上或讀入 TXT 檔，可搜尋），選取一段文字就能做成一張「資訊卡片」；
右邊是卡片清單，每張卡片有類型（場景、探索地點、資料、NPC、技能成功、備忘、道具、規則、HO1～HO4）、標題與內文，
可以一鍵複製成貼進 CCFOLIA 聊天欄用的固定格式文字，或複製成結構化的 JSON。卡片可篩選、排序、複製、刪除；
專案可以用名稱存在瀏覽器裡、匯出／讀入專案檔，所有內容自動存檔。全部在瀏覽器內完成，不連任何伺服器。

輸入是劇本文字（TXT 檔或直接貼上）、卡片的編輯；輸出是剪貼簿裡的文字或 JSON，以及專案檔。

靈感來源：くま。的「TRPG WEBツール観測所」（<https://kumachansteps.github.io/trpg-web-tools/>）

附件：[`scenario-cards.examples.json`](scenario-cards.examples.json)——「輸入→舊版輸出」範例：匯入整理 8 組（I01～I08）、
選取建立卡片 11 組（S01～S11）、複製文字 18 組（C01～C18）、CCFOLIA 資料 18 組（D01～D18）＋整組 1 組（K01）、搜尋 8 組（Q01～Q08）。
輸入全部是觀察者自編的繁中劇本片段；欄位名稱是規格自訂的。**文字類輸出的對等驗證以附件逐字相符為準**；本文只節錄規則。

用語：「內文區」＝左邊放劇本全文的文字區；「卡片」＝右邊清單的一筆；卡片的「第二標題」＝只有技能成功類型會出現的第二個標題欄（技能成功後揭露的小標）。

## 2. 輸入

- **TXT 檔**：以 UTF-8 解讀（開頭有 BOM 的 UTF-16 也會被正確解讀；Big5 等其他編碼變亂碼）。不檢查大小與副檔名。
- **直接貼上**：內文區接受任何文字。
- **專案檔**：JSON（F36）。
- 卡片的標題、第二標題、內文、專案名稱：任何文字（含引號、角括號、表情符號），輸出時原樣保留（不做 HTML 跳脫；JSON 照標準跳脫）。

### 3.1 匯入整理（F02、F03；附件 I01～I08）

依序：

1. 換行統一：CRLF 與單獨的 CR 都換成 LF。
2. 連續 3 個以上的換行縮成 2 個（也就是最多留一個空行）。只有「完全沒有字元」的行算空行；含空白或 Tab 的行不算，不會被合併（I03）。
3. 去掉整段頭尾的空白字元（含半形空白、全形空白、Tab、換行、BOM）（I01、I04、I05）。

專案名稱（只在專案名稱欄空白時）：檔名去掉最後一個「.」之後的部分，再去頭尾空白（I07：`第二章.v2.final.txt` → `第二章.v2.final`）。

### 3.2 選取 → 卡片（F12、F13；附件 S01～S11）

1. 取內文區的選取範圍（以瀏覽器文字區的選取位置計）。起訖相同 → 提示「請先選取」，不建卡（S09）。
2. 選取的文字去頭尾空白；結果是空字串 → 提示「選取是空的」，不建卡（S08）。
3. 換行統一成 LF 後分行；第一個「去掉空白後不是空的」行，去頭尾空白（含全形空白）後成為**標題**，最多取前 80 個 UTF-16 碼元（S06）。
   舊版的截斷可能把擴充 B 區漢字或表情符號切成半個字（S07 的標題結尾是孤立的代理碼元），見 5.。
4. 標題行之後的所有行以 LF 接起來，整段去頭尾空白後成為**內文**：中間的空行與各行縮排保留，但第一行的縮排與最後一行的行尾空白會因整段去頭尾而消失（S05、S11）。只有一行時內文為空（S04）。
5. 類型為技能成功時：上述標題改放進**第二標題**，標題欄留空（S03）。其他類型第二標題為空。
6. 新卡片加在清單最後，行為同 F14（捲動、亮起、游標到標題欄）。

### 3.3 複製文字（F22；附件 C01～C18）

## 5. 容易做壞的地方

- **「空行」的定義**：只有完全沒有字元的行才會被合併；含空白的行保留（I03）。
- **去頭尾空白包含全形空白、Tab 與 BOM**（I04、I05、S11、C12）。
- **標題空白時用類型名稱**，而且是「類型名稱」不是「頁首標示」（場景 → 「場景」，不是「場景描寫」；HO3 → 「△HO3 秘匿：HO3」）。
- **資料與 NPC 資訊的記號後面有半形空白**，其他類型沒有。
- **內文為空時複製文字仍以兩個 LF 結尾**。
- **第二標題**只在技能成功時輸出；換類型時保留不刪；CCFOLIA 資料裡沒有第二標題（舊版遺漏）。新版若把第二標題加進 CCFOLIA 資料，屬刻意改善，需主控確認。
- **標題截斷 80 個 UTF-16 碼元**會切斷擴充 B 區漢字與表情符號（S07）。新版改成以字（碼位）為單位截斷，屬刻意改善，需主控確認（附件 S07 以新結果為準）。
- **搜尋的第一次 Enter**：舊版打完關鍵字直接按 Enter 會跳到第 2 個（Q07）。新版改成第一次 Enter 選第 1 個，屬刻意改善，需主控確認。
- **C 鍵**：有選取時連 Shift＋C 也會建卡；沒有選取時必須正常打字。在標題欄、搜尋欄打 C 不能觸發。
- **類型快捷鍵在文字欄裡也會觸發**（Alt＋數字）。Mac 上 Option＋數字會產生特殊字元、⌘＋數字是瀏覽器切換分頁，舊版用「按下的字元」判斷，所以在 Mac 上可能無效。
  新版建議以實體按鍵位置判斷並統一用 Alt／Option，屬刻意改善，需主控確認。
- **選取用類型的預設**：舊版程式看起來想預設「備忘」，實際上是「場景」。新版照實際行為（場景），或改成備忘，需主控確認。
- **篩選中新增的卡片可能看不到**（類型不符時）。新版若新增時自動切回「全部」或提示，屬刻意改善，需主控確認。
- **建立副本加在清單最後**，不是緊接在原卡片後面。
- **已存清單選了就讀取、不確認**，會蓋掉目前沒存的編輯；**刪除卡片、清除內文不確認也不能復原**。新版若加確認或復原，屬刻意改善，需主控確認。
- **讀入任何 JSON 都會套用**：舊版讀入不相干的 JSON（例如 `[]`）會清空內文與卡片並顯示成功。新版應檢查是否為本工具的專案檔，屬刻意改善。
- **已存專案的排序**：舊版用日文排序規則；新版用繁中排序規則屬可接受差異。
- **舊版沒有「刪除已存專案」的功能**（只能覆蓋）。新版若增加，屬可接受的新增功能，需主控確認。
- **剪貼簿失敗**：舊版剪貼簿 API 失敗時改用舊式複製，但不論成功與否都顯示「已複製」。新版失敗時應顯示錯誤，屬刻意改善。
- **編碼**：只支援 UTF-8（與有 BOM 的 UTF-16）；台灣常見的 Big5 TXT 會變亂碼。新版若自動偵測 Big5，屬刻意改善，需主控確認。
- **來源提示列看不到**（F05）、**外部工具轉送實際上不會發生**（F06）。
- **CCFOLIA 資料沒有讀取端**（3.4）：保留（換成新版自訂欄位）、拿掉、或改成實際可用的輸出（例如每張卡片的複製文字合併成一份），由主控決定。
- **記號與固定文字**（十二個記號，以及 3.0 表中的括號、前綴與後綴）是複製到 CCFOLIA 聊天欄的文字的一部分。
  這些是很短的功能性格式，舊使用者可能已經習慣；逐字沿用或新版自訂，由主控決定（若自訂，附件的「複製文字」「CCFOLIA 資料」改比結構）。
- **窄螢幕**：舊版在手機寬度會橫向捲動（F44）。
