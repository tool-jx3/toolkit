# 家系圖產生器（family-tree）行為規格

## 0. 概要

在畫布上一張一張接出人物卡片，做成「一代一列」的家系圖：從始祖往下加兒子、女兒、配偶，加兄弟姊妹、上一代；
同一代的人固定在同一列、左邊標「第 N 代」；子孫多了旁邊的分支會自動讓開、不重疊。卡片可以雙擊就地改字、拖曳換順序或改父母；
父親的位置有置中、手動、對齊長子三種；可以折疊子孫、用顏色分類、搜尋名字；最後匯出 PNG 或 SVG（縱向或橫向、整張、某人以下或框選的範圍）。
第二批加上過繼（出系／入系：繼父底下「入」、生家的「出」字小卡）、母系外孫的開關、跨家系的婚姻連結、女兒寫成「女（適 丈夫）」，
以及本站的狀態（存活／死亡／失蹤）、GM 專用的人與欄位（PL 檢視、PL 用的匯出）、頭像、SVG 匯出。
跑團用：CoC 與推理劇本的舊家、繼承糾紛、血緣之謎的 handout 與 KP 自己整理人物關係。全部在瀏覽器內處理，不上傳。

輸入：人物（名字、讀音、別名、生歿年、備註、性別、色分類、狀態、GM 筆記、頭像）與親屬關係（父母、過繼、跨家系的婚姻）；可以有好幾張圖板（每個家族一張）。
輸出：PNG、SVG（PL 用或 GM 用）；專案檔（全部圖板或一張圖板；有頭像時是 ZIP）；另外讀得到原作的備份檔（JSON）。

靈感來源：가계도 편집기（<https://gagyedo.j-segrc.workers.dev>；對照的是使用者上傳的網頁存檔 `index.html`，單檔 1,645 行，純 DOM＋SVG；
字型檔、圖示檔不在存檔裡，不影響功能）。原作**沒有作者、版權、授權的字樣（未授權）**：只參考功能、數值與做法（排版的規則與數值照做）；
程式、介面文字（原作是韓文）、配色、圖示、範例、說明都自己做（繁中），不放 `UPSTREAM_LICENSE`。
**原作內建的範例是真實的歷史家族，不沿用**：本站的範例是自己編的虛構家族（昭和年代舊家的四代）。

**分兩批**（使用者 2026-10-23）：第一批＝樹的核心（F01～F72，已上線）；**第二批**（2026-10-23 實作，1.12 的 F80～F88）：
出系／入系、母系外孫的顯示、跨家系的婚姻連結、框選範圍匯出、女兒的寫法，以及本站的加強：狀態、GM 專用的人與欄位與 PL 版、頭像、SVG 匯出。
第一批先留好的資料欄位（3.6、D6）在第二批照原作排版、畫出來；資料版本由 1 改成 2（新欄位都是選填，版本 1 的資料照讀）。

用語：「原作」＝上述網頁；「成員」＝家系裡的人（原作的 member，有自己的卡片、在世代列上）；「配偶」＝嫁娶進來的人（原作的 spouse，
不另佔一列，以小卡片接在成員卡片的右邊）；「血緣上的父母」＝成員的父親（是成員時）或母親（父親不是成員、母親是成員時）——決定這個人掛在誰底下；
「始祖」＝沒有血緣上的父母的成員（每個家系的頂端，一張圖板可以有好幾個）；「子樹」＝一個成員與他所有（沒有折疊的）子孫；
新版「匯出」分頁有兩組，標題不重複：上面是「範圍與內容」（檔名、範圍、方向、卡片內容、要畫的項目），下面是共用匯出區「匯出圖片」（格式、尺寸、匯出）。

W、H、SPW、GAP、HG、VG＝卡片寬、卡片高、配偶卡片寬、配偶卡片與卡片的間距、同一列相鄰子樹的最小間距、上下兩列卡片之間的距離（數值見 3.1）。

## 1. 功能清單（對等驗證以此為準）

原作是全畫面的畫布：上方一列工具列（圖板選單、搜尋、「檢視」彈出選單、拖曳方式、＋始祖、自動整列、「匯出圖片」彈出選單、說明、更多選單、儲存狀態），
點了卡片右邊滑出人物面板（手機寬度時是底部抽屜）。
新版用共用外框（D8）：設定欄是四個分頁「人物」「顯示」「匯出」「圖板」；預覽欄是畫布的工具列（圖板的下拉、搜尋、GM／PL 檢視〔第二批〕、拖曳方式、＋始祖、自動整列）與畫布；
頁首有復原、重做與共用的專案選單。

## 2. 輸入

- **專案檔**：共用格式（JSON：`{ format: 'trpg-toolkit-project', tool: 'family-tree', version: 2, data }`；有頭像時是 ZIP：`project.json`＋`files/<資產 id>.<副檔名>`；3.5）。
  版本 1（第一批）的專案檔照讀。別的工具的專案檔、壞掉的 JSON 或 ZIP 由共用的專案選單報錯；ZIP 裡的圖片放回這個瀏覽器（存不進去時提醒：這次可以用，重新整理之後就沒了）。
- **原作的備份檔**（JSON）：`format` 是 `family-tree/v1`（一張圖板：`title`、`meta`、`people`）或 `family-tree-all/v1`（`boards` 陣列，每項 `title`、`createdAt`、`meta`、`people`）。
  讀進來的每張圖板**加成新的圖板**（名稱＝`title`，沒有時 `meta.title`，再沒有時「讀進來的家系圖」），切到第一張；通知「已讀進 N 張圖板」。
  欄位的對應見 3.5；認不得的欄位不理會；`people` 不是物件、JSON 壞掉時通知「這不是家系圖的專案檔或原作的備份檔」，不改目前的資料。
- **文字欄**：名字、讀音、出身最多 40 字；別名、父母最多 200 字；生年、歿年最多 20 字（任意文字，例如「1921」「大正 10 年」「不詳」）；備註、GM 筆記最多 2,000 字；圖板名稱最多 60 字。
  超過的部分不收（就地編輯與面板的欄位都一樣）。原作沒有上限（D19）。

- **人數**：每張圖板最多 2,000 人（成員＋配偶；超過時「加人」的按鈕停用並提示）；圖板最多 50 張。原作沒有上限（D19）。

每個孩子相對於父母的位移＝ s − p；這個子樹的輪廓＝這個人那一列（左 0、右區塊寬）＋ 孩子們每一列的左緣、右緣各減 p。

沒有共同世代時 s ＝ 目前最右的右緣 − 這個家系最小的左緣 ＋ 3 × HG ＋ g。卡片的 x ＝ 父母的 x ＋ 位移，y ＝（代數 − 最小的起始代數）×（H ＋ VG）。

**其他位置**：配偶卡片 i（從 0）在 x ＋ W ＋ GAP ＋ i ×（SPW ＋ GAP）；親子連線（含生父到「出」字小卡）從（父母 x ＋ W ÷ 2，父母 y ＋ H）往下到 y ＋ H ＋ VG ÷ 2、橫到（孩子 x ＋ W ÷ 2）、再往下到孩子 y；
世代標籤在 x ＝ min(0, 最左的卡片 x) − 84、中心高度 y ＋ H ÷ 2；世代間的虛線在 y ＋ H ＋ VG ÷ 2，從標籤的 x 起、長度＝最右的區塊右緣 − 那個 min ＋ 120。
沒有小數的座標保持整數；有 .5 的照樣保留（原作也是）。卡片的畫的先後：每個人之後是他的孩子們（含小卡），依排好的順序。

**婚姻連線**（F82）：依人物加入的順序，每張連到成員的配偶卡片 → 連到的成員的卡片；同一對成員只畫第一條。配偶卡片的位置：顯示的配偶卡片；
女兒的寫法打開、她的配偶卡片不畫時用她的卡片（寬 W）。起點 ax ＝ 配偶卡片 x ＋ 寬 ÷ 2、終點 bx ＝ 成員卡片 x ＋ W ÷ 2：
兩張同一列（y 差 < 1）時 `M ax y C ax (y − up) bx (y − up) bx y`，up ＝ min(70, VG × 0.8)；不同列時從上面那張的底邊中央到下面那張的頂端中央，
`M 上 C 上x (上y＋k) 下x (下y−k) 下`，k ＝ 兩者高度差 ÷ 2。任一邊不在排版裡（折疊、不顯示）或不顯示配偶時不畫。

**對等驗證**：同一份人物資料（原作的備份檔），每張卡片的 (x, y)、配偶卡片的 x、世代、連線，都要和原作 DOM 上的座標**完全相同**（3.7）。
卡片寬高固定，所以字型不同不影響座標；只影響卡片裡的文字什麼時候縮小、省略。

### 3.4 檔名

- PNG：`<檔名欄>.png`；檔名欄空白時用圖板名稱，再空白時「家系圖」；清理用共用的 `safeFileName`（`\ / : * ? " < > |` 與控制字元換成「_」；原作是拿掉）、結尾的 `.png` 不重複。
- SVG：`<檔名欄>.svg`（同 PNG 的規則；檔名欄結尾的 `.png`／`.svg` 都拿掉再加）。
- 專案檔：所有圖板 `家系圖 YYYY-MM-DD.json`；只存這張圖板 `<圖板名稱> YYYY-MM-DD.json`（原作的備份檔同樣的日期寫法）；有頭像時副檔名是 `.zip`。

### 3.5 專案檔與資料格式（新版）

`data`（資料版本 2；第二批加的欄位都是選填，版本 1 的資料照讀）：

```
{ boards: Board[] }
Board = { id, title, createdAt（ISO 時間）, align: 'center' | 'manual' | 'eldest', cats: { id, name, color }[], people: { [id]: Person } }
Person（成員）= { id, kind: 'member', name, reading?, alias?, birth?, death?, note?, gender: 'M' | 'F', cat?,
                 fatherId?, motherId?, gen?（只有始祖）, order, gap?（左側間距）, shift?（手動偏移）, …第二批的欄位 }
Person（配偶）= { id, kind: 'spouse', spouseOf, name, reading?, birth?, death?, origin?（出身）, parents?（父母）, note?, cat?, order, …第二批的欄位 }
```

- `people` 是以 id 為鍵的物件，**保留加入的順序**（排序值相同時以這個順序為準，同原作）。
- 第二批的欄位（第一批先留好、讀檔存檔時保留；第二批顯示與編輯）：
  成員 `adopt?: { fatherId（繼父；null＝只選了類別）, kind: 'heir'（出系）| 'adopted'（入養）, order?（「出」字小卡的排序值）, gap?（小卡的左側間距） }`；
  配偶 `link?: { personId（連到的成員）, pairId?（對方那邊成對的配偶）, auto?（連結時自動建立的） }`；
  兩者 `status?: 'alive' | 'dead' | 'missing'`（沒有＝存活）、`secret?`（GM 筆記）、`gm?: true`（只有 GM 看得到）、
  `gmFields?: ('reading' | 'alias' | 'birth' | 'death' | 'status' | 'note' | 'cat' | 'avatar' | 'adopt'〔成員〕| 'origin' | 'parents'〔配偶〕)[]`（PL 看不到的欄位，依固定順序、不重複）、
  `avatar?`（頭像的資產 id）、`avatarPos?: { zoom（1～4）, x, y（−2～2）, turns（0～3） }`（頭像在圓裡的位置；沒有＝置中蓋滿）。
- 讀檔時整理：文字截到上限、性別不認得時當男性、`order` 不是數字時依出現順序、指到不存在的人的 `fatherId`／`motherId`／`spouseOf` 清掉（沒有 `spouseOf` 的配偶丟掉）、
  `align` 不認得時置中、色分類的顏色不是色碼時用預設色、id 重複的圖板換新的 id；第二批：繼父不存在或是自己時過繼取消、連到的不是成員時連結拿掉、
  `pairId` 指到不存在的人時拿掉、狀態不認得的丟掉、`gm` 不是 true 時丟掉、`gmFields` 只留認得的（這種人物有的）、頭像的位置夾在範圍內。
- **讀原作的備份檔**的欄位對應：`name` → 名字、`hanja` → 讀音、`alias` → 別名、`birth`／`death` → 生年／歿年、`note` → 備註、`gender`、`cat`、`order`、`gen`、
  `fatherId`、`motherId`、`gx` → 左側間距、`nx` → 手動偏移；配偶的 `spouseOf`、`clan` → 出身、`parentNote` → 父母；
  `adoptFatherId`＋`adoptType`（`출계` → heir、`입양` → adopted；只有 `adoptType` 時繼父是 null）＋`stubOrder`＋`sgx` → `adopt`；`linkId`＋`pairId`＋`auto` → `link`；

## 4. 互動與手感

- 雙擊的判定：同一張卡片兩次放開（沒有拖動）間隔 < 450 ms。
- 拖曳的門檻：橫＋縱 ≥ 5 px；拖曳中每個畫面最多重排一次；放開時才記一步復原（整次拖曳一步）。
- 畫面邊緣 36 px 內自動捲動 10 px（每次指標移動）。
- 縮放：滾輪 × 1.1、按鈕 × 1.2、12%～250%；全覽最大 115%；過場 0.25 秒（`prefers-reduced-motion` 時沒有）。
- 就地編輯：輸入欄的寬度約等於內容（至少 3 字）、生歿年 5.5 字寬；打開時全選。
- 人物面板的文字欄：打字中合成一步復原（離開欄位時記下）。
- 通知：用共用的通知（預設停留 4 秒、錯誤 7 秒，附「復原」的也一樣；原作附「復原」的 6 秒、一般 2.6 秒，新版不照做）。
- 快捷鍵：Ctrl＋Z 復原、Ctrl＋Shift＋Z／Ctrl＋Y 重做、Esc（拖曳中＝取消拖曳；就地編輯中＝取消編輯；其他＝取消選取）、
  卡片上 Enter 選取、F2 就地編輯；拖曳中 Alt＝換父母、Shift（手動模式）＝連同子孫；搜尋欄 Enter＝下一個。
  第二批：P＝GM／PL 檢視；「出」字小卡上 Enter＝移到本人；框選範圍中 Esc＝離開。
- 預設值：父親的位置「置中」；卡片「詳細」；備註關；配偶開；顏色開；拖曳方式「換順序」；匯出：全部、縱向、照顯示設定、標題／世代／配偶都開、2×。
  第二批：母系外孫開（D26）、生家也顯示出系的人開、婚姻連線開、女兒的寫法關、頭像開、GM 檢視；匯出的對象「PL 用」、格式 PNG。

## 5. 容易做壞的地方

- **排版要完全照原作的步驟**（3.1）：好幾個孩子中的第一個的間距是「前導」（推孩子、不推父母），唯一的孩子的間距擴大左邊的輪廓（整家往右）；
  「已排好的左緣」對第一個孩子以外的孩子要扣掉 g（間距的空白也算在輪廓裡）；家系之間是 3 × HG；始祖的世代以起始代數對齊。
  .5 的座標不要四捨五入（原作的 DOM 座標也是 .5）。
- **長子**＝排序最前的「非女性」孩子（出系小卡不算；第二批）；沒有男性孩子時第一個孩子；只有一個孩子時不適用（同置中）。
- **排序值相同時依加入的先後**：`people` 要保留順序；Immer 與 JSON 都會保留字串鍵的插入順序（id 不能是純數字，否則 JavaScript 會把它排到最前面）。
- **拖曳時以拖曳開始時的資料為準**：每一格都從原本的資料重新算（換順序的落點、間距的累加、手動偏移的抵消），不是在上一格的結果上再加。
- **換順序的落點**：以這個人的卡片左邊＝指標位置 − 按下時指標在卡片裡的位置，比較「卡片中心」和每個兄弟姊妹的卡片中心（排版裡看得到的）；看不到的（折疊、不顯示）排在最後。
- **手動模式拖父母**：偏移改了以後孩子會跟著動（因為置中的計算），要用左側間距抵消回來（最多 6 次、差 < 2 px 停）。
- **換父母到女性成員**：父親設成她的丈夫（放在丈夫卡片上時是那位丈夫），所以孩子仍以母親掛在她底下（父親不是成員）。
- **刪除**：配偶一起刪；所有人的父親、母親（以及第二批的過繼、連結）指到不存在的人的都要清掉。
- **復原紀錄每張圖板分開**：換圖板時清空，否則復原會改到看不到的圖板。
- **折疊的子孫不進排版**：搜尋、換父母、加孩子時要把目標的祖先或目標本身展開。
- **匯出的「選取的人以下」**：子孫用「所有孩子」算（第二批的母系外孫不顯示時也算），但只畫目前排版裡有的卡片（折疊的不畫）。
- **匯出橫向**：先用換過的尺寸排版再對調 x、y，不是把縱向的結果轉 90°（兄弟姊妹方向的間距不同）。
- **「出」字小卡的排序**（第二批）：孩子先依排序值排好，小卡**依加入的先後**（不是排序值）接在後面，再一起做**穩定**排序；小卡的排序值沒有時用本人的。
  小卡的寬是 W（不加配偶卡片）；只有生父是成員時才畫；對齊長子不看小卡；換順序時小卡和孩子一起重新編號，看不到的孩子排在最後（原作同）。
- **過繼的「入」與說明行看的是「有沒有繼父」**（不管繼父是不是成員；原作同），掛在誰底下看的是「繼父是不是成員」。
- **婚姻連線的配偶卡片位置**：女兒的寫法讓她的配偶卡片不畫時，連線接在她的卡片上（寬 W）；同一對成員只畫一條；配偶卡片的 x 是排版的位置（簡易卡片時原作 DOM 的位置會差 1 px，3.7）。
- **連結的配偶顯示連到的成員的資料**：名字、讀音、生歿年、狀態、頭像都用那位成員的，就地編輯與面板改的也是他；出身、父母、備註、GM 專用是配偶自己的。
- **PL 版是複本**（3.8）：PL 檢視與 PL 用的匯出不能改到原本的資料；PL 檢視時不能編輯（D29）。拿掉一個人時，他的子孫、配偶、連到他的婚姻都要一起拿掉，不然名字會從別的卡片洩漏。
- **頭像那一欄只在有人放頭像時出現**：沒有頭像的圖板排版不變（第一批的期待值照過）；匯出的「只有名字」「名字＋讀音」不加。
