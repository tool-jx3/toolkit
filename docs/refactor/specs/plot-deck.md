# 劇本骨架抽卡（plot-deck）行為規格

## 0. 概要

抽卡組出 TRPG 劇本的**骨架**（不限規則系統）：先選題材（做什麼的故事）與氣氛（什麼樣的空氣），再抽「體驗的核心」（玩完想留給 PL 的感受）、
導入、障礙、真相、結局、舞台、氣氛卡（依氣氛換名字：怪奇・恐怖＝怪異…）、線索、NPC，以及每位 PC 的關係與秘密的卡。
卡會偏向和題材、氣氛、體驗的核心、先抽到的真相合得來的。抽好之後回答卡上的問題把骨架填滿，決定 PL 要查明的事（推理）並在場景裡放線索，
檢查每個推理至少有 3 條線索，最後排成一份劇本文件（列印／PDF、HTML、文字；另有劇本排版台可以貼上的格式）。
做好的劇本自動存在這個瀏覽器的「劇本清單」；「卡片一覽」列出收錄的全部卡，也可以挑幾張卡開始。

輸入：點選、文字欄、本站的專案檔。輸出：畫面、列印、HTML、文字檔、markdown（劇本排版台用）、專案檔。

靈感來源：Xelltis エノキ「Kadan」現代・奇幻 體驗版（<https://www.xelltis.com/>；BOOTH 販售的製品版的體驗版，使用者 2026-11-15 上傳兩個體驗版的 zip，
存在 `/home/user/upstream/Xelltis_Kadan-trial-modern/`、`…-fantasy/`）。授權：**All rights reserved**，作者條款禁止再散布、散布改作版或一部分、
整批轉載收錄卡文、用收錄卡文做同目的的製品、取出效果音。本站照 CLAUDE.md 規則 1 的「未授權、作者條款限制」：**只參考功能、互動流程、演算法與數值**，
程式照本站的結構重寫；**卡與介面文字全部本站自己寫（繁中）**，沒有翻譯或改寫原作的任何一張卡（D2、D3）。不放 UPSTREAM_LICENSE。頁尾只放靈感來源。
使用者 2026-11-15 決定：做成新工具、現代＋奇幻兩套卡；「複製給 AI 的提示詞」不做（F90）。

### 3.2 卡的權重（偏好）

「題材合」＝卡的題材有選的題材；「全部」＝沒標或標 `*`；「還沒決定」＝還沒選題材（或氣氛）。

1. 題材與氣氛：
   - PC 的卡：1。
   - 體驗的核心：氣氛不同 0（抽不到）；題材合 6，其他 1。
   - 氣氛卡：氣氛不同 0；題材合 3，其他 1。
   - 其他：題材與氣氛都不合 0.05；否則（題材的倍率）×（氣氛的倍率），合 6、全部 2、還沒決定或不合 1。例：都合 36、題材合＋氣氛全部 12。
2. 體驗的核心以外再乘（權重已經是 0 的不乘）：
   - 合體驗的核心的真相、結局 ×18；
   - 舞台已經抽到、卡有適合的場所而舞台的種類都不合 ×0.06；
   - 真相：和每張鎖定的卡合不來 → 0、合得來 → ×2（每張相乘）；
   - 其他：和目前的真相合不來 → 0、合得來 → ×4。
3. 抽一張：同一種卡在別的欄用掉的不抽（PC 的關係、秘密每人一張不重複）；重抽時也不抽現在這張；依權重抽（權重 0 的不抽）；
   全部是 0 時從還沒用掉的平均抽；一張都沒有時不動。
4. 全部抽：沒鎖定的故事的卡先清空，依序抽體驗的核心、真相、舞台，再抽導入、障礙、結局、氣氛卡、線索、NPC。
5. 真相換了（重抽、從清單挑）：沒鎖定的其他卡裡權重變 0 的重抽。
6. 體驗的核心換了（抽好之後）：沒鎖定、不合新核心的真相與結局 → 問「真相與結局也要重抽嗎？」（重抽／維持原樣）；重抽真相時連動 5。
7. 換題材與氣氛（抽好之後）：氣氛變了，核心與氣氛卡一定換（鎖定的也解除後換）；其他沒鎖定的故事的卡，新題材與氣氛的權重（第 1 項）不到 0.1 的也換；
   有要換的卡時先問；換的順序：核心、真相、其他，最後連動 5。沒有要換的卡時直接改、通知「改成「題材 × 氣氛」」。
8. 發三張核心：同一種氣氛的核心（還沒選氣氛時全部），題材合的排前面；各組裡隨機排，上一次發過的與目前選的排在該組最後；取前三張。
   每種氣氛只有 3 張，所以「換三張」是同樣的 3 張換順序（D13）。
9. 「交給系統」：題材、氣氛各自從全部裡平均抽一個（隨機抽、照條件抽開始時；卡片一覽開始時題材也是）。
10. 合得來的理由（卡上的小標、從清單挑的說明）：符合體驗的核心；（真相）和鎖定的卡合得來；（其他）和真相合得來；符合題材；符合氣氛（核心與氣氛卡不寫氣氛）。

亂數：瀏覽器的亂數；頁面上有 `window.__plotDeckSeed`（字串）時改用這個種子的決定性亂數（E2E 的視覺基準用，D16）。

### 3.3 PC 與 NPC

- 每位 PC：稱呼、立場、關係的對象。PC 人數 1～4、秘密卡開關存在每一份劇本。
- 關係的對象的選單：其他 PC（「PC2（稱呼）」）與 NPC（「NPC：名字或卡名」、追加的 NPC「追加的 NPC n」）。
- 卡上「誰的卡」：關係「PC1 → 對象」、秘密「PC1」。

### 3.4 回答與問題

- 回答與改寫的問題跟著那張卡：換卡就清掉（D6）。回答只有空白時不算回答。
- 隨機回答：從那張卡的 3 個例子挑一個和現在不同的。
- 「回答了 n／m」：清單與文件算全部有卡的欄（故事 9 張＋PC 的卡）；「回答問題」一步算故事的 9 張；「PC 與 NPC」一步算 PC 的卡。

### 3.5 劇情大綱的例子

舞台、導入、氣氛卡、線索、NPC、障礙、真相、結局都抽到才有（體驗的核心可以沒有）。五段：
1. 體驗的核心：「玩完之後想留給 PL 的感受是「核心」：說明。高潮是「回答」。」（沒回答：「高潮可以是「第一個例子」之類的場面。」）
2. 「舞台是「舞台」。PC 們〈導入的說法〉，捲入了這起事件（奇幻：這件事）。〈氣氛的一句〉」＋「要追的線索是「線索」，關鍵人物是「NPC（有取名用名字）」，擋在前面的是「障礙」。」
3. 真相（GM 用）：真相卡的大綱句，舞台換成「舞台名」，氣氛卡第一次寫「稱呼（氣氛卡的名字「卡名」）」、之後只寫稱呼（沒有稱呼時寫「卡名」）。
4. GM 要先決定的事：「關於真相：問題」「關於〈氣氛卡的名字〉：問題」（改寫過的照改寫的，D9）。
5. 結局：「結局的方向是「結局」。說明寫最後一幕之前，先決定「問題」的答案。」

### 3.6 場景與線索的草稿

- 推理：〈氣氛卡的名字〉「卡名」的真面目與規則；真相「卡名」的內容（誰、為什麼）；走向結局「卡名」的方法。
- 場景：導入：〈導入〉（地點＝舞台，內容＝導入的回答或說明）；調查：〈舞台〉（「調查「舞台」，追查「氣氛卡」的痕跡。」）；問話：〈NPC 的名字〉（內容＝和真相的關係或「向〈名字〉問話。」）；
  障礙：〈障礙〉；高潮（內容＝核心的回答或第一個例子）；結局：〈結局〉。
- 線索：線索卡（有回答時「卡名：回答」）放在「調查」、連到第一個推理；「〈NPC〉的話」放在「問話」、連到第二個推理。
- 從空白開始：一個空的推理、一個叫「導入」的場景。

### 3.7 檢查（3 條的規則）

一個推理建議連 **3 條以上**有寫內容的線索（漏掉一條也能往下走）。檢查欄依序：還沒有推理（警告）；每個推理「N1 文字：線索 n 條」（≥ 3 ok、2 提醒「再 1 條…」、≤ 1 警告「連 3 條以上…」）；
還沒決定場景的線索（警告）；沒連到推理的線索（提醒，「只是營造氣氛的話，留著也可以」）；沒放線索的場景（說明，「導入、高潮與結局沒有也可以」）。

### 3.8 文件的構成（畫面、列印、HTML 共用）

白底的紙（深色主題也一樣）；標頭：「劇本骨架・現代」、劇本名、「PC n 人・秘密卡／題材 × 氣氛／體驗的核心「…」／做法／回答了 n／m 題／YYYY/MM/DD（今天）」、「GM 用」的章。

1. 01 劇情大綱的例子（沒有時「卡抽齊之後才有劇情大綱。」）
2. 02 體驗的核心與故事的骨架（導入 → 障礙 → 真相 → 結局）：核心一張寬的卡＋4 張
3. 03 舞台與〈氣氛卡的名字〉：4 張
4. 04 場景與線索（有內容時才有）：PL 要查明的事（每個推理的線索數，不到 3 條紅字）、每個場景（名字、地點、發生的事、線索的表格：編號／線索／取得的方法／連到）、還沒決定場景的線索
5. 05（沒有場景與線索時 04）登場人物：每位 PC（稱呼、立場、關係的對象、關係卡、秘密卡〔虛線〕）、NPC（名字、卡名或角色、和真相的關係）、秘密卡的提醒

每張卡：種類（＋步驟編號、誰的卡）、標題、說明、問題、回答（沒有時「（還沒回答）」）。窄的紙（< 820 px）改成兩欄、更窄一欄。
列印：A4、紙的邊界 12 mm；HTML：獨立的檔案（灰底上一張紙）。使用者的字一律跳脫。

### 3.10 劇本排版台的格式（markdown）

給劇本排版台（scenario-editor）的原稿欄貼上（它照 markdown 讀，見其規格 F289）：`:::title` 劇本名、`:::subtitle` 卡組＋題材 × 氣氛＋PC 人數、
`#` 每一節（同文件的 01～05）、`##` 每張卡（說明、`:::note[問題]`、回答）、推理一行一個、每個場景 `##`＋線索的 `:::table[S1 線索]`
（`|編號|線索|取得的方法|連到|`）、檢查的提醒放在 `:::note[檢查]`、每位 PC 一份 `:::handout[PC1的手冊]{no=HO1}`（立場、關係、秘密與回答）、
每位 NPC 一張 `:::npc[名字]`（卡名與關係）。單元測試用劇本排版台自己的讀法確認讀得出這些段落。檔名「劇本名.md」。

### 3.11 存檔的資料

自動存檔 `trpg-toolkit:plot-deck`：`{ scenarios: 劇本[], current: 目前的 id }`；畫面的選擇（分頁、卡片／清單、卡片一覽的篩選與挑的卡、清單的搜尋）
另存 `trpg-toolkit:plot-deck:preview`（不列入復原）。一份劇本：id、建立與更新時間、劇本名、卡組、題材、氣氛、做法、階段（開始／照條件抽／抽好了）、
照條件抽的步驟與發的三張、目前的步驟、PC 人數、秘密卡、每一欄的卡與鎖定（故事 9 欄＋rel1～4、sec1～4）、每位 PC（稱呼、立場、對象）、NPC（名字、關係）、
追加的 NPC、回答與改寫的問題（`{ 欄: { card, text } }`）、場景與線索（推理、場景、線索）。專案檔的 `data` 是 `{ scenario }`。

### 3.12 檔名

劇本名（空白時自動的名字）換掉檔名不能用的字（`<>:"/\|?*` 等換成 `_`），最長 60 字：「劇本名.html／.txt／.md」、專案檔「劇本名_YYYYMMDD.json」。

## 4. 互動與手感

- 對話框（放大看、從清單挑、換題材與氣氛、確認）：焦點鎖在裡面、Esc 關閉；放大看與從清單挑點外面也關閉；從清單挑打開時焦點在目前這張。
- 點卡片的空白處＝放大看（照條件抽的時候＝從清單挑）；鍵盤用卡上的「放大看」按鈕。
- 剛換掉的卡底色亮約 1.2 秒。換步驟時，步驟列在畫面上方外面就捲回來。
- 通知：草稿做好、匯出、複製、隨機填、清單的操作（打開、複製、刪除）。
- 快捷鍵：Ctrl＋Z 復原、Ctrl＋Shift＋Z／Ctrl＋Y 重做、? 看快捷鍵。
- 版面：≥ 1024 px 劇情大綱在左欄（固定在畫面上）；< 640 px 步驟列改成上一步／下一步；390／320 寬沒有橫向捲動。

## 5. 容易做壞的地方

- 換真相時要連動其他卡；換核心要問真相與結局；氣氛換了核心與氣氛卡一定換（鎖定的也換）。
- 回答跟著卡：卡換掉後舊的回答不能留在新卡上。
- 線索的編號依場景的順序（不是加入的順序）；刪場景不刪線索。
- 文件與 HTML 一定要跳脫使用者的字；列印只印文件。
- 每個題材 × 氣氛都要抽得出整副（單元測試）。
