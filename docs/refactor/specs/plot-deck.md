# 劇本骨架抽卡（plot-deck）行為規格

## 0. 概要

抽卡拼出 TRPG 劇本的**骨架**（不限規則系統）：先選題材（PC 們要完成的事）與氣氛（希望桌上的感覺），再抽「餘韻」（散場後留在 PL 心裡的感覺）、
導入、障礙、真相、結局、舞台、焦點（最能代表這個氣氛的那樣東西，依氣氛換叫法：陰森＝怪談…）、線索、NPC，以及每位 PC 的關係與秘密的卡。
卡會偏向和題材、氣氛、餘韻、先抽到的真相合得來的。抽好之後回答每張卡的提問把骨架填滿，寫下 PL 要想通的事（推理題）並把線索放進場景，
檢查每道推理題至少有 3 條線索，最後排成一份劇本文件（列印／PDF、HTML、純文字；另有送去劇本排版台的 markdown）。
做好的劇本自動存在這個瀏覽器的「我的劇本」；「卡庫」列出全部的卡，也可以挑幾張卡開始。

輸入：點選、文字欄、本站的專案檔。輸出：畫面、列印、HTML、純文字檔、markdown（劇本排版台用）、專案檔。

靈感來源：Xelltis エノキ「Kadan」現代・奇幻 體驗版（<https://www.xelltis.com/>；BOOTH 販售的製品版的體驗版，使用者 2026-11-15 上傳兩個體驗版的 zip，
存在 `/home/user/upstream/Xelltis_Kadan-trial-modern/`、`…-fantasy/`）。授權：**All rights reserved**，作者條款禁止再散布、散布改作版或一部分、
整批轉載收錄卡文、用收錄卡文做同目的的製品、取出效果音。本站照 CLAUDE.md 規則 1 的「未授權、作者條款限制」：**只參考功能、互動流程、演算法與數值**，
程式照本站的結構重寫；**題材、氣氛、卡與介面文字全部本站自己寫（繁中）**，寫完才和原作比對（D2、D3、D24）。不放 UPSTREAM_LICENSE。頁尾只放靈感來源。
使用者 2026-11-15 決定：做成新工具、現代＋奇幻兩套卡；「複製給 AI 的提示詞」不做（F90）。

### 3.2 卡的權重（偏好）

「題材合」＝卡的題材有選的題材；「全部」＝沒標或標 `*`；「還沒決定」＝還沒選題材（或氣氛）。

1. 題材與氣氛：
   - PC 的卡：1。
   - 餘韻：氣氛不同 0（抽不到）；題材合 6，其他 1。
   - 焦點：氣氛不同 0；題材合 3，其他 1。
   - 其他：題材與氣氛都不合 0.05；否則（題材的倍率）×（氣氛的倍率），合 6、全部 2、還沒決定或不合 1。例：都合 36、題材合＋氣氛全部 12。
2. 餘韻以外再乘（權重已經是 0 的不乘）：
   - 合餘韻的真相、結局 ×18；
   - 舞台已經抽到、卡有適合的場所而舞台的種類都不合 ×0.06；
   - 真相：和每張鎖定的卡合不來 → 0、合得來 → ×2（每張相乘）；
   - 其他：和目前的真相合不來 → 0、合得來 → ×4。
3. 抽一張：同一種卡在別的欄用掉的不抽（PC 的關係、秘密每人一張不重複）；重抽時也不抽現在這張；依權重抽（權重 0 的不抽）；
   全部是 0 時從還沒用掉的平均抽；一張都沒有時不動。
4. 全部抽：沒鎖定的故事的卡先清空，依序抽餘韻、真相、舞台，再抽其他。
5. 真相換了（重抽、自己挑）：沒鎖定的其他卡裡權重變 0 的重抽。
6. 餘韻換了（抽好之後）：沒鎖定、不合新餘韻的真相與結局 → 問「真相與結局要跟著換嗎？」（一起換／先不用）；重抽真相時連動 5。
7. 改題材與氣氛（抽好之後）：氣氛變了，餘韻與焦點一定換（鎖定的也解除後換）；其他沒鎖定的故事的卡，新題材與氣氛的權重（第 1 項）不到 0.1 的也換；
   有要換的卡時先問；換的順序：餘韻、真相、其他，最後連動 5。沒有要換的卡時直接改、通知「方向改成「題材・氣氛」」。
8. 發三張餘韻：同一種氣氛的餘韻（還沒選氣氛時全部），題材合的排前面；各組裡隨機排，上一次發過的與目前選的排在該組最後；取前三張。
   每種氣氛 5 張，所以「再發三張」換得到沒看過的（D13）。
9. 「抽的時候再決定」：題材、氣氛各自從全部裡平均抽一個（一次抽齊、先挑餘韻開始時；從卡庫開始時題材也是）。
10. 搭在哪裡（卡上的小標、自己挑的說明）：跟餘韻搭；（真相）跟鎖起來的卡搭；（其他）跟真相搭；題材；氣氛（餘韻與焦點不寫氣氛）。

亂數：瀏覽器的亂數；頁面上有 `window.__plotDeckSeed`（字串）時改用這個種子的決定性亂數（E2E 的視覺基準用，D16）。

### 3.4 回答與提問

- 回答與改寫的提問跟著那張卡：換卡就清掉（D6）。回答只有空白時不算回答。
- 給個例子：從那張卡的 3 個例子挑一個和現在不同的。
- 「已答 n／m」：清單與文件算全部有卡的欄（故事 9 張＋PC 的卡）；「填答」一步算故事的 9 張；「角色」一步算 PC 的卡。

### 3.5 故事梗概

舞台、導入、焦點、線索、NPC、障礙、真相、結局都抽到才有（餘韻可以沒有）。五段（每段有標籤）：
1. 開場：「「導入」把 PC 們帶到了「舞台」。」＋氣氛各自的一句（陰森「而這附近流傳著一則怪談：「焦點」。」、緊繃「時限已經開始倒數：「焦點」。」…，每種氣氛的句子是本站寫的）。
2. 往前走：「手上的線頭是「線索」；知道內情的是「NPC（有取名用名字）」；可是「障礙」讓事情沒那麼簡單。」
3. 幕後（只給 GM）：真相卡自己的一句，`{stage}` 換成舞台名，`{tone}` 第一次寫「焦點的叫法「卡名」」、之後寫「「卡名」」。
4. 收尾：「朝「結局」收尾——結局的說明」；有餘韻時再加「散場時想留下的餘韻是「餘韻」：說明」與「最後一幕：回答。」（沒回答：「最後一幕可以像這樣：第一個例子。」）。
5. 留給 GM 的空格：「真相——提問」「焦點的叫法——提問」「結局——提問」（改寫過的照改寫的，D9）。

### 3.6 推理與場景的草稿

- 推理題：A「「線索卡」指向的是什麼人、什麼地方？」；B「〈NPC 的名字〉隱瞞了什麼？」；C「為什麼會發生「真相」？」（沒有那張卡時少一題）。
- 場景：開場：〈導入〉（內容＝導入的回答或說明）；現場：〈舞台〉（地點＝舞台，「PC 們在「舞台」第一次碰上「焦點」。」）；對話：〈NPC 的名字〉（內容＝跟真相的牽連或「和〈名字〉談一談——他知道的比說出口的多。」）；
  阻礙：〈障礙〉；揭曉與收尾（內容＝餘韻的回答或第一個例子＋「之後往「結局」收尾。」）。
- 線索：線索卡（有回答時「卡名——回答」）放在「現場」、指向 A；「〈NPC〉說溜嘴的一句話」放在「對話」、指向 B；「「焦點」留下的痕跡」放在「阻礙」、指向 C。
- 一格一格自己寫：一道空白的推理題、一個叫「開場」的場景。

### 3.7 檢查（3 條的規則）

一道推理題建議有 **3 條以上**有寫內容的線索指向它（漏了一條也走得下去）。檢查欄依序：
1. 總數「推理題 n 道、場景 n 個、線索 n 條。」（說明）；
2. 還沒有推理題時「先寫下 PL 得推理出來的事——一份劇本大約 2～4 道。」（警告）；
3. 每道題「A. 文字　…」：≥ 3「n 條線索，夠了」、2「再補一條，就算有一條沒被找到也不會卡住」（提醒）、≤ 1「只有 n 條線索：至少要 3 條才保險」（警告）；
4. 沒有線索的場景（說明，「開場、高潮、收尾這類場景本來就可以沒有」）；
5. 還沒放進場景的線索（警告）；
6. 沒指向推理題的線索（提醒，「如果只是營造氣氛的小細節，可以不管」）。

### 3.10 送去劇本排版台（markdown）

給劇本排版台（scenario-editor）的原稿欄貼上（它照 markdown 讀，見其規格 F289）：`:::title` 劇本名、`:::subtitle` 卡組／題材・氣氛／PC 人數、
`#` 每一節（同文件的六節）、`##` 每張卡（說明、`:::note[提問]`、「回答：…」）、推理題一段一題、每個場景 `##`＋線索的 `:::table[#2 線索]`
（`|#|線索|怎麼拿到|指向|`）、檢查的提醒放在 `:::note[檢查]`、每位 PC 一份 `:::handout[PC1的手冊]{no=HO1}`（身分、關係、秘密與回答）、
每位 NPC 一張 `:::npc[名字]`（卡名與牽連）。檔名「劇本名.md」。

**使用者的字照樣是文字**（L2）：照劇本排版台 `mdParse` 實際認得的寫法跳脫——行首的 ``` 與 ~~~、`#`～`######` 標題、`---`／`***`／`___` 橫線、`![…](…)` 圖片、
`::`／`:::`（含全形 `：`）的寫法前面加一個零寬空格（U+200B，看不見、`trim` 也不去掉）；段落的第一行會被猜成台詞（「』開頭）、注釋（※＊）、
特殊區塊（【判定】、〈…〉…判定）或場景（（場景）…）時，前面接標籤（「回答：」「經過：」…），標籤之後還會被猜到的（任何地方都算的那兩種）讓標籤自己成一行；
寫的字裡的空行拿掉（不然會切成好幾段）。`>`、`|`（`:::table` 以外）、`-`／`*`／數字清單 劇本排版台不當成寫法（讀它的程式確認過），照原樣。
單元測試用劇本排版台自己的 `mdParse` 確認：章節、手冊、NPC 卡、線索表讀得出來，使用者寫了這些記號的回答、提問、牽連、身分、場景與推理題都還是描述文或原本的區塊。

### 3.11 存檔的資料

自動存檔 `trpg-toolkit:plot-deck`：`{ scenarios: 劇本[], current: 目前的 id }`；畫面的選擇（分頁、卡面／列表、卡庫的篩選〔種類、題材、氣氛、搜尋〕與放進去的卡、清單的搜尋）
另存 `trpg-toolkit:plot-deck:preview`（不列入復原）。一份劇本：id、建立與更新時間、劇本名、卡組、題材、氣氛、做法、階段（開始／先挑餘韻／抽好了）、
先挑餘韻的步驟（`setupStage`）與發的三張（`coreOffer`）、目前的步驟、PC 人數、秘密卡、每一欄的卡與鎖定（故事 9 欄＋rel1～4、sec1～4）、每位 PC（名字、身分、對象）、NPC（名字、牽連）、
配角、回答與改寫的提問（`{ 欄: { card, text } }`）、推理題與場景（推理題、場景、線索）。專案檔的 `data` 是 `{ scenario }`。

**卡的 id**：存檔只記卡的 id（`core.heirloom`），所以**卡的 id 一旦上線就固定**：卡的文字可以修，但意思換掉的卡要用新的 id；拿掉的卡，它的 id 不再拿來給別的卡用
（不然舊的存檔會讀到另一張卡、回答也會掛到不相干的卡上）。上線前的開發版重用過 id（例：`truth.insurance`），沒有上線，不另外處理。
讀到這一版的卡組找不到的卡 id（舊版、卡組改過或手改的存檔）：那一欄空著（重抽或自己挑補上；列表的排法也列出空著的欄，空的欄不能鎖定），
那張卡的回答與改寫的提問一起拿掉，先挑餘韻發的三張裡的也拿掉；氣氛的 id 找不到時跟著餘韻；其他照樣讀進來。
通知「有 N 張卡在這一版的卡組裡找不到，已經拿掉；其他照樣讀進來。」：開專案檔時和「專案檔開好了」合成一則警告色的通知，自動存檔在開頁時通知一次
（N 是每份劇本各算、同一份裡同一張只算一次）。全部的卡都找不到的「抽好了」回到開始的畫面。

### 3.12 檔名

劇本名（空白時自動的名字）換掉檔名不能用的字（`<>:"/\|?*` 等換成 `_`），最長 60 字：「劇本名.html／.txt／.md」、專案檔「劇本名_YYYYMMDD.json」。

## 4. 互動與手感

- 對話框（放大看、自己挑、改題材與氣氛、確認）：用共用的 `Dialog`；焦點鎖在裡面、Esc 關閉；放大看與自己挑點外面也關閉；自己挑打開時焦點在現在這張；
  **關閉後焦點回到打開它的按鈕**（`returnFocus`；打開它的按鈕不在了〔例如從放大看裡打開自己挑〕時，回到頁面上同一欄的「自己挑」或「放大看」，M3）。
- 點卡片的空白處＝放大看（先挑餘韻的時候＝自己挑）；鍵盤用卡上的「放大看」按鈕。
- 剛換掉的卡底色亮約 1.2 秒。換步驟時，步驟列在畫面上方外面就捲回來。
- 通知：草稿放好、匯出、複製、先放例子、清單的操作（開啟、複製、刪除）、從卡庫開始時被換掉的焦點。
- 快捷鍵：Ctrl＋Z 復原、Ctrl＋Shift＋Z／Ctrl＋Y 重做、? 看快捷鍵。
- 版面：≥ 1024 px 故事梗概在左欄（固定在畫面上）；< 640 px 步驟列改成上一步／下一步；390／320 寬沒有橫向捲動（含卡庫與我的劇本）。

## 5. 容易做壞的地方

- 換真相時要連動其他卡；換餘韻要問真相與結局；氣氛換了餘韻與焦點一定換（鎖定的也換）。
- 回答跟著卡：卡換掉後舊的回答不能留在新卡上。
- 線索的標號依場景（不是加入的順序）；刪場景不刪線索。
- 文件與 HTML 一定要跳脫使用者的字；列印只印文件；送去劇本排版台的 markdown 要讓使用者的字照樣是文字（3.10）。
- 從卡庫開始時氣氛由餘韻決定，和放的順序無關（M2）。
- 一次性的動作連續按，復原也要一步一步退（F03）。
- 每個題材 × 氣氛都要抽得出整副（單元測試）。
