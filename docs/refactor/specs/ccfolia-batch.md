# CCFOLIA 角色批次產生器（ccfolia-batch）行為規格

## 0. 概要

KP 準備劇本的 NPC 與敵人群用：把 NPC 寫成幾行速記、直接貼上劇本裡的 NPC 資料（日文、繁中、簡中）、貼上試算表，
或貼上角色卡網站匯出給 CCFOLIA 的角色資料（複製到剪貼簿的 JSON），一次讀成一份**棋子清單**（每一行讀成什麼都列出來、讀法可以改）；
立繪與表情差分放進**圖片庫**（圖片名稱和棋子同名就是立繪、「名稱_笑」是差分「笑」）；匯出成**只有角色的房間 ZIP**
（在 CCFOLIA 的房間設定讀入就出現；最多 500 個、放到盤面的 8 個一列排開）與以棋子名稱命名的**素材 ZIP**。
全部在瀏覽器內處理，不上傳任何東西。

- 輸入：文字（速記・從劇本貼上、TSV／CSV、角色剪貼簿 JSON）、圖片（拖放、選檔）、專案檔（本站的 ZIP；也讀得到原作的 .json）。
- 輸出：CCFOLIA 房間 ZIP（只有 characters 與用到的圖）、素材 ZIP、一個棋子的角色剪貼簿 JSON、專案檔。

靈感來源：shiki365／キャラクター一括メーカー（<https://github.com/shiki365/character-batch-maker>，本規格依 `423a28a`
〔v1.4，2026-11-18〕；以下稱【原作】）。授權 MIT（Copyright (c) 2026 shiki365），授權全文在
`web/src/tools/ccfolia-batch/UPSTREAM_LICENSE`（`UPSTREAM_SOURCES.json` 列出原作）；詞表（日文照原作）與範例照原作翻成繁中，
繁中、簡中的詞表由本站補上（5. D5）。房間 ZIP 的格式是原作讀 CCFOLIA 1.37.4 的程式寫的、1.37.6 再確認過（README「仕組み」），
本站一律經過共用層 `@/ccfolia`。

用語：

| 本文用語 | 意思（原作的用語） |
|---|---|
| 棋子 | CCFOLIA 的角色（キャラクター、駒）。 |
| 清單 | 目前的棋子清單（できあがり）：已確定＋從輸入讀到的＋角色卡網站貼上的。 |
| 速記・從劇本貼上 | 輸入的方式之一（メモ書き・シナリオから貼る）。 |
| 貼上試算表 | 輸入的方式之一（表を貼る）。 |
| 標籤 | 「HP 12」的「HP」；讀法是技能（寫成判定）／狀態／參數／不用（ラベル、使い方）。 |
| 圖片庫 | 先放進工具的圖片（画像の置き場）。 |
| 手動修改 | 在清單裡直接改某個棋子（手直し）。第一次修改時清單固定下來。 |
| 已確定 | 「確定，換下一位 NPC」留下來的棋子（確定した駒）。 |
| key 比對 | NFKC 正規化、轉小寫、去掉所有空白之後再比（全形英數、全形括號與半形視為相同）。 |

「目視」＝截圖並排。

## 2. 輸入

### 2.1 文字

貼上或打字（換行 CR、CRLF 都當 LF）。速記的讀法見 3.2；試算表見 3.4；角色卡網站的資料見 3.5。

### 2.2 圖片

PNG（含 APNG）、JPEG、GIF、WebP，依檔頭判斷（副檔名、MIME 不對也收；AVIF、BMP 等不收，5. D8）。大小不限，但超過 5 MB 的一直警告。

### 2.3 專案檔

本站的專案檔（ZIP：`project.json`＋`files/<資產 id>.<副檔名>`；3.10）。不是本站專案檔時先試原作的專案檔（2.4），也不是時
顯示共用的錯誤（「無法開啟專案檔：…」），目前的內容不變。

### 2.4 原作的專案檔

`{ app: "ccf-character-batch-maker", version: 1, state: { images: [{ id, kind: "file", name, type, size, hash, dataUrl }], mode, memo, table,
columns, labels, kept, pasted, opts, edited } }`（`app` 不符時不是原作的專案檔）。

- 圖片：`dataUrl` 讀成位元組放進資產庫（讀不了的跳過），圖片庫的 id 沿用原作的 id（棋子以 id 指定圖）。
- `mode`：沒有 `mode` 而有表格文字的舊存檔當成試算表（同原作）。
- 棋子：欄位名稱與本站相同；原作的「行」`✓`＝已確定、`⧉`＝貼上的、空白＝手動加的、數字＝讀到的行；型別不符的欄位用預設值（3.10）。
- `opts`：原作的 9 個欄位照讀；本站新增的（能力值判定、差分的 @ 名稱）用預設值。`columns`、`labels` 的用途代碼與本站相同。

## 3. 輸出與規則

### 3.1 名稱的比對

標籤、標題、圖片名稱一律 key 比對（NFKC、轉小寫、去掉所有空白）。讀取時的詞表（`web/src/tools/ccfolia-batch/words.ts`）：
日文照原作（`words.v1.js`），繁中、簡中、少數英文由本站補上（技能名稱照本站 coc-sheet 與常見的 6 版、7 版譯名；5. D5）。

### 3.2 速記・從劇本貼上的讀法（原作 `parse.v1.js` 的 parseMemo；新版 `memo.ts` 的 readNpcText）

#### 3.2.1 段與第一行

- 空行分隔一段＝一個 NPC；每行記下行號（1 起算）。
- **PDF 斷行接回去**（一段裡）：下一行以「、」「,」「，」開頭；下一行是 2 個字以內的假名而且上一行以假名結尾；上一行的開括號多於關括號
  而且下一行的關括號多於開括號——這三種直接接上；上一行不是以數字、空白、%、。結尾、不是說明的文字、不是小標，而下一行以數字開頭
  （後面是 %、括號、空白或結尾）——以空白接上。
- **行首的項目符號與編號**去掉：「- 」「-」「• 」「·」「・」「*」「1.」「1、」（1～2 位數；後面要有字；「---」「**」「1.5」不算；5. D21）。
- 傷害的算式裡的 DB 寫法換成 `+DB`：「+傷害加值」「+傷害加成」「+傷害獎勵」「+伤害加值」「+伤害加成」「+伤害奖励」「+ダメージボーナス」
  「+ダメボ」（`+` 後面可以有空白；NFKC 之後、判斷行的種類之前；5. D19）。
- 第一行：不是小標、第一個詞不是認得的標籤（能力值、狀態、技能名稱；寫了「名稱：」時一律是名字）時是**名字**，否則提示「沒有名字」並當資料讀。
  名字的整理：去掉行首的記號（■□◆◇●○▼▽★☆◎§・）→ 去掉「名稱：」「名前:」「敵人資料：」「エネミーデータ：」「NPC：」這類前綴 →
  「【名字】其他」取括號裡的 → 「名字 ×3」「名字*2」「名字 x3 隻」取個數（1～3 位數；量詞 体、人、匹、隻、只、名、位、個、头…）→
  「頭銜─名字(讀音)」「頭銜 - 名字」取有讀音的那邊（沒有時取前面）→「名字、頭銜」取**括號外**第一個「、」「,」前面
  （括號裡的逗號不切：「老人（72 歲，退休教師）」；括號是全形、半形的 ( ) 與〈〉《》<>【】〔〕[]「」『』＜＞；5. D18）→ 名字後面的「(讀音)」「(34 歲)」「(139)」
  與之後的文字去掉（最多 3 次；讀音＝假名、拉丁字母、注音，括號裡有數字也算；5. D5）。去掉的部分在「說明的文字也放進備註」時放進備註。

#### 3.2.2 特別的行（依序判斷）

1. **標籤行**：「角色備註：」「メモ:」→ 備註（值照原文）；「立繪：」「圖片：」「立ち絵:」→ 立繪的名稱；「網址：」「url:」→ 參照網址；
   「聊天面板：」「指令：」「コマンド:」→ 照原文放進聊天面板。冒號全形半形都可以。
2. **網址**：整行是 `http(s)://…` → 參照網址。
3. **小標**：「【技能】」或「技能：〈閃避〉40」「武器：」（標籤 14 字以內；後面接數字的不是小標，例「戰鬥 60」是技能）。小標的讀法
   （詞表見 `SECTION_WORDS`）：資料（能力值、技能、屬性、狀態…）、武器（武器、裝備、持有物…）、說明（法術、特殊能力、備考、備註、特徵、
   背景、說明…，**不讀**）、備註（メモ、角色備註）、聊天面板（コマンド、指令，與結尾是「チャパレ」「チャットパレット」「聊天面板」的）。
   只有小標的行標「小標」；小標後面的文字照那一節讀。
4. 備註那一節：整行放進備註。說明那一節，或以 # ※ 開頭的行：說明的文字（不讀；勾「說明的文字也放進備註」時放進備註，用原文）。
5. **指令的行**：聊天面板那一節，或以 CCB／CC／RESB／CBRB（可以 s 開頭）、骰子式、choice、`:`、`@` 開頭，或含 `<=` 的行
   （但「1d6 的傷害」這種自己一行的傷害例外）：在下一個指令的開頭切開（`CCB<=`、`CC(`、`1d3 【`…），每個照原文放進聊天面板。
6. **自己一行的傷害**：以骰子開頭、含「ダメージ／威力／傷害」、前一個技能還沒有傷害、沒有【 → 前一個技能的傷害；
   「もしくは／または／or／或／或是／或者」＋骰子 → 前一個技能的**另一種傷害**（括號是什麼時候用，例「或 1D3+DB（用警棍打）」）。
7. **只有括號的行**（不在武器那一節）：裡面有「ダメージ／傷害 骰子式」而且前一個技能沒有傷害 → 它的傷害；
   括號裡整個是骰子式（「（1D3+DB）」）、**上一行**最後讀到的是技能而且它沒有傷害 → 那個技能的傷害（中文 PDF 常在技能與傷害之間斷行；
   中間隔了別的行時不接；5. D20）；否則不讀。
8. **武器那一節**、沒有 % 的行：有「ダメージ／傷害 骰子式」→ 上一個武器名字的傷害；沒有 → 武器的名字（去掉括號與空白）；
   說明的文字（3.2.6）不讀（5. D7）。最後，技能裡和武器同名（去掉括號後比對）而且沒有傷害的，接上武器的傷害。
9. 其他的行照 3.2.3～3.2.5 讀項目。

#### 3.2.3 一行的整理

NFKC 之後依序：

1. `±` 換成 `+`。
2. 括號裡的標籤（〈〉《》<>【】〔〕[]「」『』，1～40 字）保護成一個詞（前後加空白）。
3. 屬於標籤的括號與附註保護起來（例「藝術(魔術)」「射擊(手槍)」「(絕命時發動)」：括號裡有數字、空白、/ ( ) % . + - 以外的字），黏在前一個詞上。
4. 去掉「※2」這種註記。
5. PDF 拆開的英文代號接回去：「D EX」→ DEX（只限 STR、CON、POW、DEX、APP、SIZ、INT、EDU、SAN、LUK、MOV、BLD）。
6. PDF 拆開的數字接回去：「7 5」→ 75。
7. 括號裡只有數字、空白、/ 的（另一版的值「12(60)」「60(30/12)」、沒有收尾的「(1 0」）去掉。
8. 成對的標籤展開：「STR／DEX 60／50」「STR / CON | 80 / 65」→「STR 60 , DEX 50」（標籤與值的個數相同時）。
9. 去掉「成功率」「成功値」「技能値」「確率」「成功值」「技能值」「機率」「概率」與 %。
10. 骰子式裡的空白去掉（「1D10 + DB」→「1D10+DB」，最多 3 次）。
11. 「、」「,」「|」「;」是分項；數字之間的「/」是「目前值/最大值」，其他的「/」是分項。
12. 「HP:12」「HP=12」的冒號、等號換成空白。
13. 黏在一起的標籤與數字拆開：「STR12」→「STR 12」（骰子式不拆）；「99天文學」→「99 天文學」。

#### 3.2.4 項目

整理後以空白切成詞，依序：分項符號結束目前的標籤；整段括號的附註在標籤開頭時跳過；「呪文／法術／咒文…」開頭（後面不是數字）時，
後面全部是說明（不讀、不算讀不出）；「なし／無／沒有」接在標籤後面時丟掉這個標籤（「護甲 無」）；

- **標籤＋數值**（`12`、`12.5`、`55/99`，可以帶 + -）：一個項目；數值後面接著讀**傷害**：括號附註裡的傷害（「（傷害 1D6、對象隨機）」
  「(1D3+DB)」「（1D10，射程15米）」：讀成傷害與附註，附註照原文、不插空白；**新版新增**，原作跳過附註，5. D6）、「傷害 1d6」「ダメージ 1d6」、「1d6」、「1d6 的傷害」「1d6點傷害」「1d6のダメージ」；
  傷害骰子式後面的文字是附註（例「1d4傷害+束縛」→ 附註「束縛」；黏住的括號只留裡面，5. D7）。
- **標籤＋骰子式**（「DB 1d6」）：值是那個骰子式的項目。
- **骰子式**、前一個項目沒有傷害：前一個項目的傷害（「傷害 1d6」、「1d6 的傷害」分開寫在後面）。
- 其他的詞是標籤的一部分。

沒有讀成項目、但含數字的文字是**讀不出**的（畫面上警告色）。整行是說明的文字（3.2.6）時不讀。

#### 3.2.5 讀法的判斷

- 認得的標籤（`CANON_LABELS`、能力值）：照詞表。整個寫法比對 → 去掉括號後比對（「STR(力量)」）→ 兩個詞都指向同一個時（「力量 STR」）。
  讀成的標籤：能力值一律英文代號（力量 → STR、體質 → CON、意志 → POW…）；HP（耐久力、体力、體力、耐久值、生命值、生命…）、
  MP（マジックポイント、魔力、魔力點、魔力值、魔法值…）、SAN（正気度、理智、理智點、理智值、SAN 值…）、**幸運**（幸运、LUK；同本站 coc-sheet）
  是狀態（簡中的「点」寫法同）；DB（ダメージボーナス、傷害加值…）、體格（BLD、ビルド）、MOV（移動、移動力…）、護甲（装甲、裝甲、护甲）、年齡是參數；
  先攻值（イニシアチブ、先攻…）是先攻。「体格」（日文是 SIZ、簡中是 Build）照寫成參數（5. D4）。
- 其他：值是骰子式 → 參數；有最大值 → 狀態；標籤以「点、値、数、點、值、數」結尾 → 狀態；其餘 → 技能。
- 使用者改過的讀法（F25）優先。不用 → 不讀；先攻 → 先攻值。
- 狀態：值、最大值（沒有最大值時＝值）；同一個標籤再出現時取代。參數：值照寫法（帶正負號或骰子式時照原文）；DB 一律帶正負號
  （0 → +0、1d4 → +1d4）；同一個標籤再出現時取代。技能：值、傷害、附註、另一種傷害。
- 先攻值：讀到的先攻，沒有時 DEX 的值，都沒有時 0。
- 標籤裡的半形冒號換成全形（參數的參照 {標籤}）。
- 讀到的標籤（F25）記下：讀成的標籤、寫法、自動的讀法、目前的讀法、認不認得（認得的標籤或常用技能名稱，去掉括號後比對）、次數。

#### 3.2.6 說明的文字

整理後（去掉保護的詞）含「。」、6 個以上連續的平假名、或 **12 個以上連續的漢字**（中文的句子；5. D5），而且第一個詞不是認得的標籤。

#### 3.2.7 版本（自動判斷，判定的寫法用）

依序：原文有「%（數字/數字」（7 版的困難／極限值）→ 7 版；讀到 3 個以上的能力值、75% 以上大於 20、全部是 5 的倍數 → 7 版；
有 7 版才有的技能（近接戦闘、射撃、手さばき、魅惑、威圧、格鬥、射擊、妙手、取悅、恐嚇、信用評級…的開頭）→ 7 版；其他 6 版。

#### 3.2.8 每一行的讀法（F35）

狀態：名字、小標、不用（沒讀到東西）、讀到、讀到一部分（有讀不出的數字）、讀不出。小標籤的寫法：「名字：名 ×3」「角色備註：值」
「參照網址」「備註」「聊天面板：指令」「技能的傷害 骰子式」「武器：名」「（不用）標籤」「先攻值 n」「HP 12/99」「DEX 60」
「閃避 40（傷害 1d3）」「讀不出：文字」。

#### 3.2.9 ×N 與提示

- ×N：最多 100 個（多的不做，提示）；每個複本名字＋字尾（A～Z，26 個以上或選了數字時 1～n；名字是英數結尾時中間加空白），
  「立繪的名稱」是原本的名字（共用立繪與差分）。
- 提示（F28）：「第 n 行開始的 NPC 沒有名字。請在第一行寫名字。」、「名：第 a、b 行有讀不出的數字。寫成「標籤 數字」（例：偵查 60）就讀得到。」
  （最多列 4 行）、「名：能力值出現了 n 次。好幾個 NPC 連在一起時，請在 NPC 之間空一行。」（STR 出現 2 次以上）、「名：讀不到任何數值。」
  （沒有狀態、參數、技能、指令，而且不只一行）、「第 n 行的「名」最多做 100 個。」。沒有名字時「名」是「第 n 行開始的 NPC」。

### 3.3 聊天面板（速記讀到的棋子）

判定的指令：自動時 6 版 `CCB<=`、7 版 `CC<=`；或固定 `CCB<=`／`CC<=`／`1d100<=`；秘密骰時前面加 `s`；不寫成判定時沒有。
行的順序（照本站 coc-npc、coc-sheet：理智檢定 → 幸運 → 能力值 → 技能 → 指令；5. D1、D2）：

1. 有 SAN 狀態（最大值大於 0）、有判定的指令、劇本寫好的指令裡沒有 SAN／正気度／理智的檢定時：`判定{SAN} 理智檢定`；
   有幸運的狀態（最大值大於 0）、劇本寫好的指令裡沒有幸運／幸运／LUK 時，下一行 `判定{幸運} 幸運`（同 coc-sheet）。
2. 勾「能力值也寫成判定」時：讀到的 STR～EDU 依序 `判定值 STR`（CoC 的判定、6 版時值 ×5）。劇本寫好的指令有同名的不寫。
3. 技能依讀到的順序：`判定值 標籤`；有傷害時下一行 `傷害 標籤（傷害）`（有附註時 `標籤（傷害：附註）`）；另一種傷害各一行。
   有 DB 參數時傷害裡的 `+DB` 換成參照 `{DB}`（例 `1d3+DB` → `1d3{DB}`，DB 的值帶正負號）。劇本寫好的指令裡已經有同名的技能時不寫
   （指令的標籤＝【】裡的字，或指令後面的文字）。不寫成判定時技能變成參數（值是文字），傷害照樣寫。
4. 劇本寫好的指令照原文。

匯出、預覽時再接上共用的聊天面板（F14）與差分的 @ 名稱（F15）。

### 3.4 貼上試算表的讀法（原作 `parse.v1.js` 的 parse；新版 `table.ts`）

- 切欄用本站 `@/core/csv` 的 `parseDelimited(text, { quotes: true })`：第一行有 Tab 就是 TSV（引號包住的格可以含 Tab 與換行），否則 CSV。
  全部空白的列略過；列號照試算表（格裡有換行也是一列、空列也算；5. D12）。第一列是標題。
- 每一欄的用途：標題以「狀態:」「參數:」「差分:」（「ステータス:」「パラメータ:」「status:」「param:」「face:」，冒號全形半形都可以）開頭
  → 那個用途、標籤是後面的字；標題空白 → 不用；標題在詞表裡（`COLUMN_HEADS`：名稱、備註、先攻值、聊天面板、立繪、參照網址、顏色、
  棋子大小、放到盤面、狀態不公開、發言時不顯示立繪、不列入盤面的角色清單、不用，各有日文、繁中、簡中、英文的寫法）→ 那個用途；
  其他：內容有「10/12」或標題是 HP、MP、SAN、SP、耐久力、正気度、生命值、理智…→ 狀態，其餘 → 參數。使用者改過的用途（以標題記）優先。
  沒有名稱的欄時第 1 欄當名稱，提示「找不到名稱的欄…」。
- 每一列一個棋子（空白的格略過）：名稱（第一個名稱欄；換行換成空白）、備註與聊天面板（好幾欄時以換行接起來）、參照網址、立繪的名稱、
  差分（標籤＋圖片名稱）、先攻值與棋子大小（數字；讀不出時提示「…不是數字。」；棋子大小夾到 1～100）、顏色（`#rrggbb` 或 6 位十六進位，
  轉小寫；不對時提示）、四個開關（是：1、true、yes、y、on、○、〇、◯、o、✓、✔、はい、する、出す、有、あり、是、要、開；
  否：0、false、no、n、off、×、x、✗、いいえ、しない、出さない、無、なし、否、不要、不、沒有、關；其他提示「看不出是「是」還是「否」」）、
  狀態（「10」→ 10/10、「10/12」→ 10/12；不是這兩種時提示「請寫成「10」或「10/12」（先當成 0）」並當成 0）、參數（照原文）。
- 提示的位置：「第 n 列「標題」的「格」…」。

### 3.5 角色卡網站的資料（原作 parsePieces；新版 `pieces.ts` 的 readSheetExport）

CCFOLIA 的剪貼簿格式 `{"kind":"character","data":{…}}`；也讀：陣列、好幾個前後接著（在最外層的大括號切開，壞的那段跳過）、整段被包成字串。
每個 data → 一個貼上的棋子：名稱、備註、參照網址、聊天面板（字串，不是時空白）、先攻值（數字或數字的文字，否則 0）、顏色（`#rrggbb`，
否則預設 #888888）、棋子大小（`width` 是數字時，夾到 1～100）、狀態不公開／發言時不顯示立繪／不列入盤面的角色清單（布林值，否則照全體設定）、
狀態（標籤、值、最大值；數字的文字也讀，讀不出時 0）、參數（標籤、值都轉成文字）。**不讀** `iconUrl` 與差分（CCFOLIA 的棋子不收別的網站的圖），
只記下有沒有（F29 的提醒）。

### 3.6 圖片庫 ↔ 棋子（原作 app.v1.js 的 matchImages／portraitOf／facesOf；新版 `match.ts`）

- 每個棋子有兩個名稱：名稱、立繪的名稱（表格的立繪欄、「立繪：」行、×N 的複本、改名時記下的原本名字）。比對前名稱做 NFKC、去頭尾空白、轉小寫。
- 每張圖分給名稱是它開頭的棋子：圖片名稱＝名稱 → 立繪候選；圖片名稱＝名稱＋分隔（`_` `-` `@` 空白 `(` `[`）＋差分名 → 差分
  （差分名去掉開頭的分隔與結尾的 `)` `]`）；**新版另外**：名稱＋2 位數以上的編號＋分隔＋差分名（本站「角色差分管理器」開編號時的輸出
  「名稱01_笑」）也是差分（5. D11）。**最長的名稱優先**（「艾莉絲_童年_笑」是「艾莉絲_童年」的差分）；一樣長的都算。
- 立繪：「沒有圖」→ 沒有；指定的 → 那一張；自動 → 和「立繪的名稱」同名的，沒有時和名稱同名的。
- 差分：手動的（與表格的差分欄；指定的圖，沒有時依圖片名稱 key 比對找）在前；開「自動當差分」時接上自動找到的（依圖片庫的順序，
  標籤 key 比對和前面相同的不重複）。

### 3.7 房間 ZIP（外部格式；原作 `roomdata.v1.js`，CCFOLIA 1.37.4 讀出、1.37.6 確認；新版 `output.ts` 經共用層 `@/ccfolia`）

```
__data.json   {"meta":{"version":"1.1.0"},
               "entities":{"room":{},"items":{},"decks":{},"notes":{},
                           "characters":{"<ID>":{ …棋子… }, …},
                           "effects":{},"scenes":{},"savedatas":{},"snapshots":{}},
               "resources":{"<圖片檔名>":{"type":"image/png"}, …}}
.token        「0.」＋64 個小寫十六進位亂數（共用層 newRoomToken；一定不等於 SHA-256(__data.json)）
<圖片>        ZIP 根目錄，檔名＝內容的 SHA-256（64 個小寫十六進位）＋「.」＋副檔名（png、jpeg、gif、webp）
```

- **只追加**（`createAppendRoomData`）：`room` 是 `{}`、其他類別空的，CCFOLIA 讀入時依 ID 寫入，只多出新的棋子；讀入的人是擁有者。
- 棋子：共用層的 `createRoomCharacter`（欄位順序與預設值照共用層：name、playerName、memo、initiative、externalUrl、status、params、
  iconUrl、faces、x、y、z、angle、width、height、active、secret、invisible、hideStatus、color、roomId、commands、speaking、diceSkin、order），
  寫入：名稱、備註、先攻值、參照網址、狀態（數值）、參數（標籤與值都空白的去掉；值是文字）、立繪（圖片檔名，沒有時 null）、
  差分（有圖的，`{ label, iconUrl }`）、寬＝高＝棋子大小（1～100）、放到盤面、狀態不公開、發言時不顯示立繪、不列入盤面的角色清單、
  顏色（不是 `#rrggbb` 時 #888888）、聊天面板（含共用的與差分的 @ 名稱）。
- **位置**：放到盤面的棋子依清單順序橫向排開：x＝前面同一列的棋子大小合計 × 24、y＝前面各列的高度合計 × 24（px；原點是盤面中央），
  8 個一列，一列的高度＝那一列最大的棋子大小。只放進角色清單的用共用層的待機位置 (490, 791)（5. D8）。
- `order`：**匯出當下的秒數（floor(毫秒 ÷ 1000)）＋序號**（之後讀入的排在後面）。ID：共用層 `newRoomEntityId()`（同一個 ZIP 不重複）。
- 圖片：同一張（同一個資產）只放一個檔；`resources` 與圖片檔一一對應（`buildRoomZip` 依引用重建）。ZIP 項目順序 `__data.json`（不縮排）、
  `.token`、圖片；寫完以 `checkRoomZip` 自我檢查。
- 上限 500 個棋子（原作：讀入時一次寫入；超過時不匯出）。

  （加了之後再檢查）。副檔名：JPEG 是 jpg，其他照格式（png、gif、webp）。只打包不壓縮。

- 自動儲存：localStorage `trpg-toolkit:ccfolia-batch`（資料版本 1）；圖片內容在 IndexedDB 的資產庫（`trpg-toolkit:tool:ccfolia-batch:assets`）；

## 4. 互動與手感

- 輸入、改讀法、改用途、改全體設定立刻重讀與重畫（同樣的輸入不重算）。
- 文字欄的連續輸入約 0.4 秒內算一步復原；確定、開專案檔、重來是獨立的一步。
- 清單的選取：清單變短時夾回範圍；鍵盤移動時那一列捲進清單的可見範圍（只捲清單）。
- 窄畫面（< 1024 px）上下排列（輸入在上）；390、360、320 px 寬沒有橫向捲動；清單的狀態排到名稱下面。
- 圖片拖到修改欄時修改欄醒目（主色框）。

## 5. 容易做壞的地方

- 讀法的規則有順序：特別的行（3.2.2）在項目之前；一行的整理（3.2.3）的步驟順序不能換（例：先保護括號裡的標籤，再去掉另一版的值）。
- 「說明的文字放進備註」預設關：CCFOLIA 的備註其他玩家看得到。「備註」「備考」小標是說明（不讀），只有「角色備註：」「メモ:」進備註（D5）。
- DB 的值要帶正負號，`{DB}` 才接得上骰子式（`1d3{DB}` → `1d3+1d4`）。
- 名稱的對應在顯示與匯出時才做，圖片庫改名、之後才加的圖都要對得上；複本的「立繪的名稱」是原本的名字。
- 房間 ZIP 的 `resources` 與圖片檔要一一對應、圖片檔名要等於內容的 SHA-256，否則 CCFOLIA 忽略那張圖或讀入失敗（交給共用層）。
- 匯出前要讀出每張圖的位元組（同一張只讀一次）；找不到內容時要說是哪一張。
