# 調查熱點圖（clue-map）行為規格

## 0. 概要

做一張可以「點」的調查 handout，給跑團的 KP 用：放一張場景圖（房間、遺體、地圖、角色立繪、調查板……），在上面畫出**熱點**（矩形或橢圓），
每個熱點藏著一則**線索**——一段文字（可以多段）、一張選填的線索圖片、一句選填的檢定提示（例如「圖書館使用 50%」）。
熱點可以設成「一開始就看得到」，或「先找到指定的其他熱點才出現」（一個就夠／要全部），也可以設成「隱藏熱點」（遊玩時不畫輪廓，點對位置才出現）。
PL 玩的時候點熱點就翻出**線索卡**，找到的線索集中在「已找到的線索」清單裡（可以回頭再看），並顯示進度「找到 N／M」；
KP 可以切換「顯示所有熱點的位置」，也可以按「重來」。

輸出：**互動 HTML**（單一檔案，PL 打開就能玩，不需要網路；也可以只取程式碼貼進能貼 HTML 的網站）、**分享連結**（開連結的人只看到遊玩畫面，給 CCFOLIA、Discord 用；
場景圖與線索圖都不是上傳的圖時才放得進網址）、**總覽 PNG**（場景圖加上所有熱點的編號，下面把全部線索、解鎖條件、檢定提示與 KP 備註攤開，KP 自己看）；
另有專案檔（ZIP，含圖片）與自動儲存。全部在瀏覽器裡處理，不上傳。

輸入：場景圖（選檔、拖放、貼上、網址、或內建的場景）、線索圖片（同上，每個熱點一張）、文字與設定。

**這是本站自己的構想，不是重寫某個工具。** 靈感來源：momo102938／콕콕（<https://momo102938.github.io/MUNgs_click/>；本機 `/home/user/upstream/momo102938_MUNgs_click/repo/`，commit `9de2685`）。
原作是「點角色身體的部位提高好感度、好感度到了才解鎖更多部位」的戀愛養成小遊戲，**沒有授權條款（未授權）**。本站只借它「圖上的熱區＋點了有反應＋達成條件才解鎖」的想法，
做成跑團用的調查 handout；**程式、介面文字、預設值、範例、圖片都自己做**，不放 `UPSTREAM_LICENSE`，第 1 節的來源欄標「新」，不需要和原作對等。
只參考了原作的兩個做法：熱區用百分比座標、編輯時拖曳＋滑桿調整大小（本站用共用的 `LayoutEditor`）；遊玩時熱區輪廓可以顯示／隱藏（本站做成每個熱點的「隱藏熱點」與遊玩畫面的「顯示所有熱點」）。
原作的好感度、表情圖、對白、玩家名字、伺服器分享（Cloudflare）、語言（韓文）都不移植。

用語：「場景」＝那張底圖；「熱點」＝場景上可以點的範圍；「線索」＝點到熱點之後看到的內容（文字、圖片、檢定提示）；「線索卡」＝顯示線索的那張卡；
「找到」＝PL 點過這個熱點（卡片翻開過）；「解鎖」＝熱點的出現條件滿足；「編號」＝熱點在清單裡的順序（從 1 開始）；
「%」＝相對於場景圖寬（X、寬）或高（Y、高）的百分比；「遊玩畫面」＝PL 看到的畫面（互動 HTML、分享連結、工具裡的「試玩」都是同一份）。

驗證方式：「自動」＝e2e（`web/tests/e2e/clue-map.spec.ts`）或單元測試（`web/tests/unit/clue-map-*.test.ts`）；「目視」＝截圖。
**來源欄全部是「新」**（沒有原作可以對照）。

## 2. 輸入

- **圖片**：PNG、JPEG、WebP、GIF（取第一格）、AVIF、BMP、SVG（瀏覽器讀得了的）。選檔、拖放、貼上（Ctrl＋V，焦點在文字欄時照常貼文字）。
  場景圖長邊 > 1600 px、線索圖 > 1024 px 時等比縮小再存（JPEG 存 JPEG 品質 0.92，其他存 PNG；不放大）。
- **圖片網址**：只收 `http://`、`https://`，去頭尾空白，最多 2000 字；其他一律拒絕（含 `javascript:`、`data:`）。分享連結讀回時也檢查。

### 3.1 資料模型（自動儲存、專案檔、復原的對象）

```
{
  title, intro,
  scene: { kind: 'builtin', id: 'study' | 'paper' | 'board' }
       | { kind: 'asset', id, name, width, height }      // 圖片庫的圖
       | { kind: 'url', url, name },
  spots: [ {                                              // 順序＝編號＝疊放（後面的在上面）
      id,                                                // 'h' ＋ 6 個小寫英數字，專案內不重複
      name, shape: 'rect' | 'ellipse',                   // name 空白時顯示「熱點 N」
      x, y, w, h,                                        // 相對於場景圖的 %，0～100，取到小數 2 位
      text, check, memo,
      image: null | { kind: 'asset', … } | { kind: 'url', … },
      locked: boolean,                                   // 開啟出現條件（關閉時 requires 保留但不作用）
      requires: [id…],                                   // locked 且非空才有條件，否則一開始就看得到
      mode: 'all' | 'any',
      hidden: boolean
  } ],
  look: { theme: 'dark' | 'light', marker: 'outline' | 'pin' | 'none', accent, foundColor,
          foundMark: 'both' | 'check' | 'color' | 'none', names: boolean,
          progress: 'count' | 'found' | 'off', reveal: boolean }

```

- 讀回時一律整理（自動儲存可能缺欄位或被改壞）：數值夾到範圍、選項不認得用預設、字串截到上限、圖片參照只收合格的、

- 專案檔：共用專案檔格式（`format: 'trpg-toolkit-project'`、`tool: 'clue-map'`、`version: 1`、`data`＝上面的內容）；存出來一律是 ZIP（`project.json`＋`files/<圖片代號>.<副檔名>`，沒有圖片時只有 `project.json`，共用 ProjectMenu 的做法）；讀的時候 ZIP、JSON 都可以。

  （標題經共用的 `safeFileName`，最長 40 字，不能用的字元換成「_」）。

### 3.2 遊玩畫面的結構（互動 HTML 與工具裡的試玩是同一份）

互動 HTML 的程式碼是一段可以貼進網頁的 `<div>`＋`<style>`＋`<script>`，樣式都以元件自己的 id（`#cm-xxxxxxxx`，每次產生都不同）為範圍；
獨立 HTML 檔是把這段放進一個最小的網頁（置中、淺灰底）。程式（引擎）是工具裡同一個函式 `mountClueMap` 的原始碼，**原樣**放進 `<script>`，不依賴任何外部資源。

```
div.cm[data-cm=root][data-theme][data-marker][data-found-mark]
├ header.cm-head: h2.cm-title, p.cm-intro
├ div.cm-bar: span.cm-progress[role=status], span.cm-note[role=status], div.cm-tools: button.cm-reveal[aria-pressed], button.cm-reset
└ div.cm-main
   ├ div.cm-scene[data-cm=scene]: img.cm-img, button.cm-spot[data-spot][data-state=ready|found|locked][data-hidden]… （順序＝編號）
   └ aside.cm-side
       ├ section.cm-card[data-cm=card][aria-live=polite]（空狀態／線索卡）
       └ section.cm-found[data-cm=found]: h3, ol > li > button
```

- 熱點按鈕定位：中心 `left/top`＝中心的 %，`width/height`＝% 大小（就是熱點本身的大小，沒有最小尺寸），以中心對齊（`translate(-50%, -50%)`），`pointer-events: none`。
  點擊範圍是按鈕的 `::before`：置中、`width/height: 100%`、`min-width/min-height: 28px`、`pointer-events: auto`，橢圓的 `clip-path: ellipse()` 也放在 `::before` 上（所以小橢圓的點擊範圍是 28 px 的橢圓）。
  輪廓、圓點、編號、打勾（`.cm-ring` 等）的大小與位置只依按鈕本身，不受 28 px 影響；鍵盤焦點框（`:focus-visible::after`）和點擊範圍一樣大（至少 28 px）。
- 狀態：`data-state="ready"`（看得到、還沒找到）、`"found"`、`"locked"`（還沒解鎖）。還沒解鎖又不在「顯示所有熱點」時按鈕有 `hidden` 屬性（不在畫面、點不到、不在 Tab 順序）；「顯示所有熱點」時畫成灰色虛線，`title` 寫「尚未解鎖：先找到 …」，游標不變；點到它時引擎把點擊轉給下面第一個看得到的熱點（`elementsFromPoint`，由上到下；鍵盤或程式呼叫的 click 沒有指標位置〔`detail` 是 0〕，不轉），沒有就沒有反應。
- 隱藏熱點 `data-hidden="1"`：沒找到時 `opacity:0`、`tabindex=-1`、`aria-hidden="true"`、游標預設；找到後正常顯示。
- 顏色：`--cm-accent`、`--cm-found` 由設定帶入，其餘由 `data-theme` 決定（深色底 `#15181d`、面板 `#1e232a`、文字 `#e8e6e1`；淺色底 `#f4f1ea`、面板 `#ffffff`、文字 `#1f2328`）。
- 字型：`"Noto Sans TC","PingFang TC","Microsoft JhengHei",sans-serif`（有裝的就用，不載入字型）。
- 所有使用者的文字一律用 `textContent` 放進畫面；放進 `<script>` 的 JSON 把 `<` 換成 `<`（字串裡有 `</script>` 也不會提早結束）。
- 圖片放在一張圖片表（陣列）裡，同一張只放一份，熱點與場景用索引；開頁時由程式填進 `img.src`。
- 設定（`config`）內容：標題、導言、場景圖索引與替代文字、熱點陣列（編號、代號、名稱、形狀、%、文字、檢定提示、圖片索引、出現條件、隱藏）、遊玩設定（F50～F56）、所有介面文字（引擎本身不 import 任何東西，文字由設定帶入）、進度的儲存鍵。

### 3.3 引擎的行為（規則）

- 狀態只有「找到的代號集合」（依找到的順序）。熱點**看得到**＝已找到，或（沒有出現條件，或條件成立）；條件成立＝`all`：要求的熱點全部已找到；`any`：至少一個已找到。
- 點擊：熱點看得到才反應。每次找到新的熱點後重算誰新出現，通知數量只算「新出現而且不是隱藏」的。
- 進度 M＝全部熱點數，N＝已找到數。完成＝N ＝ M（M ＝ 0 時不算完成）。
- 重來：清集合、關卡片、關「顯示所有熱點」、清儲存。
- 「已找到的線索」清單的項目只增不減（重來時才全部拿掉）：找到新的熱點時新項目接在最後，開線索卡只更新 `aria-current`，不重建項目（鍵盤的焦點才不會掉）。
- 儲存：`{ v: 1, found: [代號…] }`，存讀都包 try/catch；讀回時只收存在的代號。

## 4. 互動與手感

- **編輯**：設定即時套用；文字欄從聚焦到離開算一步復原，單行欄位按 Enter 離開；拖曳／調整大小一次一步；其餘變更合併 400 ms 內的連續操作。
- **舞台**：預設符合畫面；熱點的輪廓與控點維持固定的螢幕大小（縮放時不變粗）；拖曳時顯示共用的參考線與距離（左／右、上／下 %）；
  選取中的熱點在最上層。畫熱點時游標變十字；拖曳過程中有即時的虛線框。
- **畫面**：390 寬時舞台在上、設定在下，沒有橫向捲動；遊玩畫面窄版面時線索卡出現在場景下方，點熱點後捲進畫面（`scrollIntoView` ＋ `block: nearest`，減少動態時不平滑）。
- **動態**：看得到的熱點輪廓每 2.4 秒輕輕呼吸一次（透明度 0.65 ↔ 1）；新解鎖的熱點淡入 0.4 秒；從清單回到場景時熱點閃 0.8 秒；全部在「減少動態」時關閉。
- **焦點**：新增或畫出熱點後名稱欄取得焦點，聚焦時不捲動頁面（`focus({ preventScroll: true })`：手機上設定欄在舞台下面，捲過去會讓剛畫出的熱點離開畫面）；Esc 與關閉鈕在遊玩畫面關線索卡並把焦點還給熱點或清單項目（清單項目打開的，焦點一直留在那一項）。
- **快捷鍵**：見 F96。
- **預設**：範例（3.7）；遊玩設定見 F50～F56；編輯舞台背景深色；輸出倍率 1×。
- **儲存**：自動儲存鍵 `trpg-toolkit:clue-map`；預覽偏好（舞台背景、輸出倍率）另存 `trpg-toolkit:clue-map:preview`，不列入復原；遊玩進度鍵 `trpg-toolkit:clue-map:progress:<內容指紋>`（只在互動 HTML 與分享連結）。

## 5. 容易做壞的地方

- **引擎只有一份**：試玩、分享連結、互動 HTML 用同一個 `mountClueMap`（匯出時 `toString()` 原樣放進 `<script>`），所以這個函式**不可以用到函式外面的任何東西**
  （import、模組層的常數與函式；型別在編譯時會拿掉，可以放外面）；介面文字、圖片網址、設定都從 `config` 帶入。單元測試要把它的原始碼拿出來在乾淨的環境執行過。
- **出現條件的規則在三個地方都要一樣**：引擎（遊玩）、`model.ts` 的 `isUnlocked`／`unreachable`（編輯的警告）、總覽 PNG 的標籤；改規則要三處一起改，單元測試用隨機資料比對引擎與 `isUnlocked`。
- **隱藏熱點不能洩漏**：沒找到時不畫輪廓、不在 Tab 順序、`aria-hidden`、游標不變；試玩與輸出的 HTML 裡 `data-hidden` 的按鈕是透明的，但**點得到**。
  （HTML 檔的原始碼裡仍看得到所有線索與座標，這是純前端的限制，對話框說明「會看原始碼的 PL 看得到全部」，D7。）
- **KP 備註不輸出**：互動 HTML、分享連結、遊玩畫面的設定物件裡一律沒有 `memo`；單元測試檢查。
- **座標是百分比、點擊範圍用最小尺寸**：編輯與遊玩用同一套 % 座標；遊玩時熱點小於 28 px 的點擊範圍從中心撐大（按鈕的 `::before`），視覺輪廓不跟著變大（不能把 `min-width` 放在按鈕上，輪廓會跟著變大）。橢圓用 `clip-path` 限定點擊，放在 `::before` 上（放在按鈕上會把小橢圓的點擊範圍切回熱點本身的大小）。
- **刪除熱點要清出現條件**：不能留下指向不存在代號的條件；條件清空後是「一開始就看得到」。讀回的資料（專案檔、分享連結）也要整理。
- **永遠不會出現的熱點**：循環等待（A 等 B、B 等 A）、等一個永遠不出現的熱點，都要在編輯時警告，否則 PL 會永遠找不到、進度永遠到不了 M。
- **上傳的圖片放不進連結**：不能悄悄丟掉圖片；停用並說明（scratch-card 同）。
- **同一批的通知合成一則**：一次放好幾張圖時，「已加入」「不是圖片」「讀不了」「存不進瀏覽器」寫在同一則。
- **開頁的圖片整理不能刪掉讀到一半的圖**：用共用的 `gcStale`。
- **試玩時重新掛載不能丟進度**：設定一變引擎會重建，進度（找到的代號）放在工具的狀態裡帶回去。
- **文字跳脫**：標題、導言、名稱、線索文字、檢定提示一律 `textContent`；`<script>` 裡的 JSON 跳脫 `<`、U+2028、U+2029。
- **調整大小超出場景要「切掉」，不是「推進去」**：把位置夾回場景內時寬度不變，會讓框被往內推、對邊跟著跑；拉控點時用 `trimBox`（超出的部分切掉、對邊不動），移動與數值欄才用 `clampBox`（單元測試）。
- **復原的合併**：共用的 store 把 400 ms 內的連續變更併成一步；拖曳、文字欄、清單排序用手勢（`beginGesture`／`endGesture`）包成一步；e2e 裡兩次修改的間隔要 ≥ 450 ms。
- **新增熱點後名稱欄要拿到焦點**：設定欄可能還停在別的分頁，名稱欄是新掛上去的元件，所以要記「要聚焦哪個熱點的名稱欄」，掛上時才聚焦（不能只靠數字有沒有變）；聚焦用 `preventScroll`，不然手機上頁面會捲到名稱欄、舞台離開畫面。
- **清單不整個重建**：「已找到的線索」清單開線索卡時重建整個清單，鍵盤使用者按下的那顆按鈕就被拿掉、焦點掉到頁面上（F72）；清單項目要保留，只更新 `aria-current`。
- **還沒解鎖的灰色熱點不擋下面的熱點**：它只負責滑過的說明；點擊由引擎用 `elementsFromPoint` 轉給下面看得到的熱點（F66）。
- **試玩切回來要帶回最新的進度**：切到編輯再切回試玩時要重新算設定（`initialFound` 等），不能沿用上一次的。
