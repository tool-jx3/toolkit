# 劇本排版台（scenario-editor）行為規格

## 0. 概要

在瀏覽器裡寫 TRPG 劇本、同時排成 A4 書頁的編輯器。原稿是一串「段落」：每個段落有一種書式（描述文、對話文、規則框、
標題 1～3、主標題、表格、NPC 卡、流程圖、圖片、彈出視窗、目錄、封面、版權頁…），左邊逐段書寫，右邊即時排成 A4 紙面，
超出版心的段落自動送到下一頁（段落不會被切開）。頁面以頁為單位設定單欄／雙欄與背景，段落可以設成跨欄或在欄內流動。
描述文、注釋、規則框裡可以用行首記號放入條列、小標、表格、對話、巢狀檢定框與彈出視窗按鈕；文字可以加注音、註解與顏色。
NPC 卡支援 Emoklore TRPG、Double Cross 3rd、克蘇魯神話 TRPG（第 6／7 版），能自動計算衍生數值、輸出成 CCFOLIA 棋子，
也能讀回 CCFOLIA 棋子與 Yutosheet 的效果／組合技表。輸出有三種：瀏覽器列印（可另存 PDF）、附目錄與彈出視窗的閱覽用 HTML、
原稿 JSON 檔。原稿（作品）可以有很多份，自動存在瀏覽器裡，保留過去的版本，刪除的作品在垃圾桶放 30 天。

靈感來源：sedn14636361/trpg-scenario-editor（<https://github.com/sedn14636361/trpg-scenario-editor>）。原作以 CC0 1.0 釋出：
範例原稿、規則框的樣板、NPC 卡的系統資料（能力值、技能、症候群…）可以沿用（介面文字改寫成繁中）。

名詞：「段落」＝原稿裡的一個區塊；「串列」＝一列段落（紙面本文、彈出視窗的內容、表格某一格的內容都各是一個串列）；
「紙面」＝排好的 A4 頁面；「版心」＝紙面扣掉上下、左右間距後放文字的範圍；「文字欄」＝逐段書寫的清單；
「設定欄」＝目前選取段落的設定；「作品」＝一份原稿。

## 1. 功能清單（對等驗證以此為準）

按鈕與欄位的名稱是本規格自己的描述，新版的介面文字照 DESIGN.md 用詞表自訂。「舊版」指 `tools/scenario-editor/`（上游 v3.3.0 的收錄版）。

## 2. 輸入

### 2.1 原稿檔

- JSON 檔（UTF-8，可有 BOM）。新版自己的檔案見 3.1.2；舊版存的檔案是原稿物件本身（有 `pages` 或 `blocks` 的物件），照 3.1.3 讀入。
- 不是 JSON、或沒有 `pages`／`blocks` 的物件：顯示「這不是劇本排版台的原稿」之類的錯誤，作品不變。

### 2.2 圖片

`image/*`。讀不出尺寸的（例如瀏覽器不支援的格式）照原檔以 data URL 存入、長寬比未知。背景圖不縮小（超過 2.5 MB 先確認）。

### 2.3 字型

.ttf、.otf、.ttc、.otc、.woff、.woff2，40 MB 以內。TTC／OTC 是多個字體的集合：只有一個時直接取出、多個時讓使用者選。
名稱讀自字型的 name 表（家族名稱或完整名稱，Windows 平台優先；新版：繁中名稱 → 英文名稱 → 檔名）。

### 2.4 CCFOLIA 棋子 JSON、Yutosheet 表格

見 3.7.4、3.7.6。

## 3. 輸出

### 3.1 原稿（文件模型）

#### 3.1.1 內容

一份原稿有：劇本名稱、上下／左右間距（mm）、內文字級（pt）、頁尾設定（頁碼開關、固定文字、第一頁頁碼）、嵌入的字型
（名稱＋data URL）、內文字型、標題字型、自己做的規則框樣板、頁面設定（每頁：單欄／雙欄、花紋、背景圖 data URL、大小、濃度）、
段落串列。段落有：id、書式、文字、雙欄時的配置（全寬／欄內）、縮排（0～4）、上／下間距（mm 或預設）、整段文字顏色、
解除文繞圖、註解（第幾字到第幾字＋內容）、文字顏色（第幾字到第幾字＋顏色）、目錄設定（寫法、收錄方式、層級），
以及各書式的資料：對話文的說話者、規則框的外觀與標題語、圖片（data URL、長寬比、寬％、說明、配置、位移、自由配置的位置與頁、
文字排法）、表格（3.6.3）、彈出視窗（名稱、不放在紙面、內容段落串列或舊式文字）、流程圖（3.6.5）、NPC 卡（3.7）、目錄（3.6.1）。

#### 3.1.2 新版的檔案

`{ "format": "trpg-toolkit-project", "tool": "scenario-editor", "version": 1, "savedAt": ISO 時間, "data": 原稿 }`。
原稿的欄位名稱沿用舊版（CC0），所以 `data` 也能直接當舊版原稿讀。

#### 3.1.3 讀入舊版原稿的整理

照舊版的規則補齊與轉換，讀進來的外觀不變：
- 數值欄補預設：間距 18／16、字級 10、頁尾 `{num:true,text:'',from:1}`；字型只留有名稱與資料的；樣板只留有名稱的（名稱最多 24 字）。
- 很舊的「段落放在頁面裡」的格式：攤平成一串，頁與頁之間插入換頁；有目錄旗標的頁面在開頭插入目錄。
- 舊的「條列」書式改成描述文，每行加上 markdown 記號（`- `、`1. `、`- [ ] `，行首每 2 個半形空白一層、最多 3 層）。
- 舊的「技能判定」「特殊規則」書式改成規則框並套用對應樣板（標題語保留）。
- 行首的舊記號一次改成 markdown 寫法：`□`→`- [ ] `、`・`→`- `、`＞`→`> `（註解與顏色的位置跟著移動），原稿記下已改過（`mdv`）。
- 表格的舊格式（字串二維陣列 `cells`／`seed`）轉成每格的段落串列。
- 流程圖沒有圖資料時從文字轉換（3.6.5）。
- 圖片補齊配置、位移、頁、寬（70）、文字排法（避開）。NPC 卡補齊所有欄位（3.7.1）。
- 沒有頁面時補一頁；沒有段落時用範例原稿的段落。

#### 3.1.4 範例原稿

新作品的內容：名稱「未命名的劇本」、間距 18／16、字級 10、第一頁花紋「紙紋」；段落：主標題「未命名的劇本」、副標題「克蘇魯神話 TRPG　劇本」、
標題 1「導入」、描述文（說明左邊寫、右邊排）、對話文「「首先，請試著點一下這個段落」」、規則框（技能檢定樣板）「〈偵查〉成功的話，會發現黏在桌子背面的信封。」。

### 3.4 巢狀書式與文字

#### 3.4.1 行首記號（描述文、注釋、規則框、舊式彈出視窗的文字、NPC 卡不適用）

逐行判斷（彈出視窗的舊式文字另外接受 `#`／`##`／`###` 標題）：

| 記號 | 結果 |
|---|---|
| `■` 或 `◆` | 小標（0.92 em 粗體、左邊 2.5 px 線、框的顏色） |
| `◇` | 次小標（0.9 em 粗體） |
| `※` 或 `＊` | 注釋（0.84 em、灰褐、左邊 2 px 線；連續的行合成一塊） |
| `>` 或 `＞` | 巢狀檢定框（虛線框、淡底）：第一行冒號（`：` 或 `:`）前是框的小標、之後是內容；沒有冒號時小標是「技能檢定」；連續的 `>` 行合成同一框 |
| `＠名稱` 或 `@名稱` | 彈出視窗按鈕（F112） |
| `- [ ] `、`- [x] `、`□` | 選項條列（□／☑） |
| `- `、`* `、`+ `（後面要有空白）、`・` | 條列（第 0 層「・」、其他層「‣」，朱色記號） |
| `1. `、`2)`、`3．`、`4）` | 編號條列（第 0 層顯示寫的數字＋「.」，其他層「‣」） |
| 記號前的空白 | 半形 2 個（全形 1 個、Tab 2 個）為一層，最多 3 層（每層 1.6 em） |
| `\|…\|` 的行 | 表格：連續的行合成一個表格，第 1 行是標題；`\|---\|---\|` 這種分隔行略過；全形 `｜` 也可以 |
| 整行是 `「…」`／`『…』`（前面可有 1～10 字的名字） | 對話（名字為說話者，小字在上） |
| 其他 | 一般文字；空行把文字分成段 |

同一種條列連續的行合成一個清單；換成別種記號就結束上一種。

#### 3.4.2 注音

`｜本文字《注音》`（`｜` 可為半形 `|`；本文字與注音都不含換行與 `｜《》`）顯示成注音（上方 0.5 em）。沒有 `｜` 的《》照原樣顯示。
目錄、頁面一覽、alt 文字等地方去掉注音只留本文字。

#### 3.4.3 註解與文字顏色

以「第 a 字到第 b 字」記錄。文字改動時，依「與改動前相同的開頭」「與改動前相同的結尾」找出改動範圍：
範圍前的位置不變、範圍後的位置平移，在範圍裡的起點移到範圍開頭、終點移到插入文字的結尾，長度變 0 的刪除。
同色的重疊或相鄰段合併。顏色範圍與註解可以重疊（分界處切開後逐段套用）。

#### 3.4.4 巢狀書式按鈕的套用（有選取範圍時）

- 對話：選取範圍整個用「」包起來；已經包起來的拿掉。
- 彈出視窗：選取的文字換成「＠選取的文字」（換行改空白）。
- 表格：選取範圍擴到整行，每行用 `|` 包起來；全部都已包起來時拿掉。
- 其他：擴到整行；所有非空行都已是同一種記號（同樣的前置空白）時拿掉記號，否則換成該記號（舊記號先拿掉；編號依序 1、2、3…；檢定框只有第一行寫小標、其他行用 `＞`）。
- 沒有選取範圍時：在游標處插入記號（不在行首時先換行）；對話時游標放進「」之間。

### 3.6 書式的資料與輸出

#### 3.6.1 目錄

#### 3.6.3 表格

- 條列：一個框（1.2 px、圓角 1 mm），每列一段、段間橫線：「編號：標題」一行（標題粗體、右下兩邊細框線）＋第 3 欄以後的內文（縮 1.6 em）。欄標題開著時第 1 列不顯示。
- 標題框：每列一個框（1.2 px、圓角），第 1 欄的題名浮在框線上（紙色底），第 2 欄以後是內容；超過 2 欄時每段內容前加該欄的欄名（第 1 列的文字，小字）。框間 3.2 mm。
- 名稱：1.05 em 粗體、字距 0.1 em，在表格上方。

#### 3.6.4 表格的輸出文字

- **roll-table**（CCFOLIA 的 `/roll-table`）：
  ```
  /roll-table
  名稱（空白時「表」）
  骰子算式（空白時 1D 列數）
  骰值:結果
  …
  ```
  列＝（欄標題開著時去掉第 1 列）有任何非空格的列；第 1 欄是數字或「數字-數字」（`-` `–` `〜` `～`，空白拿掉）時當骰值、其餘欄是結果，否則骰值依序 1、2、3…、全部欄是結果；
  結果的格以全形空白（條列外觀用換行）接起來，結果裡的換行寫成 `\n`。
- **簡單文字**：名稱一行（有的話）＋每列一段：格線且有 2 欄以上的欄標題時「欄名：值」以「／」接起來（沒有欄名的直接寫值）、每列一行；
  其他外觀「■第 1 欄」換行接其他欄（每欄一行），列與列之間空一行。
- **自己寫**：照輸出欄的文字。
- 匯出 HTML 的「複製輸出」：自己寫的文字不是空白時用它，否則用 roll-table。

#### 3.7.4 讀入 CCFOLIA 棋子

- 解析：整段是 JSON，或取第一個 `{` 到最後一個 `}`；`data` 是物件就用它，否則整個物件；要有 name、params、status、commands 其中之一。
- 判斷系統：參數有「肉体」與「感覚」或狀態有「侵蝕率」→ DX3rd；參數有「身体」「五感」「運勢」之一 → Emoklore；參數有 STR／CON／EDU 或狀態有 SAN → 克蘇魯；都不是時報告無法判斷（名字等仍會填入）。
- 名字：`名字 (讀音)`（半形或全形括號）拆成名字與讀音；memo 每行「標題: 值」：讀音類（ふりがな／フリガナ／よみ／読み／ヨミ）→讀音、`共鳴感情・表／裏／ルーツ`→共鳴感情，其他行以空白接成立場。
- 數值只收數字（可有正負號與小數）；狀態取 max（沒有時 value）。
- Emoklore：能力值、HP、MP、強度（參數）、初始共鳴等級（狀態「共鳴」的 value）、共鳴感情（`感情(屬性)`，屬性由名稱或感情反查）；指令 `NDM<=值 〈名稱〉` 或 `【名稱】`：名稱含 ＊ 的是基本技能（記判定值），其他成為習得技能（認得的技能補類別與種類，最多 24 列）；`{` 開頭或目標是變數的行略過；`//` 以外讀不懂的行計數。
- DX3rd：能力值、行動値、HP、侵蝕率、シンドローム（依數量決定血統）；`// コンボ：名稱 / … / 攻撃力X` 成為組合技（第一個不是攻擊力的段是命中）；其他 `// [種類] 名稱 LvN / 時機` 成為效果；`NdxM 【技能:種類】` 填技能（認不得的計數）；有讀到才取代原本的清單。
- 克蘇魯：有 `CCB<=` 且沒有 `CC<=` 時第 6 版，否則第 7 版；能力值、BLD、MOV、HP／MP／SAN、幸運；`1d3+X 【ダメージ判定】` 的 X 填 DB（DB 原本空白時）；
  `CC(B)<=值` 或 `1d100<=值` 加 `【名稱】`：能力值檢定略過，アイデア／知識／幸運填衍生值（變數參照的不取），其他成為技能（清單裡有的照原名、`名稱:種類` 或 `名稱（種類）` 拆開、清單沒有的當自己輸入），最多 12 列，超出的數量另外報告。
- 每次讀入都會改成棋子的系統。

#### 3.7.5 數值欄的候選

Emoklore 能力值 1～6、Lv 1～3、共鳴 1～9；DX3rd 能力值 1～12、技能與常備化 0～20、侵蝕率 0～100（每 5）、HP 10～80（每 5）；
克蘇魯第 6 版 STR／CON／POW／DEX／APP 3～18、SIZ／INT 8～18、EDU 6～21；第 7 版 STR～APP 15～90、SIZ／INT／EDU 40～90（每 5）；技能 0～100（每 5）；
DB −2、−1、0、+1D4、+1D6、+2D6、+3D6；體格 −2～4；MOV 5～12；傷害 1D3、1D4、1D6、1D8、1D10、2D6、1D3+DB、1D4+DB、1D6+DB。

#### 3.7.6 讀入 Yutosheet 的表格

每行：去掉 Tab、頭尾空白與行首行尾的 `|`／`｜`，以 `/` 切開、每段去頭尾空白並把 `<br>`（含跳脫寫法）換成換行、還原 `&amp; &lt; &gt; &quot;`；
少於 5 段、第一段空白、或第一段是「コンボ名／種別／名称／エフェクト名」（標題行）的略過。
自動判斷：第 2 段含〈或《而且含 + 或 ＋ 的列算組合技、第 3 段是 1～2 位數字或第 1 段是效果種類名稱的算效果，組合技 ≥ 效果時當組合技表。

### 3.14 作品的存放

- 作品清單的每一項：id、標題、更新時間、大小、最後存成檔案的時間、過去的版本（時間、大小）、刪除時間（在垃圾桶時）。

- 新版存放在 IndexedDB `trpg-toolkit:tool:scenario-editor`（`works`＝作品清單、`doc:<id>`＝原稿 JSON 字串、`gen:<id>:<時間>`＝過去的版本、
  `legacy`＝已接收的舊版作品、`pdf-font:<網址>`＝PDF 用的字型檔）；舊版的 `trpg-typeset` 只讀不改（F018）。
- localStorage：`trpg-toolkit:scenario-editor:current`（上次開的作品）、`…:journal:<id>`／`…:journal-meta:<id>`（關閉瞬間的備份）、
  `…:single`（沒有 IndexedDB 時的原稿）、`…:bxtpl`（這個瀏覽器記住的樣板；舊版的 `trpg-bxtpl-v1` 也讀）、`…:preview`（頁面一覽的開關與縮圖寬、設定欄保持開著）。
- 鎖：Web Locks `trpg-toolkit:scenario-editor:edit:<id>`；沒有 Web Locks 時 BroadcastChannel `trpg-toolkit:scenario-editor` 只做提醒。

### 3.15 對等驗證的比對方法

- **原稿資料**：同一份原稿（含舊版存的 JSON 檔）在兩邊開啟後存檔，比對 `data`（新版）與舊版檔案的段落欄位（id 可不同的地方：新建與貼上的段落）。
- **紙面**：同一份原稿在兩邊以 100％ 截圖並排（字型差異：新版預設 Noto Serif TC），比對分頁結果（每頁的段落 id）、段落間距、各書式外觀；分頁以「每頁放了哪些段落」逐頁比對，
  允許因字型寬度造成的換行差異（以兩邊都用同一個嵌入字型的原稿比對時須一致）。
- **輸出文字**：roll-table、簡單文字、CCFOLIA 棋子 JSON、複製文字、字數，同樣的輸入逐字比對。
- **讀入**：同一段 CCFOLIA 棋子／Yutosheet 文字讀入後比對卡片資料與狀態列報告。

- **作品管理**：兩個分頁、垃圾桶（改系統時間）、版本、關閉瞬間的備份以 Playwright 操作比對狀態。

## 4. 互動與手感

- 自動儲存：最後一次修改後 0.7 秒；持續修改時從第一次修改起 3 秒內一定寫一次。關閉時的備份在 `pagehide`／分頁隱藏時寫入。
- 復原：每一步是一次自動儲存點（0.7 秒的停頓）之間的所有修改；最多 60 步。
- 打字時紙面約 0.26 秒後重排；文字欄正在打字的列不被重畫（游標不跳）。
- 選取時紙面只在段落看不到時才捲動，捲到從上方約三成的位置，並閃一下（0.7 秒）。
- 縮放倍率 25～300％；「配合寬度」依紙面欄的寬度計算（15～200％）。
- 流程圖拖曳：每 0.5 mm 吸附，Alt 自由；編輯視窗開啟時依視窗寬決定倍率。
- 作品清單在啟動時顯示，已選取目前的作品、焦點在「開啟」。
- 開頁預設：顯示「全部」、頁面一覽關（記住上次）、縮放 100％。

## 5. 容易做壞的地方

- **段落不切開**：分頁一律以整個段落為單位；一頁連一個都放不下時硬放一個，否則會無窮迴圈。
- **頁首的間距歸零**要在量測溢出之前套用，否則分頁結果不同；封面例外。
- **間距重疊**：前一段的下距與這一段的上距只留較大的（3.2.4），不是相加。
- **雙欄的溢出**是往右超出，不是往下；量測要看右邊與下邊兩個方向，也要排除自由配置的圖片。
- **註解與顏色的位置**是字數區間，任何改寫原稿文字的地方（打字、巢狀書式按鈕、改名、記號遷移）都要經過 3.4.3 的平移，否則會錯位。
- **注音的判斷**要用不帶全域旗標的比對（舊版曾因殘留狀態使注音時有時無）。
- **條列的 `-` 後面要有空白**才算記號（`-5度` 是一般文字）；選項要比條列先判斷。
- **表格每格至少一個段落**；增減列欄時其他格的內容要跟著重新對應位置。
- **彈出視窗不能搬進自己（或孫層）裡**。
- **改彈出視窗的名稱**要同步改寫指向它的「＠名稱」行。
- **ID 要全部換新**：複製、貼上段落時連巢狀的段落、流程圖的方框與線都要換新 id，否則改副本會改到原本的。
- **輸入法選字中的 Enter** 不是分段；選字確定後約 60 毫秒內的 Enter 也略過。
- **NPC 卡的手動值優先**：自動計算只在欄位空白時顯示；CCFOLIA 輸出用「手動或自動」的值。
- **CCFOLIA 指令裡的日文字串**（正気度ロール、アイデア、ダメージ判定、コンボ、シンドローム、行動値、侵蝕率、共鳴、強度…）是格式的一部分，讀回棋子時也靠它們，不能翻譯。
- **舊原稿的接收**（F018、3.1.3）不能改壞外觀：記號遷移只做一次（`mdv`）。
- 以下為**舊版的問題或新框架上的做法差異（刻意差異，需主控確認）**，括號內是建議做法：

- **F233 下載 PDF 是空白頁**：量測用的容器是 `visibility:hidden`，`core/paged/pdf.ts` 的 `paintElement()` 把它整個略過——修正（共用模組要能畫隱藏容器裡的內容，或改用不靠 visibility 的離屏做法），並補一個解析 PDF 文字的 e2e（每頁都有文字、能選取）。**缺字**：PDF 用的字型沒有的字（例如 NPC 卡系統資料的日文漢字「検」「覚」「撃」「渉」「歳」）要用備援字型補上（例如 Noto Serif JP／Noto Sans JP 的子集，經 `core/fonts` 取得），不能缺字或變豆腐——修正。字型下載失敗時的錯誤說明照規格。
