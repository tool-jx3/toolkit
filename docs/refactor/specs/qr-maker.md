# QR Code 產生器（qr-maker）行為規格

## 0. 概要

把網址或文字做成**有樣式的 QR code**：點的形狀與顏色（單色或漸層）、三個角的外框與中心各自的形狀與顏色、背景（單色、漸層、透明、圓角或圓形）、
中間放 Logo 或角色頭像、整體做成圓形；匯出 PNG、JPEG、WebP、SVG，或直接複製圖片。跑團的用途：劇本販售頁、handout 上的線索、
角色卡或角色社群帳號的連結、團報與宣傳圖。產生後**自動讀一次**（照每一格的顏色讀回內容），讀不出來、對比太低、定位方框太淡時提醒。
設定與圖片只存在這個瀏覽器，**不會上傳**。

輸入：內容（文字、網址；中文、表情符號以 UTF-8 編碼）、樣式設定、中間的圖（選填）。輸出：PNG／JPEG／WebP（點陣，可以放大 1～4 倍）、
SVG（向量，圖嵌在檔案裡）、剪貼簿（PNG）、專案檔（JSON；有圖時 ZIP）。

靈感來源：QCS＝**kozakdenys/qr-code-styling**（<https://github.com/kozakdenys/qr-code-styling>，npm 套件 v1.9.2；讀的是 `43d4171`，2025-04-11）。
原作是**程式庫，不是工具**：選項（README 的 options、`src/core/QROptions.ts`）與畫法（`src/core/QRSVG.ts`、`src/figures/`、`src/tools/calculateImageSize.ts`、
`sanitizeOptions.ts`、`getMode.ts`）是功能的依據。原作附的 demo 網站（qr-code-styling.com）在本環境連不到（代理拒絕連線），
所以介面由本站設計（D1）。

授權：MIT。畫點、角、漸層、中間的圖、圓形外圍補點的演算法與數值、預設值照原作改寫成 `@/core/qr`（共用模組，id-ticket 也用它編碼）；
授權全文在 `web/src/tools/qr-maker/UPSTREAM_LICENSE`。README 的範例圖（Facebook、Telegram 等）不拿；介面文字、說明、外觀預設、範例內容本站自己做。
編碼用已經在相依裡的 `qrcode-generator`（MIT）。

**和既有工具的差別**：證件與票券產生器（id-ticket）在卡片背面畫一個黑白的 QR code（固定等級 M、方塊），是卡片的一部分；
這個工具專門做 QR code 本身的樣式與檢查。兩者共用 `@/core/qr` 的編碼（id-ticket 的 `qr.ts` 搬進 `core/qr`，輸出不變）。

用語：「格」＝QR code 的一個模組；「點」＝深色的格畫成的形狀；「角」＝三個角的定位圖案（7 × 7 的外框＋3 × 3 的中心）；
「版本」＝格數（第 v 版＝(4v＋17) × (4v＋17) 格）；「等級」＝錯誤更正等級；「碼字」＝8 位元的資料單位（錯誤更正以碼字為單位修正）。

## 1. 功能清單（對等驗證以此為準）

## 2. 輸入

- 內容：任何文字（最多 7089 字；實際放得下多少看模式與等級，第 40 版 L 的位元組模式是 2953 位元組）。
- 中間的圖：瀏覽器解得開的圖片（PNG、JPEG、WebP、GIF、AVIF、BMP、SVG）；長邊超過 2048 px 時縮小（JPEG 存 JPEG、其他存 PNG）。
  讀不了的檔案通知、不換掉目前的圖；一次給好幾張時只用第一張。
- 專案檔：共用格式（`format: 'trpg-toolkit-project'`、`tool: 'qr-maker'`、`version: 1`）；內容讀入時整理（同自動儲存）。

## 3. 輸出與數值

### 3.1 版面（原作 QRSVG）

n＝格數；可用邊長 S＝min(寬, 高) − 2 × 邊距（邊距先夾在 min(寬, 高) 以內）；方形時 Q＝S、圓形時 Q＝S ÷ √2。
一格 d＝Q ÷ n（取整數時無條件捨去）；n > 寬或高、或 d 不到 1（取整數時）時「尺寸太小」。
左上角 (x₀, y₀)＝((寬 − n·d) ÷ 2, (高 − n·d) ÷ 2)（取整數時捨去）。三個角在 (x₀, y₀)、(x₀＋(n−7)d, y₀)、(x₀, y₀＋(n−7)d)。

### 3.2 點的形狀（原作 QRDot）

每個深色的格依「上下左右的格有沒有點」決定形狀（被圖蓋住而拿掉的格、角的 7 × 7 都算沒有）：

| 樣式 | 沒有鄰居 | 1 個鄰居 | 2 個相鄰的鄰居（L 形） | 左右或上下都有、或 3 個以上 |
|---|---|---|---|---|
| 方塊 | 方塊 | 方塊 | 方塊 | 方塊 |
| 圓點 | 圓 | 圓 | 圓 | 圓 |
| 圓角 | 圓 | 背著鄰居的那一邊是半圓 | 外側的角是半徑 d/2 的圓角 | 方塊 |
| 大圓角 | 圓 | 同圓角 | 外側的角是半徑 d 的四分之一圓 | 方塊 |

葉形：沒有鄰居時左下與右上兩角圓（半徑 d/2）；左邊與上面都沒有時左上角圓；右邊與下面都沒有時右下角圓；其他方塊。
圓葉形同葉形，但單角的圓是半徑 d 的四分之一圓。

### 3.3 角的分層與顏色（原作 drawCorners）

- 外框：選了方框（外 7d、內 5d 的方形環）、圓框（外徑 7d、內徑 5d 的圓環）、圓角框（外圈圓角半徑 2.5d、內圈 1.5d）時畫整塊（evenodd）；
  其他用那種點畫 7 × 7 的外框；「跟著點」一律用點的樣式一格一格畫（點的樣式和整塊的類型有同名的 square、extra-rounded，不能混用）。
  中心：方塊（3d）、圓（直徑 3d）畫整塊；其他用點畫 3 × 3；「跟著點」用點的樣式畫 3 × 3。
- 顏色：外框「跟著點」＝用點的填色（漸層的範圍是整張圖）；中心「跟著外框」＝外框有自己的顏色時用外框的填色（漸層的範圍是 7 × 7），否則用點的。

### 3.4 漸層（原作 _createColor）

角度同 CSS（0° 由下往上、90° 由左往右）；換成原作的旋轉 r＝(角度 − 90°)，角的漸層再加 0°／90°／−90°（左上／右上／左下）。範圍 (x, y, w, h)：

- 線性：中心 (cx, cy)。r 在 −45°～45° 時起點 (x, cy − h/2·tan r)、終點 (x＋w, cy＋h/2·tan r)；45°～135° 時起點 (cx − w/2 ÷ tan r, y)、終點 (cx＋w/2 ÷ tan r, y＋h)；
  其餘兩個象限反過來。端點四捨五入到整數（例：100 × 100、90° → (0, 50)～(100, 50)；135° → (0, 0)～(100, 100)；180° → (50, 0)～(50, 100)）。和 CSS 的漸層線長度不同（D7）。
- 放射：中心＝範圍中央、半徑＝長邊 ÷ 2。
- 色標依位置排序、位置夾在 0～1。

### 3.5 中間的圖（原作 calculateImageSize）

最多拿掉 M＝floor(係數 × 修復比例〔L 0.07、M 0.15、Q 0.25、H 0.3〕× n²) 格，每邊最多 n − 14 格。k＝圖高 ÷ 圖寬：
橫向格數 hx＝floor(√(M ÷ k))（至少 1、不超過每邊上限、偶數時減 1），圖寬＝hx·d；縱向 hy＝1＋2·ceil((hx·k − 1) ÷ 2)、圖高＝round(圖寬 × k)；
hx·hy > M 或 hy 超過上限時改以縱向為準重算。拿掉的範圍：第 (n − hy)/2～(n＋hy)/2 列、(n − hx)/2～(n＋hx)/2 行（不含尾）。
圖的位置＝QR code 的中央，四周縮「圖的邊距」，圖等比放進去（同 SVG 的 xMidYMid meet）；寬或高不到 0 時不畫。
（原作的測試值：圖 2020 × 1000、M＝50、d＝10 → 90 × 45、拿掉 9 × 5 格。）

### 3.6 圓形的外圍（原作 drawDots 的 circle）

外圍圈數 e＝floor((S ÷ d − n) ÷ 2)；在 (n＋2e) × (n＋2e) 的格子裡，離 QR code 一格以內的不畫、離中心超過 floor((n＋2e) ÷ 2) 格的不畫，
其餘第 (r, c) 格取 QR code 第 (f(c), f(r)) 格的深淺（f(i)＝i < 2e 時 i、i ≥ n 時 i − 2e、其他 i − e，夾在 0～n−1），用點的樣式畫。

### 3.7 匯出

- PNG／JPEG／WebP：新的畫布（寬 × 倍率、高 × 倍率），同預覽的畫法乘上倍率；JPEG 先鋪白；JPEG／WebP 的品質 1（同原作）。
- SVG：開頭 `<?xml version="1.0" standalone="no"?>`；`<svg width height viewBox>`（寬高乘倍率）；`<defs>` 放漸層（同一個填色只定義一次）；
  背景 `<rect>`（有圓角時 `rx`）；每一層一個 `<path>`（點一層；三個角的外框、中心各一層）；圖 `<image>`。
- 檔名：`〈檔名〉.png`／`.jpg`／`.webp`／`.svg`。

### 3.8 編碼（`@/core/qr` 的 encodeQr，qrcode-generator）

位元組模式先把文字轉成 UTF-8 位元組再交給套件；漢字模式用 Shift_JIS（從瀏覽器的 Shift_JIS 解碼器反建「字 → 碼」表，只收 0x8140～0x9FFC、0xE040～0xEBBF）；
遮罩由套件依規格的扣分選最好的。結果快取（同樣的輸入回傳同一個物件）。

### 3.9 掃描檢查（`@/core/qr` 的 checkQrPixels、qrPaintContrast）

- 取樣：每一格中央邊長約 0.34 格的方塊，灰階＝0.299R＋0.587G＋0.114B（透明疊在白底上）；Otsu 法分成深淺（兩群中間沒有值時取那一段的正中間，驗證後修正：原本貼著深色那一端，反鋸齒的淺灰邊都被當成淺色）。
- 解碼：讀格式資訊（兩份，容許 3 位元錯）→ 去掉遮罩 → Z 字順序讀碼字 → 拆回區塊 → Reed–Solomon 修正（每塊最多 ⌊錯誤更正碼字 ÷ 2⌋ 個）→ 解析數字、英數字、位元組、漢字、ECI。
  位元組沒有 ECI 時是合法 UTF-8 就當 UTF-8，否則 ISO-8859-1。照一般的深淺讀不出來時再反過來讀一次（反色）。
- 「用掉的容錯」＝修正最多的那一塊的修正數 ÷ 那一塊的上限。
- 定位方框：每個角穿過中心的橫線與直線（從外側分隔線的中間到另一側，共 8 格）；深淺差（兩條線的最亮減最暗）不到 64 時當成看不見，
  否則以兩條線自己的中間值分深淺（局部二值化）；兩端與中間不到 0.3 格的段不算（併進旁邊）；去掉兩端的淺色後要剛好 5 段，
  每段和 1:1:3:1:1 的長度差在半格以內（中間在 1.5 格以內）、總長至少 5 格。
- 對比：點、外框、中心的顏色（漸層取每個色標）和背景（漸層取每個色標；透明＝白）用 WCAG 的算法；前景平均比背景亮時是反色；
  一般時取「背景最暗」對「前景最亮」、反色時反過來。門檻：< 1.5 錯誤、< 3 警告、< 4.5 資訊。
- 其他門檻：每格 < 4 px 警告（驗證後由 3 改 4：3 px 的格子兩個獨立解碼器常常讀不出來）；方形時四周留白 < 2 格資訊。

### 3.10 自動儲存與專案檔

- localStorage `trpg-toolkit:qr-maker`：`{ data, width, height, margin, shape, qr: { version, mode, ecl }, dots: { type, paint, roundSize },
  cornerSquare: { type, paint }, cornerDot: { type, paint }, background: { mode, color, gradient, round }, image: { id, name, width, height } | null,
  imageOptions: { size, margin, hideBackgroundDots } }`；畫法 `paint`＝`{ mode, color, gradient: { kind, angle, stops } }`（mode：solid／gradient，角另有 inherit、背景另有 transparent）。

## 5. 容易做壞的地方

- **中文要 UTF-8**：qrcode-generator 的位元組模式只取每個字的低 8 位，直接交中文會變亂碼（原作就是這樣）；先轉 UTF-8 位元組、再一個位元組一個字元交給套件。
  漢字模式要暫時換掉套件全域的 `stringToBytes`，加完資料馬上換回來（同步）。
- **預覽與匯出同一段畫法**：canvas 與 SVG 都照同一個場景（路徑字串）畫；點的旋轉直接算進座標（90° 的倍數，沒有誤差），不用 transform。
- **整層的點合成一條路徑**：點彼此不重疊，用 nonzero 沒問題；有洞的角（方框、圓框、圓角框）一定要 evenodd，所以和點分開畫（同一個填色）。
- **漸層的端點照原作的算法**，不是 CSS 的漸層線；角的漸層每個角轉向不同。
- **「拿掉圖後面的點」也影響鄰居**：被拿掉的格對旁邊的點來說是「沒有點」（圓角的形狀會跟著變）。
- **掃描檢查的角**：方框類的角是整塊的形狀（圓環等），格子中央不一定落在形狀上；資料區的格數比對不算三個角的 8 × 8，角另外用 1:1:3:1:1 檢查。
- **只照格子讀不等於掃得到**：漸層的淡端讓某個角幾乎看不見時，每一格還可能靠錯誤更正讀回來，但掃描程式找不到那個角；所以定位方框要另外檢查（F24）。
- **透明背景與 JPEG**：canvas 預設透明，JPEG 會變黑，先鋪白。
- **檢查的時機**：畫布的寬高一改就被清空；檢查要在重畫之後、延後一點、用最後一次的設定（舊的計時器要取消）。
