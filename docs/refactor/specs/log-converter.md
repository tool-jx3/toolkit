# CCFOLIA 日誌轉換器（log-converter）行為規格

## 0. 概要

把 CCFOLIA 匯出的聊天日誌（HTML）轉成適合保存、分享或貼到部落格的網頁。輸入是一個或多個日誌檔：「舊格式」（純文字）一次一個檔，
「新格式」（含頭像與時間，每個分頁一個檔）可以多檔合併。輸出有三種樣式：**小說**（台詞與敘述連成散文段落）、
**時間軸**（左側一條直線串起頭像圖示，依序排列）、**CCFOLIA 風格**（接近 CCFOLIA 聊天欄的一列一則）。
可以選旁白角色與副旁白、閒聊分頁的呈現、系統訊息（擲骰）的顯示、分頁的顯示與顏色、名稱顏色、頭像圖片與壓縮品質、
字型與排版、在指定的訊息序號後插入插圖、依則數、大小或固定檔數分割、轉成可以放進部落格文章的 HTML 片段。轉換後有預覽（可選範圍）
與下載（單檔、分割檔、ZIP）。設定自動記在瀏覽器，也可以匯出成設定檔。全部在瀏覽器內處理，不上傳。

靈感來源：Eon-00/eon-ccfolia-log-converter（<https://github.com/Eon-00/eon-ccfolia-log-converter>）

附件：[`log-converter.examples.json`](log-converter.examples.json)——36 組「日誌樣本＋設定→輸出結構」的舊版實際紀錄
（舊格式 26 組、新格式 10 組；樣本日誌與圖片全部是觀察者自編的繁中 CoC 情境，依 CCFOLIA 匯出檔的結構製作，附在檔案裡）。
附件的「區塊」是輸出 HTML 抽掉樣式後看得到的結構（種類、文字、名稱、顏色、頭像識別、斜體／置中等），**輸出的結構與文字以附件為準**；
第 3 節的規則是附件的歸納，外觀以量測描述。

名詞：
- **則**：日誌裡的一則訊息（舊格式一個段落、新格式一個訊息元素）。合併同人連續對話（F47）後，合併成的一則算一則。
- **分頁**：CCFOLIA 的聊天分頁（メイン、情報、雑談、自訂分頁…）。
- **旁白角色**：指定的一位發言者，他的發言當成敘述（預設「GM」）。**副旁白**：另外指定、套用四種樣式之一的發言者。
- **閒聊**：指定為閒聊分頁（F19）裡的訊息。**系統訊息**：擲骰結果與 CCFOLIA 代發的數值變更通知。
- **訊息序號**：每一則（合併後）從 1 起的序號，插圖位置用它指定；僅預覽時出現。

## 2. 輸入

### 2.1 外部格式事實：CCFOLIA 日誌（舊格式）

CCFOLIA 房間選單的日誌匯出（ログ出力）下載的 HTML（純文字版）。舊版辨識的結構：

- 一份一般的 HTML 文件；每一則訊息是一個段落元素（`p`），段落的行內樣式以文字顏色記錄發言者的名字顏色。
- 段落裡依序有三個 `span`：①「 [分頁名稱]」（前面有空白，方括號包住分頁名稱；預設分頁以代碼 `main`、`info`、`other` 出現，
  自訂分頁以名稱出現）、②發言者名稱、③訊息內容（HTML：換行是 `br`，`<`、`&` 等以字元實體表示）。②與③之間有「 : 」。
- CCFOLIA 代發的數值變更通知，發言者是 `system`，內容像「[ 角色名 ] SAN : 48 → 45」。
- 擲骰是一般訊息，指令與結果寫在同一段文字裡，例如「CC<=60 【偵查】 (1D100<=60) ＞ 23 ＞ 成功」「1d6 → 4」。
- 檔名由使用者決定（常見寫法是把參加者、劇本名、分頁用方括號標在檔名裡，本工具據此帶入標題，見 3.2）。

### 2.2 外部格式事實：CCFOLIA 日誌（新格式）

含頭像資訊的 HTML，一個分頁匯出成一個檔，也可以有一個全分頁檔。以下依舊版辨識的結構整理（觀察者在沙盒裡無法取得實際的
CCFOLIA 匯出檔對照，附件的樣本依此結構自製）：

```text
文件
├ title（以及一個 class 含 log-title 的元素，兩者都有時以後者為準）：「房間名 [分頁名]」
│   全分頁檔，方括號裡是代表「全部」的字樣（すべて、全て、전체、all…）
├ style 元素：每張頭像一條規則，對象是 class avatar-image-N（N 是數字），背景圖片是該頭像的 data URL
└ article.message（CCFOLIA 代發的系統列另有 class system）× 則數，屬性 data-channel＝分頁代碼
  │   （預設分頁 main／info／other；自訂分頁是一串隨機英數，例如 Xk3pQ9aZ）
  ├ 頭像：class 含 avatar 的元素，另有 class avatar-image-N（沒有頭像時沒有這個 class）
  └ .message-content
    ├ .speaker：發言者名稱；行內樣式的自訂屬性 --speaker-color＝名字顏色（系統列沒有這個元素）
    ├ time：datetime 屬性是 ISO 8601 時間（可能沒有）
    ├ .message-text：內文（換行是 br）
    └ .roll-result：擲骰結果文字，例如「(1D100<=60) ＞ 23 ＞ 成功」（沒有擲骰時沒有）
```

### 2.3 格式判斷

- 新格式＝檔案內容裡有「class 含 message 的 article」，而且有 `data-channel` 屬性或 class 為 `message-text` 的元素。其餘一律當成舊格式。
- 檔案一律以 UTF-8 讀取。

### 2.4 載入與合併

**舊格式**

- 所有段落（`p`，也接受 `div`）中含 3 個以上 `span` 的才算一則：分頁＝第 1 個的文字去掉方括號與頭尾空白；發言者＝第 2 個的文字去頭尾空白；
  內容＝第 3 個的 HTML 原文去頭尾空白（保留標籤與實體）。第 3 個的文字去頭尾空白後是空的就略過（附件：只有空白的訊息不出現）。
- 分頁清單與發言者清單依第一次出現的順序（發言者清單含 `system`，旁白選單與名稱顏色不含）。段落記錄的名字顏色不使用（見 5.）。

**新格式**

- 每個檔：標題若以「[…]」結尾，前面（去頭尾空白）是房間名稱、括號內是分頁標籤；否則整段是房間名稱、沒有分頁標籤。
- 每則：內文（`br` 換成換行）與擲骰結果（去頭尾空白）都空就略過。輸出用的內容＝內文去掉結尾空白、轉成純文字（HTML 字元跳脫、換行保留），
  有擲骰結果時再換一行接上結果。發言者＝系統列為 `system`，否則是發言者元素的文字去頭尾空白。
- 名字顏色：每位發言者取出現次數最多的那個顏色。頭像：該則 `avatar-image-N` 對應的圖。
- **多檔合併**：
  1. 分頁名稱：只含一個分頁、而且有分頁標籤的檔，以標籤當那個分頁代碼的名稱（標籤是 すべて、全て、전체、全部、所有、all〔不分大小寫〕時不算）；
     其餘分頁代碼用 F12 的預設名稱，再沒有就用代碼本身。
  2. 來源：含 2 個以上分頁的檔中取則數最多的一個（其餘捨棄，F06）；只含一個分頁的檔，若它的分頁已被前面採用的檔涵蓋就捨棄，否則採用。
  3. 排序：每則的時間是它自己的時間；沒有時間的則沿用同一檔裡前一則的時間（檔案開頭就沒有時間的則，用該檔第一個出現的時間；
     整檔都沒有時間時排在最前面）。依時間由早到晚；時間相同時依來源檔的順序（全分頁檔排第一，其餘依選檔順序），同檔內依原順序（附件 V08）。
  4. 每位發言者的「代表頭像」＝他最常用的那張（F30 關閉時使用）。名字顏色依來源檔順序取第一個有記錄的。房間名稱取第一個有房間名稱的來源檔。
- 發言者清單（旁白選單、名稱顏色、頭像卡）依第一次出現的順序，不含 `system` 與空白名稱。
- 時間只用來排序，**任何樣式都不顯示時間**；CCFOLIA 的擲骰成敗顏色不保留。

### 2.5 訊息分類

依序判斷，先符合的就是：

| 順序 | 舊格式 | 新格式 |
|---|---|---|
| 1 | 分頁＝閒聊分頁 → 閒聊 | 系統列，或有擲骰結果 → 系統訊息（不論發言者，旁白角色的擲骰也是） |
| 2 | 發言者＝旁白角色 → 旁白（**旁白角色的擲骰也算旁白**，附件 L01 的「CC<=50 【幸運】…」） | 分頁＝閒聊分頁 → 閒聊 |
| 3 | 發言者是 `system`，或內容 HTML 原文含「cc<=」或「數字＋d＋數字」（不分大小寫）→ 系統訊息 | 發言者＝旁白角色 → 旁白 |
| 4 | 其他 → 對話 | 其他 → 對話 |

- 舊格式的第 3 條：CCFOLIA 把「<」寫成實體，所以「cc<=」實際上不會命中，只有「1D100」「2d6」這類寫法有效；台詞裡出現「2d6」也會被當成擲骰（附件 L24）。
- 比對旁白角色與閒聊分頁都是完全相同的字串。
- 副旁白（F21）只作用在「對話」；CCFOLIA 風格另外也作用在旁白角色（見 3.5）。閒聊、系統訊息不受副旁白影響。

### 2.6 其他輸入

- 頭像與插圖：瀏覽器能解碼的圖片檔（image/*）或網址（下載轉內嵌時需要對方允許跨網域）。
- 設定檔：新版自訂格式（`.json`）；不做舊版設定檔的匯入。

## 3. 輸出

### 3.1 檔案

- 一份完整的 HTML 文件（UTF-8）：文件語言 `zh-Hant-TW`、文件標題＝標題（分割時加「 (Part n)」）。整頁只有一個外層容器，裡面是標題區、內容區塊、（分割時）頁尾。
- 樣式全部寫在檔案裡，不含任何指令碼。頭像與上傳的插圖以 data URL 內嵌；外部資源只有字型（Google Fonts 或自訂字型網址）、網址插圖與直接引用網址的頭像。
- 舊版的成品是固定寬度的版面（容器有最大寬度、置中），沒有針對手機另外排版。

### 3.2 標題、檔名、字型、頁碼

- **標題區**在最上方：標題（大字）、副標題（有填才有）、摘要（有填才有）。
- **標題**＝標題欄的內容（照原樣，不去頭尾空白）；標題欄空白時，從「檔名主體」取第一個「]」與其後第一個「[」之間的文字（去頭尾空白），
  沒有就用預設標題（F92）（附件以外的實測：新格式清空標題時，檔名用房間名稱，但標題是預設標題）。
- **檔名主體**：標題欄去頭尾空白後不是空的 → 把 `\ / : * ? " < > |` 各換成「_」、去頭尾空白、連續的「_」合成一個、去掉頭尾的「_」，
  結果是空的就用一個後備檔名（舊版是 `session_log`，新版可自訂；例：「  a/b:c**d  」→ `a_b_c_d`；「___」→ 後備檔名）；標題欄空白、新格式而且有房間名稱 → 房間名稱照同樣規則清理；
  其他 → 舊格式的檔名去掉「.html」（不清理）。
- **舊格式從檔名帶入**（F11）：檔名去掉「.html」後，標題＝第一個「]」與其後第一個「[」之間的文字（去頭尾空白），沒有時是整個檔名；
  副標題＝開頭「[…]」裡的文字，沒有時是空的。例：「[小芋、阿和] 霧港燈塔 [main].html」→ 標題「霧港燈塔」、副標題「小芋、阿和」；
  「legacy-short.html」→「legacy-short」、空白。
- **下載檔名**：單檔 `主體.html`；分割 `主體_part{n}.html`；全部打包 `主體_all.zip`（內含各 part 檔，ZIP 內檔名以 UTF-8 記錄）；
  部落格貼文版 `主體_web.html`、`主體_part{n}_web.html`、`主體_web_all.zip`（內含 `主體_part{n}_web.html`）。
- **字型**：自訂字型名稱有填時，字型＝「該名稱（以引號包住）, 預設字型」。舊版的預設字型是韓文的 Noto Sans KR／Noto Serif KR（小說內文用襯線、
  標題附註用黑體；時間軸內文黑體、標題與旁白段落用襯線；CCFOLIA 風格全部黑體），由 Google Fonts 載入。新版改成繁中字型
  （例如思源宋體／黑體）屬刻意差異（見 5.）。
- **頁碼**：分割成多檔時，每檔的標題加上「 #n」，檔尾有置中的頁碼（F92；上方一條強調色細線、灰色小字）。

### 3.6 各樣式共通的規則

**輸出順序與分組**

- 閒聊：連續的閒聊收成一組（一個摺疊區塊；全部顯示時是一組連續的列或項目），遇到下列情況才輸出這一組：
  - 小說：遇到旁白、對話、插圖或結尾。**系統訊息不會打斷這一組**，所以夾在閒聊中間或緊接在後的系統訊息會排到這組閒聊**前面**（附件 L01：SAN 通知排在閒聊之前；見 5.）。
  - 時間軸、CCFOLIA 風格：遇到旁白、對話、系統訊息、插圖或結尾。
- 時間軸的旁白合併：遇到對話、系統訊息、閒聊、插圖或結尾時結束。**旁白類的副旁白不會結束合併**，所以副旁白項目會排到還沒輸出的旁白前面（附件 L13；見 5.）。
- CCFOLIA 風格的獨立區塊：遇到其他任何一則（含不同發言者或不同分頁的旁白）時結束。

**不輸出的訊息**：不顯示的分頁（F55）裡的所有訊息、系統訊息隱藏（F53）時的系統訊息、閒聊完全隱藏（F51）時的閒聊。它們仍佔訊息序號。

**名稱顏色**

- 名稱顏色（F32）套用在三種樣式的對話名稱、CCFOLIA 風格旁白列的名稱。擲骰的名稱一律用系統文字色。
- 閒聊的名稱：小說一律灰色；時間軸與 CCFOLIA 風格，若這個人在同一個檔裡也有「對話」，用他的名稱顏色，否則用預設色（時間軸灰色、CCFOLIA 風格主題文字色）。

**分頁顏色（F62）**：啟用時每個分頁都有顏色（未改動的是淺灰文字、透明背景，所以一啟用就會影響所有分頁）。

| 樣式 | 效果 |
|---|---|
| 小說 | 3.3 的分頁區段；閒聊組的文字（含標題）用閒聊分頁的文字色，背景用閒聊分頁的背景（透明時維持深灰）。 |
| 時間軸 | 對話項目的色塊背景＝分頁背景（透明時用容器色）、文字＝分頁文字色；旁白合併項目用第一則所在分頁的顏色（背景透明時用旁白背景、文字沒設時用旁白文字色）；閒聊組用閒聊分頁的顏色；旁白類副旁白同對話。 |
| CCFOLIA 風格 | 列的背景＝分頁背景（透明時照原本）、內容文字＝分頁文字色、分頁標籤＝分頁文字色；閒聊摺疊標題用閒聊分頁的文字色；獨立區塊用第一則所在分頁的顏色。 |

**內容文字**：舊格式的內容原封不動保留 HTML（粗體、斜體等標籤會生效，見 5. 的安全性）；新格式的內容是純文字（換行保留）。
合併同人連續對話的一則，每則原本的訊息是一行。

### 3.7 插圖

- 位置：插在「訊息序號＝指定值」那一則之後；同一位置有多張時依新增的順序。插圖本身沒有編號；插入前會先輸出還在累積的閒聊組與旁白合併。
- 外觀：圖片寬度撐滿到上限（小於上限的圖會被放大到上限或內容寬）、高度等比，圓角約 8 px、淡陰影；依 F44 靠左、置中或靠右；有替代文字（F92）。
  CCFOLIA 風格時插圖區上下各有一條細線、四周約 24 px 內距。
- 上傳的插圖：長邊超過 800 px 時等比縮到 800（四捨五入），以「目前品質預設的格式」（見 3.8）、品質約 0.9 重新編碼（即使沒縮小）；網址插圖照原網址。

### 3.8 頭像與圖片處理

| 圖片品質 | 頭像的長邊上限 | 格式 | 編碼品質（約） |
|---|---|---|---|
| 最小 | 100 px | WebP（瀏覽器不支援時 JPEG） | 0.6 |
| 標準 | 150 px | WebP（同上） | 0.75 |
| 較高畫質 | 200 px | JPEG | 0.85 |
| 原圖 | 不縮放 | PNG | — |
| 自訂（滑桿 x） | 64 ＋ x% × 236，四捨五入 | x ≤ 80：WebP；x > 80：JPEG | 0.4 ＋ x% × 0.55 |

（上限與格式是量測值：例如 200×260 的圖在「最小」時變成 77×100 WebP、「標準」時 115×150；編碼品質由檔案大小推定。）

- 只縮小不放大：寬或高超過上限時等比縮到長邊＝上限（四捨五入）；沒超過也一律重新編碼成上表的格式。
- 縮放圖片關閉（F27）：上傳與網址下載的頭像照原檔（格式與位元組不變）。
- 新格式的日誌裡的頭像：縮放開啟且品質不是原圖時，依上限縮放並**一律編成 WebP**（瀏覽器不支援時 PNG），處理失敗的用原圖；否則保留原檔（附件 V04）。
- 每一則用哪張頭像（時間軸的對話與副旁白對話（斜體）、CCFOLIA 風格的對話列與旁白列）：F30 開啟且該則有自己的頭像 → 該則的頭像；
  否則 → 使用者為這位發言者上傳／輸入網址的頭像；再沒有 → 新格式的代表頭像；都沒有 → 人形圖示（附件 V06、V07）。
  CCFOLIA 風格的閒聊列只用後兩者（不用每則的頭像）。時間軸的旁白、擲骰、閒聊用固定圖示。
- 嵌入：成品裡每一張不同的圖只嵌入一次（多則共用同一張圖時只存一份）；不會輸出的訊息（見 3.6）才用到的圖不嵌入。頭像元素有無障礙名稱（發言者名稱）。

### 3.9 分割

- **依則數** n（1～100000 的整數；其他值＝不分割）：每 n 則一檔。
- **固定檔數** n（2～1000；其他值＝2）：每檔「總則數 ÷ n 無條件進位」則依序切，檔數可能少於 n（附件 L19：17 則分 3 檔＝6、6、5）。
- **依大小** n KB（1～100000；其他值＝不分割）：一則一則加入目前這一檔，每加一則就計算「這一檔的完整 HTML」的 UTF-8 位元組數，
  超過 n × 1024 時把剛加入的那則移到下一檔；單一則就超過時它自己一檔。新版的 HTML 大小不同，切點可以不同；驗證時檢查
  「每檔不超過上限（單則超過除外），而且下一則放不進去才換檔」。
- 這裡的「則」是合併、分類後的每一則，**包含**不輸出的訊息（所以每檔實際顯示的數量可能較少）。
- 每個分割檔都是完整獨立的頁面：同樣的標題區（標題加「 #n」）、頁尾頁碼、各自依該檔內容計算的名稱欄寬與嵌入的圖片。
- 插圖在分割檔中的位置：見 5.（舊版錯誤；新版以全域訊息序號插在正確的那一檔）。

### 3.10 部落格貼文版

- 由對應的 HTML 檔轉成能放進部落格文章裡的**片段**：沒有文件宣告、`html`、`head`、`body` 與文件標題；開頭是 UTF-8 字元集宣告與一段樣式，
  接著是原本外層容器的全部內容（含字型連結）。開頭與結尾的空白去掉，不含訊息序號。
- 所有樣式都限定在外層容器之內，不影響部落格頁面的其他部分；頁面層級的規則（整頁背景、全域的字型與排版設定）改成作用在容器上。
- 外層容器的識別名稱加上一個由「檔名主體＋第幾檔」算出的固定後綴（同樣輸入每次相同、不同檔不同），頭像的樣式名稱也加上同一後綴，
  所以同一篇文章貼多份成品時顏色與頭像不會互相覆蓋。舊版的樣式會在片段裡重複一份（開頭的限定版＋容器內的原版）；新版只輸出一份屬可接受差異。

### 3.11 預覽與訊息序號

- 預覽＝範圍內的則用同樣的樣式與設定轉成的單一頁（不分割），範圍外的插圖不出現。
- 訊息序號＝每一則（合併後）從 1 起的全域序號，含不輸出的與閒聊（所以預覽裡的編號可能跳號）。
- 顯示編號時（F40），帶編號的區塊右上角浮出小小的「#n」：等寬字、約 0.7 倍字級、灰色、半透明深色底、圓角、不能點；小說與時間軸放在區塊外的右上方（約右移 30 px、上移 8 px），
  CCFOLIA 風格放在列內右上角（約距上 4 px、距右 8 px）。帶編號的區塊：小說的旁白、對話、擲骰、場景分隔；時間軸的對話、擲骰、副旁白項目，
  以及旁白合併項目裡的**每一段**；CCFOLIA 風格的對話列、旁白列、擲骰列（獨立區塊只在每則的第一行）。閒聊、通知列沒有編號。
- 下載的檔案一律不含編號。

### 3.12 對等驗證的比對方法

1. 附件 36 組：新版用同樣的樣本日誌、圖片與設定轉換，用同樣的方式抽出區塊（種類、順序、文字行、名稱、頭像的識別與尺寸／格式、斜體、置中、
   使用者指定的顏色），逐項比對。允許的差異：字型；非使用者指定的固定配色（明暗關係要相近）；介面字樣與頁碼字樣（F92）；ZIP 的壓縮方式；
   部落格貼文版的後綴值；第 5 節列出、經主控核准改正的舊版錯誤（附件中受影響的案例在驗證紀錄寫明）。
2. 隨機比對：產生至少 200 份隨機日誌（新舊格式、多分頁、閒聊、系統訊息、空白訊息、長名稱、HTML 特殊字元、缺時間），隨機組合樣式與設定，比對區塊結構。
3. 流程（Playwright 操作兩邊）：載入、加入／移除檔案、分頁改名、預覽區段（用 1200 則的長日誌）、下載的檔名與 ZIP 內容、部落格貼文版
   （兩份貼到同一頁不互相干擾）、設定的記住、匯出與匯入。
4. 外觀：三種樣式各取附件 L01～L03、V02、V03 並排截圖，比對版面（標題區、名稱欄、色塊、圖示、間距）。
5. 效能：1200 則轉換約 0.4 秒（舊版），新版不得明顯變慢；依大小分割大日誌時不得明顯變慢。

## 4. 互動與手感

- 選檔即分析；轉換要按按鈕；改設定後要重新轉換，預覽和下載才會更新（預覽區段的操作除外）。
- 狀態列（結果區上方）、檔案提示列（選檔欄下方，警告色）、瀏覽器原生的提示／確認對話框（舊版用於錯誤、匯出、匯入、重設、大圖警告）。
  新版改用共用的 Notice、toast 與 ConfirmDialog 屬可接受差異（訊息種類與時機要對應）。
- 副旁白卡片約 0.3 秒淡入下滑；預覽每次重畫約 0.3 秒淡入。沒有快捷鍵、沒有復原／重做。
- 設定分頁（基本／外觀／插圖／進階）一次顯示一個；預覽框固定高度約 500 px，內容在框內捲動。
- **舊版自動記住的範圍**：改動下列項目時立刻存進瀏覽器——樣式、旁白顯示方式與置中、閒聊分頁、自訂字型兩欄、合併同人連續對話、字級、行距、頁寬、
  閒聊呈現與數量、系統訊息、配色預設與 9 色、分割方式與三個數值、分頁顏色開關、小說排版微調、名稱過長時換行、台詞版面、分隔符號與自訂分隔字、顯示訊息序號。
  副旁白、名稱顏色、分頁顯示、分頁顏色本身的改動不會立刻存（要等上述任一項改動時一起寫入）。開頁時還原：上述各項＋副旁白設定＋分頁顏色
  （依分頁名稱）；不還原：旁白角色、分頁顯示設定、名稱顏色（載入日誌時重設）、標題三欄、頭像與圖片品質相關設定、逐則頭像、插圖、部落格貼文版。
  閒聊分頁在載入日誌時會被自動選擇覆蓋。新版用共用的自動存檔記住全部設定（日誌、頭像、插圖除外）屬可接受的改善。
- 預覽的內嵌框不執行任何指令碼。

## 5. 容易做壞的地方

**一定要做對的**

- **新舊格式的分類規則不同**（2.5）：舊格式旁白角色的擲骰算旁白；新格式有擲骰結果就一定是系統訊息。
- **新格式的合併與排序**（2.4）：全分頁檔優先、重複分頁捨棄、缺時間沿用前一則、同時間依檔案順序。分頁名稱從單分頁檔的標題取。
- **時間軸名稱欄的寬度**用「顯示寬度 × 0.55 無條件進位」；**小說的名稱欄寬**用字數（含 `system` 與閒聊的人）。分割檔各自計算。
- **閒聊組的輸出時機**在三種樣式不同（3.6）；**時間軸連續旁白合成一項**、**CCFOLIA 風格獨立區塊只合併同人同分頁**。
- **小說的「***」**：內容含「***」的旁白或對話整則變成場景分隔（文字消失）；時間軸與 CCFOLIA 風格不特別處理。
- **不輸出的訊息仍佔訊息序號與分割則數**。
- **頭像的選用順序**（3.8）與**每張圖只嵌一次、不用的不嵌**。
- **預覽區段超出時的修正**（F74）。
- **檔名主體的清理規則**與「標題空白時」的各種來源（3.2）。

**舊版的錯誤與怪異行為（刻意差異，需主控確認）**

1. **旁白角色的自動選擇**：舊版想自動選「GM」，但實際選到的是發言者清單裡排在 GM **前一位**的人（GM 是第一位發言者時才剛好正確；附件 L24 選到林曉雨）。
   建議新版改成真的選 GM（沒有 GM 時選預設的 GM 選項）。改了之後 L24、L25 的結果不同。
2. **時間軸副旁白的順序錯置**（附件 L13）：副旁白項目排到尚未輸出的旁白前面。建議新版依原本順序輸出。
3. **小說的系統訊息插到閒聊組前面**（附件 L01）：建議新版維持原順序（遇到系統訊息時先把閒聊組輸出），需主控決定（改了會改變附件 L01 等案例的順序）。
4. **名稱過長時換行沒有效果**（F48）：建議新版做出說明的效果（名稱超過 10 個字時可以換行，CJK 不從字中間斷）。
5. **自訂字型名稱加了引號就失效**（實測：照說明輸入「'Noto Serif TC'」時字型變成瀏覽器預設的襯線字）：新版有沒有引號都要能用。
6. **分割時插圖的位置**：舊版每個分割檔重新從 1 編號，所以插在第 3 則後的插圖會出現在**每一個**有 3 則以上的檔，而編號大於每檔則數的插圖**永遠不出現**
   （實測：每 5 則一檔、插圖在 #3 與 #8 → part1～3 各一張 #3 的圖，#8 的圖消失）。新版以全域訊息序號插在正確的那一檔。
7. **配色預設與實際顏色不一致**：初次開頁時選單顯示第一組預設，但 9 個顏色是另一組初始值；重新整理後若記住的是非自訂的預設，選單顯示該預設但顏色回到初始值。
   新版選單顯示的預設要和實際顏色一致。
8. **標題、副標題、摘要與發言者名稱以 HTML 原文寫進成品**（在標題裡打斜體標籤會真的變成斜體；可以插入任意標籤），**舊格式的訊息內容也原樣保留 HTML**（含可能的指令碼）。
   建議新版：標題、名稱一律跳脫；舊格式內容用白名單淨化（保留 br、b、i、u、s、span 等排版標籤，去掉指令碼與事件屬性）。
9. **分頁改名的副作用**：改成與另一分頁同名時，原本那個分頁的設定可能被搬到改名的分頁；加入或移除檔案後，手動改過的分頁名稱會回到自動名稱。建議修正。
10. **全部移除檔案後**詳細設定區仍顯示上一份日誌的選單，可以繼續改但轉換時才說要先選檔。新版回到未載入狀態。
11. **新格式的名字顏色有記錄，舊格式的段落顏色卻沒使用**：舊格式的名稱顏色只能手動指定。新版若改成讀取段落顏色當初始值，屬功能改善，需主控確認。
12. **預設字型是韓文字型**：新版改用繁中字型（DESIGN.md「字型預設用繁中字型」）。
13. **偵錯紀錄面板**（F96）建議不移植。
14. **依大小分割**每加一則就重建整份 HTML 量大小，大日誌很慢；新版可以用增量估算，但要滿足 3.9 的條件。
15. **小說的「***」吃掉整則內容**：只要內容含「***」（例如「她低聲說：***」），整則就只剩置中的「***」。建議新版改成只有整則（去頭尾空白後）是「***」時才當場景分隔，其餘照常輸出；需主控確認（附件的樣本只有整則是「***」的情況，不受影響）。

**可接受差異**

- ZIP 改成壓縮、部落格貼文版的樣式只輸出一份、後綴值不同、佔位圖自畫、原生對話框改成共用元件、頁碼字樣改繁中、設定全部記住。
