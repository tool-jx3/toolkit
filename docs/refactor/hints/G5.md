# G5（CCFOLIA 資料）各工具的共用層使用提醒

G5 共用層已提交（2026-10-02）。各模組的完整 API 見 DESIGN.md 第 4.2 節「`@/ccfolia`（G5：…）」四列、「`@/core/files`（G5…）」與
「`@/core/decode`（G5：PSD）」；用法看單元測試 `web/tests/unit/ccfolia-*.test.ts`、`core-hash.test.ts`、`core-psd.test.ts`
（裡面有附件逐字／逐值比對的寫法，可以照著擴充）。照 PROCESS.md 第 0 節：實作時讀原作的程式，把功能改寫成下列共用模組。

## 共通

- **CCFOLIA 的外部格式只從 `@/ccfolia` 取**（欄位、預設值、欄位順序、檔名規則、日文錨點）；CCFOLIA 改版時只改那裡，工具裡不要再寫一份。
  缺的事實補進 `web/src/ccfolia/`（向下相容），不要寫在工具目錄。
- 共用層的錯誤與問題都回傳**種類代碼**（`'syntax'`、`'marker'`、`'dangling-ref'`…），介面文字在工具的 `strings.ts` 依代碼自訂。
- 內容雜湊用 `@/core/files` 的 `sha256Hex`（非安全環境也是真的 SHA-256）；ZIP 用 `zipFiles`／`unzipFiles`
  （要保留資料夾項目或檢查有沒有資料夾時 `unzipFiles(bytes, { directories: true })`）。
- 日誌解析用 `DOMParser`，只能在主執行緒；單元測試檔開頭加 `// @vitest-environment jsdom`。PSD 讀取不需要 canvas，可以搬進 Worker。

## character-editor（角色資料編輯器）

- 讀 JSON（F01、F02、F08）：`parseCharacterClipboard(text)` → 失敗時 `error` 是 `'syntax'`／`'root'`／`'kind'`／`'data'`（F02 的四種，
  依序判斷）；成功時 `character` 已照 2.3 修正、`raw` 是修正前的 data。
- 顏色是否列入比較（F04）：來源是 JSON 或檔案、而且 `isCharacterColor(raw.color)`；編輯畫面複製文字一律不列入。
- 編輯畫面複製文字（F05～F07）：`parseCharacterEditScreen(text)` → `error: 'marker'` 是 F07；只有開頭標記也算成功（E10）。
  **E06 已依第 7 節裁定修正**（標籤空白不再把「現在値」當成標籤），驗證紀錄要寫明 E06 比的是修正後的預期
  （`ccfolia-character.test.ts` 有修正後的完整輸出）。
- 輸出（F33）：`serializeCharacterClipboard(character)`——9 個欄位、固定順序、2 格縮排、結尾無換行、項目的額外欄位保留。
  開頁狀態（F37）：`normalizeCharacter({ name: '新角色', status: [{ label: '', value: 0, max: 0 }], params: [{ label: '', value: '' }] })`。
- 存檔（F35，裁定一律直接下載）：`downloadText(serializeCharacterClipboard(c), characterFileName(c.name), 'application/json')`。
- 差異清單與套用（3.2、3.3：身分、初始空白列、逐列重新判定）、色碼欄（3.4）是工具自己的規則，寫成工具內的純邏輯模組並用附件
  J02、J06、J07、J17、J20 等多步驟範例測（單步驟「全部覆寫」的範例共用層測試已逐字比過）。不保留狀態（F38）：`persist: false`。

## room-zip（房間 ZIP 產生器）

- 組 `__data.json`：`createRoomData({ room: createRoom({…}), scenes, items, characters, effects })`，各類的值用
  `createScene`／`createMarker`／`createItem`／`createRoomCharacter`／`createEffect` 補預設值（與附件 Z01、Z03、Z06、Z07 逐欄相同）。
  ID 用 `newRoomEntityId()`。
- 座標：工具內是中心座標（整數格）→ 輸出前 `centerToTopLeft({ x, y, width, height })`；拖曳、輸入後的取整用 `roundGrid`、寬高用
  `gridLength`（.5 往絕對值大的方向）。預覽的 px 換算用 `GRID_PX`／`boardToPx`。
- F271：`enableCrossfade: crossfadeFlag(畫面上的勾選)`（**相反**）、`hidden3dDice: 舊式骰子`。
- 棋子（3.1.7、D1 修正）：`createRoomCharacter({ name, memo, status, iconUrl, faces: [{ label, iconUrl }], commands, order })`；
  差分以 `{ label, iconUrl }` 寫出，差分圖要收進 ZIP。
- 素材：`packRoomImage(blob)` 得到 `<SHA-256>.<副檔名>`（jpeg 不是 jpg）與 MIME，可以直接當素材的識別名。BMP、AVIF 等不收
  （會丟錯），依 D8 先轉 PNG；動態圖不轉檔。
- 匯出（F279～F281）：`buildRoomZip(data, images)` 只收 JSON 有引用而且有圖的（resources 一一對應），回傳的 `missing` 不是空的就走
  F279／F280 的修復流程；產生後 `checkRoomZip(bytes)` 自我檢查，`problems[].code` 對應「已中止」的訊息。D2：刪掉的素材不要留在
  JSON 引用裡（共用層不會替你收「已刪除但還被引用」的圖）。
- 共有メモ（D14 維持不輸出）：`createNote` 有提供，但不要用。

## psd-studio（CCFOLIA & 圖片調色工作室）

- PSD（F10、2.2）：`readPsdLayers(file)`（第一次用時才下載 ag-psd，處理中畫面要涵蓋這段）。清單**由下到上**，依裁定清單與面板要
  由上到下顯示（反轉）。舊版「隱藏的圖層、隱藏群組裡的全部略過」＝`{ includeHidden: false }`；沒有像素的圖層本來就不列。
  同名圖層依裁定**全部保留**：檔名照 2.2 把 `/ \ ? % * : | " < >` 換成「_」＋`.png`，重名用 `uniqueFileName`（`_2`）。
  預覽依 `opacity`、`blendMode`、`clipping`、`mask`、`groups` 合成（共用層只提供屬性），匯出用原始的 `rgba`。
- 房間 ZIP（F09、F22）：`readRoomZip(bytes)` → `isRoom` 決定房間模式或圖片模式；`images` 是 ZIP 裡的圖（保留路徑）。
  配置檢視：`listRoomImageRefs(json).filter((r) => r.layout)`，`matchRoomImage(r.value, 路徑清單)` 找圖，位置大小從 `r.object`
  （x、y 是左上角的格座標；缺 z、寬高時工具自訂）；背景、前景的大小用 `resolveRoomData(json).room` 的 `fieldWidth`／`fieldHeight`
  與 `boardTopLeft`。其他引用（場景、切入、差分、筆記、`kind: 'other'`）給面板的清單用。
- 房間匯出（3.4＋裁定）：`rewriteRoomZip(read, 看得見的圖.map((x) => ({ path, data: 新內容, mime: 'image/png' })))`——給 `mime`
  時副檔名改 `.png`、resources 的 type 一併改正（裁定）；看不見的圖不要放進清單（保留原名原內容）；沒被引用的圖照樣放進清單
  （會改名，但不會加進 resources）。`.token` 與其他檔案原封不動。
- 圖片模式的 ZIP（3.2）：`unzipFiles(bytes, { directories: true })` 保留其他檔案與資料夾項目，同名的換成處理後的內容再 `zipFiles`。

## foreground-frame（前景框產生器）

- F05：`suggestGridCells(寬 px, 高 px)` → `{ width, height, approximate }`，`approximate` 時註明是接近值。規格 3.13 的表除了最後一列都相同；
  **極端比例依第 7 節裁定修正**：64 × 4096 改成 1 × 64（任一邊超過 64 格時以高為長邊），驗證紀錄寫明。
- F11：`rectToGridCells(窗的範圍, 畫布大小, 格數)`，同一套單位（都用 1080 單位制或都用 px）；顯示時 `toFixed(1)`。
- F52 的格線：依 F05 的格數等分畫布。說明頁（F88）的「1 格＝24 px」用 `GRID_PX`。
- 其餘（框、裝飾、差分、匯出）不依賴本層，可以和共用層同時做。

## log-converter（CCFOLIA 日誌轉換器）

- 載入（F01～F06）：每個檔 `parseCcfoliaLog(await file.text())`（內部先 `detectLogFormat`）；舊格式只用第一個檔（F03），
  混選時只留新格式（F05）。
- 新格式多檔（F04、F06～F09）：`mergeCcfoliaLogs(檔案, { defaultChannelNames: { main: '主要', info: '情報', other: '閒聊' } })`；
  `droppedMulti` 不是空的就顯示 F06 的提示；`sources` 是採用的檔；沒有分頁代碼（`channel === ''`）的歸在「其他」（F12，工具決定字樣）；
  分頁顯示名稱用 `logChannelName(merged, code)` 再套使用者改的名稱（F54）。F08 的「重複檔」（分頁組合與則數相同）是工具的規則。
- 旁白選單、名稱顏色、頭像卡：`speakers` 濾掉 `'system'` 與空字串；名稱顏色初始值用 `speakerColors`（舊格式也有，第 7 節裁定第 11 項）；
  代表頭像（F30 關閉時）用 `mainAvatars`，逐則頭像用 `message.avatar`（data URL）。
- 訊息分類（2.5）寫在工具裡：舊格式的擲骰判斷要看 `message.html`（原文，「<」是 `&lt;`，所以 `cc<=` 不會命中，附件 L24）；
  新格式「`system` 或 `roll` 不是空的」→ 系統訊息。時間（`time`、`sortMs`）只用來排序，不顯示。
- 輸出安全（裁定第 8 項）：舊格式的 `html` 是原文，**輸出前用 DOMPurify 白名單淨化**（工具實作時用 npm 加 `dompurify`）；
  標題、發言者名稱一律 `escapeHtml`（`@/core/html`）。新格式的 `html` 已經是跳脫過的。
- 從檔名帶標題（3.2：第一個「]」到其後第一個「[」）是工具的規則；新格式的房間名稱用 `roomName`。

## scenario-cards（劇本資訊卡片產生器）

- 幾乎不依賴本層，可以和共用層同時做。複製到剪貼簿用 `@/core/files` 的 `copyText`（原封不動，含全形空白）；
  專案檔用 `@/core/storage` 的 `serializeProject`／`parseProject`。
- 「CCFOLIA 資料」JSON 依裁定不移植，所以不需要 `@/ccfolia` 的角色或房間格式；若之後要輸出可以貼進 CCFOLIA 的角色，
  用 `serializeCharacterClipboard`，不要自己拼 JSON。

## （之後）G6 的 session-log／session-report

- CCFOLIA 聊天紀錄：`parseCcfoliaLog(html)`——`title`（文件標題原文）、`roomName`（新格式）、`messages[].speaker`／`text`／`time`；
  發言統計濾掉 `system`。多個新格式檔先 `mergeCcfoliaLogs`。
- 房間資料（JSON 或房間 ZIP）：ZIP 用 `readRoomZip(bytes).json`，JSON 直接 `JSON.parse`；`resolveRoomData(json)` 的 `room`
  （房間名稱若有在 `room.name`）與 `entities.characters`（物件或陣列，取各筆的 `name`）。
- 角色剪貼簿 JSON：`parseCharacterClipboard(text)` 的 `character.name`。
